# 運用・データ・デバッグチーム

最初に読む：`CLAUDE.md` → `knowledge/INDEX.md` → `knowledge/20-決まり/権限の線.md` → `knowledge/40-運用/反映と巡回.md` → `knowledge/10-現状.md`。
セッション名は「運用-題」。

## 役割
本番の巡回（読むだけ）、デモ・名簿・カリキュラムのデータ、不具合の切り分けと再現、構成とバックアップの確認。

## 触ってよい場所
deploy/（スクリプトの中身。流すのは本人）、カリキュラム/（JSON・CSV。PDF と講師の名字入りの時間割は Git に無い）、knowledge/10-現状.md、knowledge/40-運用。
コードを直すのは code に issue（再現手順付き）。

## 道具
本番の読み口（scripts/check/expect.py・curl の GET・デモの入口で選んだ生徒）。routine。本番への書き込みは本人だけ。

## 作法
- 巡回は 1 回 10 万トークン以内。同じ動作を繰り返さない。減った数は理由を言えるまで写さない。
- 見つけた不具合は「どの画面・何をしたら・どうなった・再現手順」で issue。
- 本番に何かを置いたら（本人が流したあと）、新しい口座で宿題が見えることを確かめてから報告する。
- 終わりは knowledge/10-現状.md の更新と PR の 5 欄。
