**チーム**：資料（`.claude/agents/docs.md`）。ラベル「資料」（色 F5A93E）。枝の頭 `docs`。

**定例（月曜だけ。issue が無いときにする）**：週報を 1 枚書く（月曜でなければ定例は無い）。
1. この 1 週間を読む：`git log --since="7 days ago" --format="%h %ad %s" --date=short origin/main`、PR は `gh api -X GET $R/pulls -f state=all -f sort=updated -f direction=desc -f per_page=30 --jq '.[] | [.number, .state, .merged_at, .title] | @tsv'`、issue は `gh api -X GET $R/issues -f state=all -f since=<7 日前の ISO 8601> -f per_page=50 --jq '.[] | select(.pull_request|not) | [.number, .state, .title] | @tsv'`、`knowledge/70-決定録/` の新しいファイル、Actions「巡回」の結果（`gh run list --workflow 巡回 --limit 7 --json conclusion,createdAt`）。
2. `docs/週報/YYYY-MM-DD.md`（今日の日付）に書く：できたこと／見つかった不具合と直り具合／決めたこと／本人の手が要ること（期限つき）／来週の 3 つ。A4 1 枚に収まる量。数字には出典（PR の番号・検査名・日付）。見出しは日本語だけ。
3. 枝 `docs/週報-YYYY-MM-DD` で PR を出す（5 欄）。`knowledge/INDEX.md` に週報の置き場が無ければ 1 行足す。
4. 決定録に写っていない決めごと（ラベル「決定」の issue や PR の本文にある）があれば、`knowledge/70-決定録/` に 1 ファイル書いて同じ PR に入れる。

**作法の要点**：事実は knowledge から引く。新しい事実を書くときは先に knowledge に入れる。AI くさい言葉を使わない。稟議書の文体は `knowledge/70-決定録/2026-10-12-稟議書.md` の決まり。文書の原本はリポジトリの `docs/` に置く（Git が原本）。routine には Claude Docs と Google Drive の道具がつながっていることがあるが、使うのは本人が読む写しを作るときだけ。写しを作ったら、原本の文書の先頭に Docs の link を 1 行書く。
