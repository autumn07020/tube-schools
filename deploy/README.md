# AWS への配備

10校舎・2,500名を1台で運ぶ構成。**所要はおよそ40分**、うちあなたの手を動かすのは
最初の10分だけ。

---

## まず、私にできないこと

**AWSアカウントの作成と、アクセスキーの取得は私が行いません。**

アカウント作成は本人確認とクレジットカード登録を伴います。また、取得した
認証情報は請求と全データへの権限を持ちます。私がこれを代行すると、
誤操作の責任も、鍵の管理責任も、あなたに渡らないまま残ります。

代わりに、**あなたが10分で終わる状態まで全部用意してあります。**
下の「あなたがやること」の3つを済ませたら、あとはスクリプト1本です。

---

## 構成をこうした理由

    Lightsail 1GB × 1台（ロンドン eu-west-2）
      Ubuntu 24.04
      Python 3.12（標準ライブラリのみ。追加パッケージなし）
      Caddy（TLSを自動取得。証明書の更新も自動）
      /srv/myacady/ にデータ
      毎日3時に S3 へバックアップ

### 大きさは実測から決めた

推測ではなく、動いているものを測った値である（2026-08-18）。

| 何を | 実測 | 借りる側の用意 |
|---|---|---|
| サーバのメモリ | **28 MB** | 1GB あれば OS ごと余る |
| さばける量 | **毎秒 576件**（同時50人） | 300名の校舎の山場でも毎秒 4件 |
| 通信量（10校舎3,000名） | **月 8.7 GB** | 最小の枠でも 1TB 付く |
| 保存（10校舎・1年） | **199 MB** | 20GB あれば足りる |
| 教材＋アプリ一式 | 2 MB | ― |

**どの数字も、いちばん小さい枠に対して2桁の余裕がある。**
以前ここには「2GB」と書いてあったが、測った結果まったく要らない。
メモリを積んでも速くはならない ―― 詰まる場所が別だからである。

通信量は返事を圧縮するようにして 5.3倍小さくなった（実測）。
   宿題の一覧 21,838 → 2,798 バイト
   名簿        4,670 →   889 バイト

### 月額の目安

**価格は変わるので、必ず https://aws.amazon.com/lightsail/pricing/ で
確かめること。** ここに書けるのは考え方だけである。

| | |
|---|---|
| Lightsail の最小〜1GB の枠 | 月 $5〜7 程度 |
| S3（バックアップ 5GB） | 月 $0.15 程度 |
| 独自ドメイン | 年 $10〜15 程度 |
| **合計** | **月 $6〜8 程度＋ドメイン代** |

10校舎3,000名まで増えても、この枠のままで足りる見込み。
足りなくなったら、Lightsail は**再起動だけで上の枠に移せる**。
最初から大きく借りる理由はない。

### 1か月だけ借りられるか

**できる。**

* AWS に最低契約期間はない。解約金もない。
* Lightsail は**1時間ごとの課金**で、月額はその上限にすぎない。
  月の途中で消せば、使った時間ぶんだけになる。
* 止め方は「インスタンスを削除する」だけ。そこで課金が止まる。
  **止めるのは「停止」ではなく「削除」**である ―― 停止では
  ディスク代がかかり続ける。
* 新しいアカウントには無料枠が付くことがある。条件は変わるので
  申し込み画面で確かめること。

やめるときの手順は、このファイルのいちばん下にある。

### ECS / RDS を選ばなかった理由

10校舎2,500名の負荷はこの1台で十分に収まります。実測で、講師1人あたりの
応答は14KB、300名の校舎全体の記録が14MBです。CPUもメモリも余ります。

問題は障害時です。ECS + RDS + ALB + VPC の構成は、平常時は快適でも、
**深夜に落ちたとき一人で直せません。** 塾のシステムは、あなたが直せる範囲に
収まっていることのほうが、理論上の可用性より価値があります。

1台構成で足りなくなったら、そのときはデータを持って移せます
（`MYACADY_ROOT` を変えるだけです。移行の手順も下に書いてあります）。

## あなたがやること（10分）

### 1. AWSアカウントを作る

<https://portal.aws.amazon.com/billing/signup>

クレジットカードと電話番号が要ります。**ルートアカウントには必ずMFAを
かけてください**（作成直後にIAM → セキュリティ認証情報から）。

### 2. Lightsail インスタンスを作る

<https://lightsail.aws.amazon.com/> → Create instance

| 項目 | 選ぶもの |
|---|---|
| リージョン | London (eu-west-2) |
| プラットフォーム | Linux/Unix |
| 設計図 | OS Only → Ubuntu 24.04 LTS |
| プラン | **1GB RAM / 40GB SSD**（実測 28MB なので最小でも動く） |
| 名前 | `myacady` |

作成後、**静的IPを割り当てます**（Networking → Create static IP →
インスタンスにアタッチ）。これをしないと再起動でIPが変わります。

ファイアウォールは 22 / 80 / 443 の3つだけ開けます。他は閉じたままに。

### 3. ドメインを向ける

お使いのドメイン業者で、A レコードを静的IPに向けます。

    app.example.com    A    （静的IP）

反映まで数分から数時間かかります。`dig app.example.com` で確認できます。

---

## ここから先はスクリプト

### 4. 配備する

手元（このMac）から：

```bash
cd deploy
./deploy.sh app.example.com 静的IP
```

やっていること：

1. サーバに Python と Caddy を入れる
2. `app/` と `server/` を `/opt/myacady/` へ転送
3. `/srv/myacady/` を作り、systemd サービスとして登録
4. Caddy に TLS を自動取得させる（Let's Encrypt）
5. 起動して疎通確認

終わると `https://app.example.com/` が開きます。

### 5. 校舎と名簿を入れる

```bash
ssh ubuntu@静的IP
cd /opt/myacady
sudo -u myacady python3 server/tube_server.py school-add london 'ロンドン校' --code l
sudo -u myacady python3 server/tube_server.py roster-import 名簿.csv --school london --yes
```

CSVは `classId,seat` の2列だけです。**氏名の列は作らないでください**
（作ると取り込みが拒否されます）。

### 6. バックアップを入れる

```bash
./backup-setup.sh 静的IP バケット名
```

毎日3時に `/srv/myacady/` を S3 へ送ります。30日ぶん保持します。

## シークレットの扱い

**コードにもリポジトリにも、鍵を1つも書きません。**

| 何 | どこに置くか |
|---|---|
| SSH鍵 | 手元の `~/.ssh/` のみ。サーバには公開鍵だけ |
| 生徒のパスワード | 保存しない。置くのは、確かめるための値だけ（scram-sha256。PBKDF2 60万回）。**サーバは合言葉そのものを受け取らない** |
| セッション | `/srv/myacady/tokens.json`。中身はSHA-256ハッシュ |
| S3の認証情報 | サーバの **IAMロール**。キーをファイルに置かない |
| 氏名と番号の対応表 | **このシステムの外**。先生の手元、または別のGoogleドライブ |

最後の行が要点です。氏名の対応表をこのサーバに置いた瞬間、
「攻撃されても個人と成績が結びつかない」という性質が失われます。

### IAMロールにする理由

S3への書き込みキーをサーバのファイルに置くと、サーバが破られたとき
バックアップまで消せます。IAMロールなら、鍵はファイルとして存在せず、
権限も「このバケットへの PutObject だけ」に絞れます。
`backup-setup.sh` がその最小権限のポリシーを作ります。

## 移行と撤収

### 別のサーバへ移す

    rsync -az ubuntu@旧IP:/srv/myacady/ ./backup/
    rsync -az ./backup/ ubuntu@新IP:/srv/myacady/

`MYACADY_ROOT` が指す先を丸ごとコピーするだけです。
データベースサーバが無いので、ダンプもリストアも要りません。

### 全部消す（1か月で終える／試用をやめる）

**先にデータを手元へ引き上げること。** 消したら戻せません。

    # 1. 記録を手元に落とす
    rsync -az ubuntu@静的IP:/srv/myacady/ ./myacady-backup-$(date +%Y%m%d)/

    # 2. 生徒の記録が入っているか確かめる（ここを飛ばさない）
    ls ./myacady-backup-*/schools/*/progress/ | head

そのうえで、Lightsail の画面から次の4つを消します。
**消し忘れると課金が続きます。** 課金が止まるのは削除した時点です。

| 消すもの | どこ | 消し忘れたときの費用 |
|---|---|---|
| インスタンス | Lightsail → Instances | 枠の全額 |
| 静的IP | Lightsail → Networking | **付け外ししたIPは有料** |
| スナップショット | Lightsail → Snapshots | GBあたり少額 |
| S3バケット | S3 → 中身を空にしてから削除 | GBあたり少額 |

最後に AWS の請求画面（Billing → Bills）で、翌月の請求が
0になっていることを見ること。**「停止」では止まりません。削除です。**
月額はその時点で止まります。

## 動かなかったとき

| 症状 | 見るところ |
|---|---|
| 開かない | `sudo systemctl status myacady` |
| 証明書が出ない | `sudo journalctl -u caddy -n 50`。DNSが向いているか |
| ログインできない | `sudo -u myacady python3 server/tube_server.py list --school london` |
| 記録が保存されない | `/srv/myacady/` の所有者が `myacady` か |
| 遅い | `htop`。実測28MBなので、まず疑うのはメモリ以外。足りなければ Lightsail の枠を上げる（再起動のみ） |

サービスのログ：

```bash
sudo journalctl -u myacady -f
```

## 本番に移す前に必ず

`SECURITY.md` の該当箇所を読んでから、次を済ませてください。

- [ ] ルートアカウントにMFA
- [ ] 本物の校舎の席・講師・管理者は、手元で作った束（`scripts/accounts/make.py`）と管理ページ（`/admin`）で作る。デモの校舎は架空のまま（本物の生徒を入れない）
- [ ] `--demo` を **付けずに** 起動する（付けると合言葉が画面に出ます）
- [ ] DPIA（データ保護影響評価）を書く。**UK GDPR上、子どものデータでは必須**
- [ ] 保護者への説明と同意（UK GDPR 8条、13歳未満は保護者の同意が要る）
- [ ] ICO への登録（英国で個人データを扱う事業者の義務。年 £52 程度）

最後の3つは技術の問題ではありませんが、**これが無いまま本番稼働すると
違法になります。** 稟議の前に整えておくべきものです。
