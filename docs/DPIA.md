# データ保護影響評価（DPIA）―― TUBE study（ロンドン校）

> 版：2026-11-02 下書き（法務チーム）。前の草案（2026-08-17。対応表・NAS・6 か月で削除の設計）を、今の仕組みに合わせて書き直した。
> 根拠：UK GDPR 35 条、Data Protection Act 2018、ICO「DPIA」ガイダンスと Age appropriate design code（Children's code）。
> 事実の出どころ：`knowledge/30-仕様/技術仕様と法的対応（2026-10-13 の Docs）.md`（第 2〜8 節）、`knowledge/50-法務/法的対応の一覧…md`（第 10〜14 節）、`CLAUDE.md`。保持の値は仕様の第 7 節から写した。
> **これは下書き。管理者（校舎）の承認で確定する。** 法律の専門家の確認が要る所は「要確認」。本人・管理者が決める点は末尾の「決める点」に番号で並べた。仮の名：管理者の承認者＝「承認者」、窓口＝「担当者」。

## 1. DPIA が要る理由

次の 3 つに当たるので、UK GDPR 35 条により処理を始める前に行う。

- **子どものデータ**：生徒は小4〜中3（9〜15 歳）。ICO が DPIA を求める処理の例（子どもに向けたオンラインサービス、子どもの行動の記録）に当たる。
- **系統的な記録と評価**：宿題の提出・評価・テストの点・毎日テストの正答から、生徒ごとの理解度を出し、講師に提案する（プロファイリングに当たる）。
- **新しい技術の使い方**：写真の提出、間隔をあけた出題の自動調整。

## 2. 処理の説明

### 2.1 目的
宿題を出す・写真で受け取る・評価とコメントと書き込み添削を返す・記録を生徒ごとに残す・保護者が様子を見られるようにする。広告・販売・第三者への提供は行わない。

### 2.2 役割

| 役割 | 誰 | 備考 |
|---|---|---|
| 管理者 | WASEDA ACADEMY UK. CO.LTD（早稲田アカデミー ロンドン校の運営法人） | 目的と手段を決める。ICO に登録済みの見込み（登録番号 ZB561802、2027-06-27 まで。登録簿で確かめる） |
| 処理者 | 提供者（個人事業。ロンドン校の講師でもあるが、雇用とは別の契約） | 管理者の指示の範囲で提供・保守。UK GDPR 28 条の契約を結ぶ（法的対応の一覧 #8） |
| 副処理者 | Amazon Web Services（Lightsail・S3。英国 ロンドン）、Cloudflare（DNS・TLS・トンネル。通信をいったん復号して中継する） | 管理者の承認と各社の DPA の控えが要る |
| 開発・点検の道具 | GitHub（ソースと点検の記録）、Anthropic の Claude（開発の補助） | 生徒の記録は置かない・写さない方針。点検の記録には ID と数だけが残る（3.4・R8） |
| 日本の本部 | 稟議の承認者。生徒の記録は受け取らない | 本部へ送らない限り、日本の個人情報保護法は直接は及ばない見込み（要確認） |

### 2.3 データ主体と規模
生徒（小4〜中3）約 200 名・約 250 アカウント、保護者（生徒の端末で見る。別のアカウントは作らない）、講師 7 名前後、管理者 2 名まで。

### 2.4 扱うデータ

| 種類 | 中身 | 取らないもの |
|---|---|---|
| 登録 | ID（例 s-042）、学年・クラス・受講教科（保護者の自己申告）、無作為の内部番号 | 氏名・住所・電話・メール・生年月日 |
| 認証 | パスワードを照合する値（salt・storedKey・serverKey。PBKDF2 60 万回）、入ったままの印のハッシュ | パスワードそのもの（サーバーに届かない） |
| 学習 | 宿題の配信と提出の記録、答案の写真・PDF、講師の評価（5 段階）とひとこと、書き込み添削の画像、塾内テストの点（大問ごと）、毎日テストの記録、今週の目標、組分けの申告（任意で点数） | 教材の本文 |
| 連絡 | 保護者から教科の講師へのメッセージ（600 字まで）と返事、宿題の変更のお知らせと「わかった」「質問」 | |
| 運用 | 最後に使った日、監査の記録（IP は書かない）、不具合の報告、入口の見張り（締め出した ID） | IP アドレスの保存（数えるためにメモリでだけ使う） |
| 端末の中 | 入ったままの印・好み・送る前の写真（localStorage） | Cookie、広告・解析の識別子 |

氏名が無くても、ID はクラスと結びつき、講師は教室で生徒と結べるので**個人データとして扱う**（「匿名」とは書かない）。写真やメッセージに、氏名・顔・健康などが**写り込む・書き込まれる**ことがある（R3・R4）。

### 2.5 情報の流れ
- **初回登録**：校舎が登録コード（QR）を配る → 保護者がコードを入れ、学年・クラス・受講教科を選ぶ → ID が出る → 端末でパスワードを決める（照合の値だけを送る）→ 当日から今の宿題が出る。
- **運用**：講師の授業計画から授業日ごとに宿題が出る → 生徒が写真で出す（紙の教科は従来どおり講師へ）→ 講師が評価・ひとこと・書き込み添削を返す → 生徒と保護者が見る → 記録が生徒ごとに残り、理解度（保存せず毎回計算）が講師の画面に出る。
- **見る人**：生徒は自分の分だけ。講師は担当のクラス×教科だけ。管理者は席・講師・担当・登録コード・報告だけで、答案と記録を読む口が無い。判定はすべてサーバーで行う。

### 2.6 置き場所
英国（ロンドン）のサーバー 1 台。毎日 3 時に英国内の S3 へ複製（30 日で削除。サーバーには書く権限だけ）。本部・早稲アカOnline・校舎のネットワークとはつながない。

## 3. 必要性と均衡

### 3.1 法的根拠
**正当な利益（UK GDPR 6 条(1)(f)）**。評価は `docs/legal/LIA.md`。同意は根拠にしないので、8 条（子どもの同意）は当たらない。登録は保護者が行う。異議（21 条）が来たら、記録を止めて紙の提出に切り替える。

### 3.2 最小化と正確さ
登録は学年・クラス・受講教科の 3 つだけ。写真は確認後に消える。クラスと受講教科は保護者が設定からいつでも直せる（管理者も直せる）。

### 3.3 保持（仕様の第 7 節から）

| 何を | いつ消える | 状態 |
|---|---|---|
| 答案の写真・PDF | 講師が見てから 7 日。見ていなくても 180 日 | 実装ずみ（1 時間ごと） |
| 返した添削の画像 | 生徒が消すか、アカウントが消えるまで | 実装ずみ |
| 使われないアカウント | 92 日使われないと、記録ごと全部（本番の校舎だけ） | 実装ずみ |
| 在籍終了のアカウント | 6 か月で消す | 運用者のコマンド（自動ではない） |
| 登録しかけの仮のアカウント | 1 時間 | 実装ずみ |
| 入ったままの印 | 生徒 14 日・講師 12 時間・管理者 8 時間 | 実装ずみ |
| バックアップ | 30 日 | 実装ずみ |
| 監査の記録・不具合の報告 | **消す仕組みが無い** | 期間を決めて実装（法的対応の一覧 #14・#19） |
| 試し運用の退避 | **いつ消すか未定** | 期間を決める（#22） |

### 3.4 処理者・移転・道具
- 処理者とは 28 条の契約を結び、副処理者（AWS・Cloudflare）を管理者が承認する。
- 記録は英国内に置く。Cloudflare は通信を英国外の拠点で中継することがあるので、Cloudflare の DPA の移転の枠組み（UK の補遺・IDTA など）を確かめる（**要確認**）。
- 毎晩の点検（GitHub Actions）は本番を読むだけで、記録には ID と数だけを残す（パスワードが混ざれば消す網がある）。開発の補助（Claude）には生徒の記録を渡さない。**本導入のあと、点検が本物の生徒の ID を記録に残すかを確かめる（要確認）**。

### 3.5 権利の行使
開示・訂正・消去・異議は管理者の窓口で受け、提供者が実行する（1 か月以内）。本人確認は ID と、校舎での対面で行う。手順は 1 枚にする（法的対応の一覧 #13）。法的な効果をもつ自動の決定は行わない。

## 4. 相談
- 校舎（管理者）と講師に、この下書きと試運用の範囲を説明して意見をもらう。
- 保護者には、登録の前の案内（通知）で目的・データ・保持・窓口を示し、質問を受ける。
- 残るリスクが「高」でないので、ICO への事前相談（36 条）は要らない見込み。
- DPO は置かない見込み（公的機関でなく、大規模な系統的監視でもない。37 条）。理由をここに残す。

## 5. リスクと対策

可能性・重大さ・総合は「低・中・高」。総合は対策をしたあとの残り。

| # | リスク | 可能性 | 重大さ | 主な対策 | 残り |
|---|---|---|---|---|---|
| R1 | サーバーへの侵入で記録が漏れる | 低 | 中 | 氏名・連絡先・パスワードを持たない。Web の入口を外に開けない（Cloudflare のトンネル）。校舎ごとに分けて保管。外部への通信は CSP で遮断。依存部品なし | 低 |
| R2 | アカウントの乗っ取り（推測・使い回し・共用端末） | 中 | 中 | 照合方式（SCRAM）でパスワードを送らない。試行回数の制限と締め出しの表示。印の期限。保護者のパスワードは 8 文字以上 | 低 |
| R3 | ID から生徒が分かる（教室での結びつき、写真に名前・顔が写る） | 中 | 低 | 対応表を作らない。写真は確認後 7 日で消える。案内で「名前を書かない・顔を写さない」と頼む | 中（講師は元々生徒を知っている。許容） |
| R4 | 写真やメッセージに要配慮の情報（健康・家庭の事情）が入る | 中 | 中 | 案内で書かないよう頼む。写真は自動で消える。**メッセージを 1 件ずつ消す道が無い**（生徒ごと消すしかない） | 中（消す道を作るまで） |
| R5 | 子どもへの悪い影響（比べられる・見られている・機械の判定） | 低 | 中 | 生徒の画面に順位と％を出さない（保護者の画面だけ）。毎日テストの出題順の調整と理解度は学習の補助で、判断は講師が行う。**子ども向けの短い説明（保護者が見られること）がまだ** | 低（説明を足せば） |
| R6 | 必要以上に長く持つ | 中 | 低 | 3.3 の自動の消去。監査の記録・報告・退避は期間を決めて実装 | 中（実装まで） |
| R7 | 処理者・副処理者での扱い | 低 | 中 | 28 条の契約、DPA の控え、英国のリージョン、最小限の権限（バックアップは書くだけ） | 低 |
| R8 | 開発・点検の道具に記録が流れる | 低 | 低 | 本番は読むだけ。点検の記録は ID と数だけ。開発の道具に記録を写さない。本導入後の点検の範囲を確かめる | 低 |
| R9 | 止まる・失う（保守が 1 人、復元をまだ練習していない） | 中 | 中 | 毎日のバックアップ（サーバーから消せない）。紙の提出を併用。引継ぎを契約に定める。復元の練習を 1 回行う | 中（練習まで） |
| R10 | 目的外の利用（本部・ほかの用途） | 低 | 中 | 本部に送らない。契約で目的を限る。教材の改善などに使うなら、ID を外した数字だけにして契約と案内に書く | 低 |
| R11 | 権利の請求に応えられない | 中 | 中 | ID で特定できる。消去はコマンドで即日。手順と窓口を決める | 中（手順まで） |
| R12 | 漏れに気づかない・報告が遅れる（ICO へ 72 時間） | 低 | 高 | 入口の見張り、監査の記録。**侵害時の手順と、止まったことを知らせる仕組みがまだ** | 中（手順まで） |

## 6. 結論

対策と下の「本導入の前に終えること」を済ませれば、残るリスクは「高」ではない。処理を始めてよいと判断する（承認者の承認による）。

**本導入の前に終えること**
1. 28 条の契約（#8）と副処理者の DPA の控え（#9）
2. 保護者への通知・規約・子ども向けの説明（#5・#6・#7）
3. 侵害時・権利の請求・苦情の手順と担当者（#12・#13・#17）
4. 監査の記録・報告・退避の保持期間を決めて実装（#14・#19・#22）
5. 復元の練習を 1 回（#11）
6. メッセージを 1 件ずつ消す道（R4。コードチーム）

年に 1 回、または機能を足すとき（通知・順位・外部への送信などは Children's code の基準 13・5・9 に当たる）に見直す。

## 決める点（本人・管理者に返す）

1. 承認者は誰か（校舎長か、運営法人の役員か）。
2. 権利の請求・苦情・侵害の窓口になる担当者 1 名。
3. 監査の記録と不具合の報告の保持期間（案：12 か月）。試し運用の退避をいつ消すか（案：本導入から 30 日）。
4. ID を外した数字を教材の改善に使うか（使うなら契約と案内に書く）。
5. ICO の登録（ZB561802）が今の運営法人のものかを登録簿で確かめる。
6. 子ども向けの説明と、アプリ内の問い合わせ先の文（法務チームが下書きする）。
