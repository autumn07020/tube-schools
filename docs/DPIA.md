## 1. なぜ DPIA が必要か

UK GDPR 35条は、**「高いリスクを生じ得る」処理**に DPIA を義務づけています。
本システムは ICO が示す該当事由のうち **3つ** に当たります。

| 該当事由 | 本システムでの当てはまり |
|---|---|
| 子どものデータ | 対象は9歳〜15歳（小4〜中3） |
| 系統的な監視 | 学習の日時・正誤・所要時間を継続的に記録する |
| 大規模な処理 | 最終的に10校舎・約2,500名 |

**したがって、稼働前の DPIA は任意ではなく法的義務です。**
未実施のまま稼働すると UK GDPR 違反となり、ICO の是正措置または制裁金の
対象になり得ます。

## 2. 処理の内容

### 2.1 何のために

塾の生徒が、宿題と自主学習を継続できるようにする。
講師が、つまずいている生徒に早く気づけるようにする。

### 2.2 何を集めるか

| 項目 | 中身 | 個人が特定できるか |
|---|---|---|
| ログインID | `lj2a01`（校舎コード＋クラス＋出席番号） | **単体では不可** |
| パスワード | 保存しない。scrypt / pbkdf2 600k のハッシュのみ | 不可 |
| 座席番号 | `01`〜`30` | **単体では不可** |
| クラス・学年 | `j2a` / `j2` | 不可 |
| 学習記録 | 問題ごとの正誤・復習間隔・最後に解いた時刻 | 不可 |
| 宿題の達成 | 番号ごとの済／未済、完了時刻 | 不可 |
| 紙の宿題の評価 | 4段階（任意） | 不可 |
| 監査記録 | 誰がいつ誰の記録を見たか（内部IDのみ） | 不可 |

### 2.3 **集めないもの**

- 氏名、生年月日、住所、電話番号、メールアドレス
- 保護者の情報、支払い情報
- 位置情報、端末の識別子、Cookie による追跡
- 写真、音声、生体情報
- 特別カテゴリのデータ（UK GDPR 9条）

**氏名を受け取る経路が存在しません。** 名簿の一括登録は、氏名の列が
あるファイルを**機構的に拒否**します（`server/tube_server.py` の
`roster-import`）。

### 2.4 誰が見るか

| 誰 | 見える範囲 | どう担保しているか |
|---|---|---|
| 生徒 | 自分の記録のみ | サーバ側で判定。他人のIDを指定しても403 |
| 講師 | **担当クラスの生徒のみ** | 同上。校舎をまたぐ参照も403 |
| 教室長 | その校舎の全生徒 | 明示的に権限を付与した場合のみ |
| 開発者（私） | サーバ管理権限 | 下記7.2の残存リスク |

校舎間の分離は `server/test_isolation.py` の24項目で機械的に検証しています。
**同一クラスID（`j2a`）がロンドンとNYの両方に存在する状態**でも
他校舎の生徒が見えないことを確認済みです。

### 2.5 どこに置くか

| | |
|---|---|
| 場所 | AWS ロンドンリージョン（eu-west-2） |
| 国外移転 | **なし。** 英国内で完結 |
| バックアップ | 同リージョンの S3。30日保持、その後自動削除 |
| 保持期間 | 在籍中＋卒業後1年。以降は自動削除（**要実装、下記8参照**） |

## 3. 必要性と比例性

### 3.1 なぜこの処理が必要か

紙の宿題では、生徒が「いつ・どこで・何回まちがえたか」が残りません。
そのため講師は、テストの結果が出るまでつまずきに気づけません。
学習記録を残すことで、**気づくまでの時間を数週間から数日に短縮できます。**

### 3.2 なぜこの範囲で足りるか

**氏名なしで目的が達成できます。** 講師は「中2A-07」という番号で生徒を
特定でき、それが誰かは手元の名簿で分かります。システムに氏名を入れる
必要が無いため、入れていません。

これは UK GDPR 5条(1)(c)（データ最小化）の実装です。

### 3.3 法的根拠（UK GDPR 6条）

**6条(1)(f) 正当な利益** を根拠とします。

- **利益**: 生徒の学習到達度の向上、講師による適時の支援
- **必要性**: 上記3.1のとおり、記録なしには達成できない
- **均衡**: 氏名を持たず、記録は学習に限られ、第三者提供もない

> 6条(1)(a)（同意）を根拠にしない理由：塾の学習支援という文脈で
> 同意を根拠にすると、「同意しない生徒だけ宿題の記録が残らない」という
> 運用上成立しない状態が生じます。ICO も、教育機関では正当な利益または
> 公的任務のほうが適切な場合が多いとしています。
> **ただしこの判断は専門家に確認してください。**

### 3.4 子どもへの配慮（ICO Age Appropriate Design Code）

| 基準 | 対応 |
|---|---|
| 子どもの最善の利益 | 順位・点数を表示しない（下位の子が離脱するため） |
| データ最小化 | 氏名を持たない |
| 既定はプライバシー保護側 | 追跡Cookieなし、外部送信なし（CSPで機構的に遮断） |
| 分かりやすい説明 | 生徒向けの平易な説明を用意（**要作成、下記8**） |
| プロファイリング | 出題の最適化のみ。**広告・行動ターゲティングなし** |
| ナッジしない | 「続けている日数」のみ。射幸性のある仕掛けを置かない |

## 5. リスクの洗い出し

| # | リスク | 起きやすさ | 深刻さ | 総合 |
|---|---|---|---|---|
| R1 | サーバが侵害され記録が流出する | 低 | **低** | 低 |
| R2 | 対応表（番号↔氏名）が流出し、記録と突合される | 中 | 高 | **中** |
| R3 | 講師が担当外の生徒の記録を見る | 低 | 中 | 低 |
| R4 | 生徒のパスワードが共有され、なりすまされる | **中** | 中 | **中** |
| R5 | 開発者が全データにアクセスできる | 高 | 中 | **中** |
| R6 | バックアップが消される・書き換えられる | 低 | 高 | 低 |
| R7 | 保持期間を過ぎたデータが残り続ける | **高** | 低 | **中** |
| R8 | 生徒・保護者が自分のデータを確認できない | 中 | 中 | **中** |

**R1 の深刻さが「低」である理由**が、この設計の核心です。
流出しても出てくるのは「ある番号が単語を51語やった」という事実だけで、
それが誰かは分かりません。氏名を持たないことが、そのまま被害の上限を
決めています。

## 7. 残存リスク（事業判断が要る部分）

### 7.1 R2 ―― 対応表の管理

システム側では対処しきれません。**「番号と氏名の対応表を、このシステムの
外で、誰がどう管理するか」を塾の運用ルールとして決める必要があります。**

決めるべきこと：

- 保管場所（Google Workspace の制限付き共有ドライブを推奨）
- アクセスできる人（教室長と担任のみ、など）
- 退職時の権限剥奪の手順

### 7.2 R5 ―― 開発者のアクセス

あなたはサーバ管理者として全データにアクセスできます。
これは1人で運用する以上、技術的には避けられません。

緩和策：

- 業務委託契約に守秘義務と、データへのアクセス制限条項を入れる
- 保守作業のログを残す
- 将来的に、塾側の担当者にもサーバ権限を持たせて相互監視にする

**この点は稟議で必ず聞かれます。** 先に答えを用意してください。

### 7.3 R7 ―― 保持期間

いまは削除の仕組みがありません。**卒業した生徒の記録が無期限に残ります。**
UK GDPR 5条(1)(e)（保存期間の制限）に反する状態です。

稼働前に、少なくとも次を決めてください：

- 在籍終了から何年で削除するか（1年を推奨）
- 誰が削除を実行するか
- 削除の記録をどう残すか

## 9. ICO への相談について

**リスクが「高」と判断された場合のみ**、ICO への事前相談（36条）が必要です。
本 DPIA の評価では、対策後の残存リスクはいずれも「中」以下であり、
**事前相談は不要と考えます。**

ただし 4.1 の管理者が確定しない、または 7.3 の保持期間が
決まらないまま稼働する場合は、この判断は成立しません。
