**私は弁護士でも弁理士でもありません。** この文書は、弁理士に持ち込むための
下ごしらえです。出願の可否と請求項の書き方は、必ず英国の弁理士
（Chartered Patent Attorney）に確認してください。

## 1. まず、期待値を下げておきます

「国際特許を取れるレベルの発明を」というご要望でしたが、
**このシステムの中核は、おそらくそのままでは特許になりません。** 理由は2つです。

### 教授方法は保護されない

欧州特許条約 52条(2) は、**「精神的活動・遊戯・事業活動の計画、規則及び方法」**
と **「プログラムそのもの」** を発明から除外しています。英国特許法 1条(2) も同じです。
「忘却曲線に沿って出題する」「苦手な単元を重点的に出す」は、
教え方の工夫であって、この除外にまっすぐ当たります。

### 間隔反復には長い先行技術がある

SM-2 アルゴリズム（Wozniak, 1987）をはじめ、間隔反復の実装は
1980年代から公開されており、Anki・SuperMemo・Duolingo などの
実装が広く知られています。**間隔反復そのものは新規性がありません。**

## 2. それでも出願を検討する価値がある1点

EPO の審査基準では、除外に当たる主題でも **「さらなる技術的効果」
（further technical effect）** があれば特許適格になり得ます。
計算機の内部動作を改善する、通信量を減らす、といった効果です。

このシステムには、それに当たり得る機構が1つあります。

### 部分観測下での、確信度つき学習状態推定

**課題（技術的な形で述べる）**

複数の学習者が、一部の課題のみを計算機で解き、残りを計算機の外で解く。
サーバは全課題の一部しか観測できない。この状態で全学習者の状態を
同一の尺度で表示すると、観測率の低い学習者が「活動が少ない」と誤って
提示される。これは表示の問題であると同時に、**誤った学習者に対して
不要な追加課題を生成し、計算資源と通信量を無駄に消費する** 問題でもある。

**解決手段**

1. 各教材に、計算機で観測可能か否かを示す属性を静的に付与する
2. 学習者ごとに、割り当て課題のうち観測可能な割合（観測率）を算出する
3. 学習者の状態量に観測率を随伴させ、観測率が閾値未満の学習者を
   「活動が少ない」判定から機構的に除外する
4. 観測できない課題については、指導者の離散評価（4段階）を任意入力として
   受け取り、入力がない場合は状態量に一切影響させない

**技術的効果として主張し得るもの**

- サーバが返す応答量の削減（実測で 1.3MB → 14.3KB、約96分の1）。
  全学習記録を返す代わりに、観測率つきの要約のみを返す構成による
- 不要な追加課題生成の抑制による計算量の削減
- 部分観測下でも表示の一貫性が保たれることによる、再取得要求の減少

**先行技術との差（要調査）**

- 学習管理システムにおける「未提出」の扱いは、通常は二値です。
  観測可能性を教材の静的属性として持ち、観測率を状態量に随伴させる構成が
  公知かどうかは、弁理士による先行技術調査が必要です
- 特に調べるべき分類: G06Q 50/20（教育）、G09B 5/00、G09B 7/00

## 3. 実際に競争優位を守るもの

特許より先に効く手段が4つあります。**費用はほぼゼロで、効果は即日です。**

### (a) 著作権 ―― すでに発生している

- **教材 4,767項目**（英語1,894／漢字1,422／理科624／社会801／数学26）。
  問題文・選択肢・解説はすべて自作で、市販教材からの転記がありません。
  これは編集著作物として保護されます
- ソースコード約1万行

**いま済ませておくべきこと**

1. 全ファイルの先頭に著作権表示を入れる
   `Copyright (c) 2026 <氏名>. All rights reserved.`
2. リリースごとに、リポジトリ全体のハッシュと日時を記録する
   （`git tag` ＋ タイムスタンプ。作成時期の証拠になる）
3. **早稲田アカデミーとの契約で、著作権の帰属を明記する。** ここが最重要です

### (b) 契約 ―― いちばん効く

個人事業主として提供する以上、**契約書がすべてを決めます。**
とくに次の3条項です。

| 条項 | なぜ要るか |
|---|---|
| **著作権の帰属** | 明記しないと、業務委託の成果物として塾側に帰属すると解釈される余地が残ります。「ライセンス供与であって譲渡ではない」と書く |
| **他校舎への展開権** | ロンドン校で作ったものを、NY校・東京校・他塾へ提供できるか。ここを縛られると事業が終わります |
| **競業避止の範囲** | 塾側が「同種のシステムを他社に作らせない」と求めてきたとき、期間と地域を限定する |

**この3つは、稟議が通ったあとでは交渉できません。** 通る前に決めてください。

### (c) 営業秘密

特許は公開が前提です（出願から18か月で公開）。
**公開したくない中身は、出願しないほうが守れます。**

秘密として管理すべきもの:

- 出題間隔の調整パラメータと、その決定に使った実データ
- 観測率の閾値設計（どこで「気にかける」に切り替えるか）
- 教材の帯（難度）の設計基準

不正競争防止法で保護されるには **「秘密として管理されていること」** が要件です。
アクセス制限とマル秘表示を実際に行っている事実が要ります。

### (d) 商標

「Tube for Schools」または新しい名称を、英国 IPO に出願します。
**費用 £170、期間3〜4か月。** 費用対効果はこの4つの中で最良です。

区分は 9類（ソフトウェア）と 41類（教育）。

## 5. 稟議で聞かれそうなこと

本社に出す前に、答えを用意しておくべき項目です。

| 質問 | 用意すべき答え |
|---|---|
| データはどこにあるか | 英国（AWS London）。生徒の記録は校舎ごとに分離。`deploy/README.md` |
| 個人情報は | 氏名を保持しない。座席番号のみ。対応表はシステムの外 |
| 漏えいしたら | 成績と個人が結びつかない。`server/test_isolation.py` で機構的に検証 |
| UK GDPR は | **DPIA が未了。稼働前に必須**（下記） |
| 著作権は大丈夫か | 教材は全て自作。告示（学習指導要領・常用漢字表）は著作権の対象外 |
| 誰が保守するか | **単一障害点。ここが最大の弱点**（下記） |
| 費用は | 月 $13 前後。10校舎2,500名まで同一 |

### 正直に伝えるべき弱点2つ

**1. DPIA が未了です。**
UK GDPR 上、子どものデータを扱う体系的な処理には
データ保護影響評価が必要です。ICO への事業者登録（年 £52 程度）も要ります。
**これが無いまま本番稼働すると違法です。** 稟議書に「稼働前に完了」と明記してください。

**2. 保守があなた一人に依存しています。**
本社が最も気にするのはここです。緩和策を用意しておいてください。

- ソースコードのエスクロー（第三者預託）
- 引き継ぎ文書（`SPEC.md`、`CLAUDE.md` は既にその役割を果たしています）
- 標準ライブラリのみで書いてあり、依存パッケージが無いこと
  （これは実際に強い論拠です。5年後も動きます）
