# セキュリティと個人情報の扱い

作成日: 2026-07-31
対象: `server/` の仮サーバと、その先の本番構成

---

## 0. いまの立ち位置

`server/tube_server.py` は**ノートPCの中で動く試用の道具**であって、サーバではない。

- 既定で `127.0.0.1` にしか口を開けない（このMacの中からしか繋がらない）
- TLS が無い
- Macを閉じれば止まる。IPは繋ぐ場所で変わる
- テザリングは一時的な回線であって、公開の経路ではない

**したがって、ここに実在の生徒の氏名・保護者連絡先・支払い情報を入れてはいけない。**
入れた瞬間、ノートPCの紛失・盗難がそのまま個人情報の漏えいになる。

いま入っているのは動作確認用の架空の名前だけである。

## 1. 最重要の設計判断 ―― 氏名と学習記録を分ける

顧客情報を扱うなら、技術的な対策より先にこれを決めるべきである。

```
      学習サーバ（このアプリ）              塾の生徒管理（既存の仕組み）
  ┌──────────────────────────┐      ┌──────────────────────────┐
  │ sid  Y724T7HT            │      │ sid  Y724T7HT            │
  │ 学年 中2 / クラス j2a      │ ←──→ │ 氏名 ○○ ○○              │
  │ 進捗 v:reluctant:adj …   │      │ 保護者連絡先              │
  │ 宿題 No.1000-1050 済     │      │ 支払い情報                │
  └──────────────────────────┘      └──────────────────────────┘
        漏れても「誰か」が分からない          こちらが本体
```

**学習サーバには、その子が誰かを特定できる情報を置かない。**
対応表は塾の既存の生徒管理側に置き、必要なときだけ突き合わせる。

こうしておくと、学習サーバが破られても流出するのは
「Y724T7HT という記号が単語を51語やった」という事実だけになる。
これは事故の重大性を一段も二段も下げる、いちばん効く対策である。

### 実装済み（2026-07-31）

**このアプリは氏名を持たない。** アカウントが持つのは出席番号だけで、
画面には `中2A-07` と出る。誰かは先生が手元の名簿で分かる。

```jsonc
// server/data/accounts.json ―― 実際の中身
{ "j2a01": { "sid": "Y724T7HT", "seat": "01", "role": "student",
             "level": "j2", "classId": "j2a", "alg": "pbkdf2-600k",
             "salt": "…", "hash": "…" } }
```

古い形式（氏名を持っていた版）からの移行は次で行う。
実行前に対応表を表示し、`--yes` が無ければ何もしない。

```bash
python3 tube_server.py anonymise          # 対応表を見る（控える）
python3 tube_server.py anonymise --yes    # 氏名を消す。進捗は残る
```

対応表はここで消えるので、**実行前に必ず控えること。** それが狙いである。

**支払い情報・住所・保護者の連絡先は、このアプリに入れない。**
学習アプリがそれらを持つ理由が無い。持たないものは漏れない。

### 端末内だけの経路も、氏名を持たない（2026-08-11 修正）

以前は、サーバに繋がらないときの入口で生徒に**氏名を入力させていた**
（`app/js/ui.js` の「はじめての人はここに名前」）。その文字列はサーバへは
送られないが、端末の localStorage に平文で残っていた。共用のPCやiPadでは
他の家族から見える状態で、**「このアプリは氏名を持たない」は、この経路については
事実ではなかった。** 出席番号の入力に置き換えて塞いだ。

同時に、`curriculum.js` に平文で置いていた**講師用コードを廃止**した。
このファイルは生徒の端末へそのまま配信されるので誰でも読め、しかも
それを打つと講師画面に入れた。サーバへの到達を数秒妨げるだけで成立する穴で、
共用端末では**その端末にいる全生徒分**を書き出せた。
講師はサーバへのログインでしか入れないようにした。

## 2. 置き場所（本番）

ノートPCをサーバにする案は採らない。スリープで止まり、IPが変わり、
TLSが無く、盗難がそのまま漏えいになる。

| | 向いている点 | 引っかかる点 |
|---|---|---|
| **本部・校舎のIT部門に載せる**（まず確認） | 規程・DPA・バックアップ・事故時の連絡経路が既にある。**説明が最も簡単** | 承認に時間がかかる。自由度は低い |
| **Supabase（EUリージョン）** | Postgres の行レベル権限で「生徒は自分の行だけ」をDB層で担保。TLS・バックアップ込み。50人なら無料枠 | 米国事業者。**EUリージョン指定とDPA締結が必須** |
| **Cloudflare Workers + D1** | 安い。DDoS防御込み | データ所在地の制御が弱い。集計は自前 |
| **ロンドンのVPS** | データが英国内に留まる。全部自分で決められる | OS更新・証明書更新・侵入検知・バックアップを**誰が続けるのか**。専任がいなければ実務上いちばん危険 |

**推奨の順序**

1. まず**本部／校舎のIT方針と既存の生徒管理システム**を確認する。
   勝手に外部サービスへ生徒データを置くと、技術が正しくても規程違反になりうる
2. 自前でよいと言われたら **Supabase の EU リージョン**。
   行レベル権限は、アプリのバグがあっても他人の行を返さない ―― これは
   「サーバのコードで判定する」より一段強い

## 3. 実装済みのこと

仮サーバの時点で入れてある。置き場所が変わっても持っていける。

| | 中身 |
|---|---|
| パスワード | 平文で持たない。`scrypt` が使える環境ならそれ、無ければ `pbkdf2-sha256` 60万回（実測162ms）。古い形式は**ログインが通った瞬間に自動で作り直す** |

| 権限 | 生徒は自分の記録だけ読み書き。講師は担当クラスを**読めるが書けない**。判定はすべてサーバ側 |

| 応答ヘッダ | CSP（`'self'` で閉じきり）／`frame-ancestors 'none'`／`nosniff`／`no-referrer`／`Permissions-Policy` |
| 画面のログ | 標準出力に内部IDを出さない（伏字にする） |
| 教材の著作権 | 市販単語帳の語・訳語を持たない。番号だけを扱う |
| 氏名 | **持たない。** 出席番号のみ（`中2A-07`）。移行コマンドあり |

## 6. 本部・IT部門に確認すること

置き場所を決める前に、これを確かめる。技術が正しくても、規程の外で
生徒データを扱えば問題になる。**答えを持ち帰れば、次の一手が決まる。**

**データの置き場所**
1. 生徒のデータを外部サービス（Supabase等）に置いてよいか。承認は誰が出すか
2. 置いてよい国・地域の指定はあるか（EU / UK / 日本）
3. すでに使っている学習管理システムや生徒管理システムはあるか。
   あるなら、そこに載せるほうが早い可能性が高い

**個人情報の扱い**
4. UK GDPR の管理者は誰か（ロンドン校か、日本の本部か）
5. 保護者への説明と同意は、既にどの範囲まで取れているか
6. データ保持期間と削除の規程はあるか
7. ICO への登録状況と、事故時の連絡経路（72時間ルール）
8. DPIA（データ保護影響評価）の要否を判断するのは誰か

**運用**
9. サーバの保守（OS更新・証明書・バックアップ）を誰が続けるか
10. 講師端末の管理規程（画面ロック、退職時の失効）はあるか
11. 費用の上限と、承認の手続き

**このアプリについて言えること（説明用）**
- 氏名・住所・連絡先・支払い情報を**一切持たない**。出席番号と学習記録だけ
- 生徒はメールアドレスを持たない。IDとパスワードは講師が発行する
- 誰が誰かの対応表は、塾の手元の名簿にしかない
- 市販教材の中身を複製していない（番号で指す方式）
- 1人あたり最大95KB、50人で4.6MB。移行も撤退も容易

## 7. 自己攻撃の記録と、教材依存の切り離し（2026-09-13）

### 自己攻撃（`server/attack.py`。デモに対して 17 項目、再攻撃で 17/17 PASS）

**見つけて直したもの**

| 穴 | 何が漏れたか | 直し方 |
|---|---|---|
| ディレクトリ一覧が出ていた（`/content/` `/js/` `/css/` `/content/math/`） | ファイル構成が丸見え | `serve_static` のフォールバックを 404 に。許可リスト外・ディレクトリ・拡張子なしは配信しない（`SimpleHTTPRequestHandler` へ落とさない） |
| `.DS_Store` が配信されていた | Finder のメタ情報（構成・名前） | ドット始まりの名前は一律 404。ファイル自体も削除 |

**破れなかった（設計どおり守れていた）もの**

- 未ログインの API はすべて 401。
- **IDOR**: 他生徒の `/p/<sid>`・`/head`・答案画像はすべて 403。生徒は名簿を読めない。
- **クロステナント**: `auth()` はトークンの校舎だけを使い、リクエストが名乗る校舎を見ない。
- **認証**: 存在しないIDでも同じ時間・同じ返事（ユーザ列挙ができない）。合言葉は sha256 で保存。
- 静的配信は `directory=APP_DIR` に固定。`..` 遡上とデータファイル（ROOT 配下）は届かない。

### まだ残る最大の露出 ―― 教材が未ログインで丸取りできる

`/content/manifest.js` ほか教材パック（約1.2MB）が**未ログインで誰でも落とせる**。
著作権（自社教材）と情報露出の両面で最大の穴。ただし現状のクライアントは
ログイン前に `<script>` で教材を読むため、認証必須化はアプリ・デモを壊す。
**対処は part 3 の再設計**（`Claude outputs/PLAN-教材に依存しないアーキテクチャ.md`）。
既定は「教材を持たない設計」。置く場合は認証必須の断片API＋別権限ストア。デモは変えない。

### パスワードと氏名の不可分性（再確認 ―― 現状で要件を満たす）

- パスワードは平文で持たない。salt付き `scrypt`（無ければ `pbkdf2` 60万回）、`hmac.compare_digest` で定数時間照合。
- **氏名はサーバに一切無い。** `roster-import` は氏名列を検出したら登録を拒否する。持つのは出席番号＋クラス＋**ランダムな sid**。
- **名前から ID／パスワードを生成する仕組みは無い。** ID＝`code+クラス+席`、パスワード＝ランダムな単語＋4桁。
- **学習記録の鍵はランダムな sid。** progress／submissions／ratings／summary は sid で引く。`sid → (クラス, 席)` の対応は `accounts.json` だけにあり、**氏名はどこにも無い**。
- したがって `accounts.json` と全記録が同時に漏れても、得られるのは「ある番号(sid)の生徒が何をやったか」＋「その sid は 中2A の07番」まで。**実名には原理的に到達しない**（サーバに実名が無く、席→実名 は塾の手元の紙の名簿だけが持つ）。
- 割り切り: `login_id` と `index.json` は「学年・クラス・席」という擬似識別子を明かす。教師が ID で生徒を探し、カードを配るために要る。実名ではないので、**実名不可分の要件は満たす**。抜本修正は不要。

## 8. 席・管理者・合言葉（2026-09-30。10/15 の本導入に向けて）

お金をいただいて運用する前に、口座まわりを作り直した。決めごとの全文は `CLAUDE.md`「席・管理者・管理ページ」、検査は `server/test_admin.py`（373件）と `server/attack.py`（56項目）。**2026-09-30、できあがったあとで第三者に2回検査させ（1回目3人・直したあとの2回目2人）、見つかったものを直した**（下の表の後半）。

### 何がどこにあるか

| もの | どこに | だれが読めるか |
|---|---|---|
| ID・合言葉を**確かめるための値**（salt・storedKey・serverKey） | サーバ `schools/<校舎>/accounts.json` | サーバを動かす人だけ。**これだけでは入れない** |
| **合言葉そのもの** | 合言葉の表（手元の `合言葉の表.nosync/` → Google スプレッドシート）と、刷ったカード。オンラインで引き換えた生徒の分は、**本人の端末の画面に1回出るだけ**（表にも無い） | 表を共有された人・カードを持つ本人 |
| だれがどの ID か（氏名） | **どこにも無い**（10-01 から。塾は ID と名前を結ばない。保護者が自分で登録し、ID は家庭が持つ） | 本人と家庭だけ |

**サーバは、合言葉そのものを一度も受け取らない。作るときも、入るときも。**

- 作るとき：管理者のブラウザ（WebCrypto）か、手元の道具（`scripts/accounts/make.py`）が作り、サーバへ渡すのは確かめるための値だけ。
- 入るとき：SCRAM-SHA-256 の考え方（`server/scram.py`・`app/js/scram.js`）。サーバが出した使い捨ての数（nonce）に対する「証明」だけを送る。途中で見ている人（TLS をほどく Cloudflare を含む）は、合言葉を見られず、同じ証明をもう一度使うこともできない。サーバの印を端末が確かめるので、保存の値を持たない偽のサーバは「入れた」と言えない。
- オンラインの生徒に渡すとき：送るのは**1回だけ使えるリンク**。本人が開くと、本人の端末が本物の合言葉を作る。リンクにもメールにもサーバにも、合言葉は載らない。

### 強さ

| 役割 | 形 | 通り数 |
|---|---|---|
| 生徒・席・引き換えの言葉 | 3語＋4桁（`neko-yama-sora-4821`） | 256³×10⁴ ≒ 2³⁷ |
| 講師 | 4語＋4桁 | ≒ 2⁴⁵ |
| 管理者 | 5語＋4桁 | ≒ 2⁵³ |

当てるには、1つ試すごとに PBKDF2-HMAC-SHA256 を60万回（保存の値が漏れたときも、入る手順を横で見ていたときも同じ）。入口から試すなら、同じ相手から同じIDに15分で8回まで（相手を次々に変えても、1つのIDに15分で300回・1日で約3万回まで。2³⁷ 通りには届かない）。ことばの表（`app/words.json`）は公開。強さは無作為に選ぶことだけに依る。

### 塞いだ隙間（どれも検査が、わざと壊すと × になることを確かめてある）

| 隙間 | 前 | 今 |
|---|---|---|
| 入るたびに合言葉が線の上を流れる | TLS の中を平文で。Cloudflare とサーバの中では読めた | 合言葉は端末から出ない。流れるのは、その回かぎりの証明 |
| 同じ証明・同じリンクをもう一度使う | ― | nonce は1回きり・2分。引き換えのリンクは1回きり・7日 |
| 同じIDへ同時に何百本も試す | 「確かめる」と「失敗を数える」が別で、30本送ると30本とも確かめまで進んだ | 確かめた鍵の中で先に数える。進むのは8本 |
| 確かめの途中で合言葉を作り直す・在籍を終える | 古い合言葉で入った画面が残った | 書く鍵の中で確かめ直す。始めたあとに作り直されたら、続きは通らない |
| サーバの横でコマンドを流す | 鍵がプロセスの中だけ。後から書いたほうが先を消した | 鍵を1つに（`paths.GUARD`：スレッドの鍵＋ `ROOT/.lock` の flock）。コマンドも同じ鍵 |
| 2人が同時に保存する | 一時ファイルの名前が1つ | 書き手ごとの一時ファイル → fsync → 付け替え |
| 口座を同時に足す | 計算のあいだに足された席を消せた | 計算は鍵の外、確かめて書くのは鍵の中 |
| 自分の席に入り直して、相手（IP）ごとの上限を 0 に戻す | 通ると相手の失敗を全部忘れた | 通った1回ぶんだけ戻す |
| http で開く | `http://tube-study.uk/` がそのまま 200 を返していた | サーバが https へ送る。API は http では受けない。HSTS 1年 |

### 初回登録（2026-10-01。招待コードから、保護者が自分で口座を作る）

- **塾は ID と名前を結ばない。** 登録に名前・メール・電話は要らない。学年・クラス・受講科目は自己申告。漏れて困る対応表が、どこにも無い。
- 入る前の口が3つ増えた（`/api/join/check`・`/api/join`・`/api/join/finish`。`server/join.py`）。守りは：招待コード（6文字・作り直せる）／
  同じ相手からコードの確かめ15分に20回・登録1時間に6回・1回に4人／仮の口座は名簿に出ず1時間で消える／本文は 8KB まで。
- 合言葉は本人が作る（8文字以上）。作るときも入るときも、サーバへは来ない。**3語＋4桁より弱い合言葉を選ぶ人は出る**（入口の回数の上限と、PBKDF2 60万回が残りを支える）。
- 知らない人が招待コードを手に入れると、口座を作って、選んだクラスの宿題を見られる。見えるのは宿題の指示だけで、ほかの生徒の記録は見えない。
  講師の一覧に知らない ID が増えたら在籍終了にし、コードを作り直す。
- **合言葉の作り直しは、ID を言えた人に渡すことになる**（名前と結んでいないので、本人かどうかをシステムでは確かめられない）。渡すのは、本人に確かめられる場で。
- 規約には「個人情報を保存しない」と書かない。氏名・連絡先は集めないが、学習の記録と答案の写真は ID に結びつけて保存する（UK GDPR では個人データ）。`app/terms.js` は下書きで、名義は仮。公開の前に人が確かめる。

### 使われない口座の破棄と、残す数字（2026-10-01。`server/retire.py`）

- 本番に切り替えた校舎では、**92日 使われない生徒の口座を、記録ごと自動で消す**（口座・入ったままの印・アプリの記録・要約・答案の写真・評価・点・
  落とした単元・特筆事項・宿題の決まり・連絡・宿題の受け取り手）。退塾を塾から伝える道が無い（ID と名前を結ばない）ので、「使われなくなったこと」で見分ける。
- 残すのは `retired.jsonl` の1人1行：消した月・学年・クラスの記号・受講科目・使っていた週の数・宿題の評価・テストの点・落とした単元・アプリの数。
  **ID・内部の番号（sid）・時刻・文章・写真は入れない。** 検査が、行の中に ID と sid が無いことを見ている。
- **「だれのものか絶対に戻せない」とまでは言えない。** 1クラス40人以内で、点の並びを覚えている講師なら、行から本人を思い当たることはありうる。
  だから規約には「ID を外して、だれのものか分からない形にした数字」と書き、「匿名化した」とは書かない。外へ出すときは、クラスの記号と月を落とす。
- 監査の記録（audit.log）には、消した ID が「使われず破棄」として残る。**ID は空きに戻り、別の人に出ることがある**ので、記録を読むときは日付で人を分ける。
- 在籍終了から6か月の `purge` も、同じ消し方（`retire.erase`）を通る。前は、連絡・宿題の受け取り手・入ったままの印が消し残っていた（10-01 に直した）。

### できないこと・残っているもの（正直に）

- **画面のプログラム（js）を書き換えられる相手には効かない。** 入る手順は、正しい js が届くことを前提にしている。支えているのは TLS と CSP（`script-src 'self'`）。
- **入ったあとの印（トークン）は、TLS をほどく所（Cloudflare）とサーバの中では読める。** 守っているのは合言葉そのもの。印は、生徒14日・講師12時間・管理者8時間（さわらなければ30分）で切れ、合言葉を作り直せばその場で切れる。
- **サーバの保存（確かめるための値）と、その人が入る手順の記録の両方**を手に入れた相手は、合言葉を当てなくても その人として入れる（この方式の性質）。保存だけ・記録だけでは入れない。保存が漏れたと分かったら、全員の合言葉を作り直す。
- **「管理者は答案も記録も読めない」は、口を分けてあるという意味。** 管理者は講師の口座を作って担当に付けられるので、その気になれば講師として読める。だから管理者は信頼できる2人までにし、作った・付けた跡は監査の記録（audit.log）に残る。
- サーバは1本の接続に1つのスレッドを使い、数に上限が無い。入ったあとの口（写真の提出など）は 12MB まで受ける。大量の同時接続は、前に立つ Cloudflare で止める前提。
- 相手（IP）ごとの数え方は、サーバが **Cloudflare のトンネルの後ろだけにある**ことを前提にしている（外向きの口を開けていない。`deploy/aws.sh`）。80/443 を開けて別の中継を置くと、相手の名乗りを偽れるようになる。開けない。
- 1つのIDを、38以上の相手（IP。IPv6 は /64 ごと）から15分に300回たたき続ければ、そのIDを締め出せる。締め出したことは、管理ページの「報告」に「入口の見張り」として出る（管理者は合言葉を作り直せるが、たたかれ続けるあいだは止められない。そのときは Cloudflare の側で相手を止める）。知らせは、校舎ごと・種類ごとに1時間20件まで ―― 本物の ID を20個たたかれると、その1時間は ほかの ID の知らせが出ない（1件の知らせに、たたかれた ID が並ぶので、攻められていること自体は分かる）。
- 合言葉の表（.xlsx）は 09-30 の数時間、iCloud Drive の中（`合言葉の表/`）にあった。いまは写されないフォルダ（`合言葉の表.nosync/`）に移したが、iCloud の「最近削除した項目」に30日残ることがある。**気になるなら、反映の前に作り直せる**（手順の「作り直すとき」）。
- 生徒の合言葉（3語＋4桁）は、保存の値か、入る手順の記録を手に入れた相手が、計算機を大量に使えば当てられる（1席あたり、グラフィックボード1枚で平均2か月ほど）。手に入るのは、氏名の無い宿題の記録。講師は4語、管理者は5語にしてある。
- 合言葉の表（Google スプレッドシート）と刷ったカードは、合言葉そのもの。**表の共有は「制限付き」、Google アカウントは2段階認証に。表に氏名を書かない。** カードの QR には合言葉が入っている（読むと入れる）。カードは、合言葉を書いた紙と同じに扱う。
- Cloudflare の SSL/TLS は「フル（厳密）」、「常に HTTPS を使用」を入に（サーバ側でも https へ送るが、二重にする）。
- 反映（`更新.sh`）の数秒は、古いサーバが新しいファイルを配ることがある（`--delay-updates` で縮めた）。使われていない時間に流す。
- デモ（`/demo`）は、だれでも架空の講師として入れる。本物の校舎とは校舎の分離（test_isolation）で隔てているが、同じサーバの上にある。
- 教材が未ログインで読める（7章）は、そのまま残っている。
- Safari・iPad では、機械で確かめていない（Chrome だけ）。本導入の前に、実機で「入る・引き換える・カードの QR を読む」を1回ずつ。
