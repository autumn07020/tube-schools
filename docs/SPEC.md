## 1. 何をつくっているか

**早稲田アカデミー ロンドン校の生徒向け、多教科の学習アプリ。**

| | |
|---|---|
| 生徒 | 小4〜中3（9〜15歳）。**最終的に200名**、講師を含めて250アカウント |
| 講師 | 8〜10名。それぞれ担当クラスだけを見る |
| 端末 | 中学生は個人スマホ、小学生は保護者のPCまたはiPad |
| 教科 | 英語・理科・社会・数学・国語（漢字）。今後も増やせること |
| 中核 | 忘却曲線にもとづく出題間隔の制御（SM-2）。丸暗記させない |
| 宿題 | 冊子の番号範囲＋期限を、クラス一括または生徒個別に |
| 制約 | **氏名を持たない**。市販教材を複製しない。20分で終わる分量 |

**成功の定義は「毎日開かれること」**です。機能の多さではありません
（`HANDOVER.md` 1.4）。

## 3. 設計の骨格 ―― なぜそうしたか

引き継ぐ人が最初に理解すべき4つです。**理由まで含めて**書きます。

### 3-1. 教材と進捗を絶対に混ぜない

```
教材   app/content/     全員共通・読み取り専用・アプリと一緒に配る
進捗   1人1ファイル      その子だけ・毎問更新・1項目61バイト
```

進捗は1人あたり最大95KB、**250人で24MB**。全校分がスマホの写真1枚に収まります。
この小ささが、置き場所を後から変えられる理由です。

混ぜると、教材を1語直すたびに全員分を書き換える羽目になります。

### 3-2. 項目IDは中身から作り、科目で名前空間を分ける

```
en:v:reluctant:adj      英語・単語
sci:t:光合成            理科・用語
soc:q:経度15度の…       社会・選択問題
```

配列の位置を使うと、教材の途中に1語挿した瞬間に**全生徒の進捗がズレます**
（前身で実際に起きた。`HANDOVER.md` 5.2）。

科目コード（`en`/`sci`/`soc`/`mat`/`jpn`）は**一度決めたら変えないこと**。
変えるとその科目の進捗が全部別物になります。

### 3-3. 氏名を持たない

アカウントが持つのは**出席番号だけ**。画面には `中2A-07` と出ます。
誰かは講師の手元の名簿にしかありません。

```jsonc
{"j2a01": {"sid":"Y724T7HT", "seat":"01", "role":"student",
           "classId":"j2a", "alg":"pbkdf2-600k", "salt":"…", "hash":"…"}}
```

**破られても流出するのは「ある番号が単語を51語やった」という事実だけ**です。
これは技術的な対策より効きます。支払い情報・住所・保護者連絡先も入れません。
持たないものは漏れません。

### 3-4. 市販教材の中身を持たない

`Vocabulary GRIT 2500` のような冊子は、**語の選定と訳語が編集著作物**です。
そこでアプリは**番号だけ**を扱い、生徒は冊子を見て自己採点します。

```
生徒の画面: 「No.1024」  →  まだ / おぼえた / かんたん
```

番号も忘却曲線に載るので、一度おぼえた番号も間隔をあけて戻ってきます。

## 5. 踏んだ罠 ―― 同じ穴に落ちないために

**この章がいちばん価値があります。** すべて実際に起きたものです。

### 5-1. データが消える系

| 症状 | 原因 | 対処 |
|---|---|---|
| ログアウトで直前の学習が消える | 送信待ちの行列を送らずに捨てていた。実測で18問中4問が未着 | 出る前に送りきる。行列は消さない |
| セッション終盤の数問が毎回落ちる | 送信中に増えた保存を、古い控えで上書きしていた | 1件ずつ読み直して消す |
| **オフラインで解いた20問が消える** | 衝突が「ブロブ丸ごと・時計が新しい方が勝つ」だった | **項目単位で合流**。回数の多い方を採る |
| IndexedDB だけ古いまま残る | 遅延書き込みのタイマーを鍵ごとに持っていなかった | 鍵ごとにタイマーを持つ |
| 空の状態を本物に上書き | 読み取りが空のときに保存していた | 空なら書かない（`refused-empty`） |

**時計に頼らないのが要点**です。子どもの端末は時刻がずれます。
「答えた回数」は減らないので、時計が狂っても順序が壊れません。

### 5-2. 権限・情報漏れ系

| 症状 | 原因 | 対処 |
|---|---|---|
| **氏名が端末に平文で残る** | サーバに繋がらないときの入口で氏名を入力させていた | 出席番号に置換 |
| **誰でも講師画面に入れる** | 講師コードが `curriculum.js` に平文。配信ファイルなので誰でも読める | コード自体を廃止。講師はサーバ経由のみ |
| 全講師が全50名を見られる | `--teacher` が無条件で `classes=["*"]` | 担当クラスを必須に |
| **担当外の学年の進度を書き換えられる** | 進度が1文書で、範囲を絞っていなかった。実測で他学年の進度が消えた | 担当学年の行だけ差し替え |
| **公開したら全員が締め出される** | 中継の後ろでは全員が 127.0.0.1 に見え、試行制限の枠を共有 | 中継のヘッダを（相手が自分自身のときだけ）信じる |

### 5-3. 画面・使い勝手系

| 症状 | 原因 |
|---|---|
| **ログインしても遷移しない** | `j2a01` が placeholder（薄いグレー）で、入力済みに見えた。エラー文も13pxのグレーで気づけない |
| 入口に戻ると入力欄が無い | 画面遷移で入口の段階を初期化していなかった |
| 数字を打つとカーソルが飛ぶ | 入力のたびに画面を作り直していた |
| カレンダーが1日ずれる | 午前4時区切りの変換を、日付のマスにも掛けていた |
| 講師画面に新しい生徒が出ない | 集計を握ったまま更新していなかった |
| 起動しない | 自分で掛けた CSP が、自分のインラインスクリプトを弾いた |
| 新規ログインで教科が1つしか出ない | 進度をサーバから取るのが「合言葉が残っていたとき」だけだった |

### 5-4. 教材づくり系

**教材を書いていると、別の言語の断片が紛れ込みます。** キリル文字・ハングル・
英単語が日本語の説明に混ざる事故が**35件**起きました。目で読むと必ず見落とします。

→ `python3 app/tools/check-content.py` を必ず通すこと。

### 5-5. 検査スクリプト自体の罠

- 学習セッションを開いたまま次の検査に進むと、以降の画面遷移が全部無視されて止まる
- 裏に回ったタブはタイマーが1秒に1回まで間引かれる。1手ごとに `setTimeout` を挟むと1日分の走行に何十分もかかる
- 検査が誤検出だらけになると人は検査を見なくなる（発音記号や数学記号まで弾いて161件中大半が誤報だった）

## 6. いま残っている課題

### 6-1. 本番前に必ず直すもの

| # | 課題 | なぜ急ぐか |
|---|---|---|
| 1 | **講師画面が250名に耐えない** | 担当全員の進捗を丸ごと取得。250名なら**1回の表示で23MB**。サーバ側で要約を作り、開いた生徒だけ詳細を取る |
| 2 | **CSV一括登録がない** | 入れ替わりの多い200名を1人ずつコマンドで作るのは無理 |
| 3 | **在籍終了（アーカイブ）がない** | 物理削除すると過去の記録が消える。ログインだけ止める仕組みが要る |
| 4 | 常時動くサーバがない | いまはノートPC＋トンネル。Macを閉じると止まる |

### 6-2. 決まっていないこと（技術ではなく判断）

`SECURITY.md` 6章に本部・IT部門へ確認する11項目があります。うち最重要は3つ。

1. **EU圏の外部サービスに生徒データを置いてよいか**（承認は誰が出すか）
2. **校舎のNASに氏名対応表が実在するか**（実在するならアプリを同居させない）
3. **講師の2人目は誰か**（1人だと機種変1回で入室カードを出せる人がゼロになる）

加えて未決のもの:

- **XP・連続記録・バッジを出すか** ―― ICO の子ども向け規範は、子どもを留める
  仕掛けを戒めています。XPは内部に持っているので、表示するかは判断だけ
- ~~小4に渡すか~~ → **渡す**（2026-09-10 決定。小4 α・β・K のコースを作り、授業計画と宿題はコースから出す。進度は SEED-ロンドン校.md）
- **テストに制限時間を設けるか** ―― 設けるなら学年ごとの設定値に

### 6-3. 教材の不足（実測）

| 学年 | 英語の項目 | 新出が尽きるまで |
|---|---|---|
| 中1 | 609 | 約49日 |
| 中2 | 1,187 | 約80日 |
| 中3 | 951 | **約34日**（文法が先に尽きる） |

**中3は1学期で枯れます。** 理科・社会・数学・国語は見本の分量（16〜47項目）
しかないので、本運用には足りません。

### 6-4. 技術的に弱いところ

| | いま | どうするか |
|---|---|---|
| パスワード保管 | pbkdf2-sha256 60万回 | Argon2id（macOS標準Pythonに scrypt が無いため妥協中） |
| 講師の二要素認証 | 無し | 復旧経路が揃ってから |
| 監査ログ | 同じサーバ上のファイル | 別の場所へ送る |
| 単元テスト | 生徒が自分で押す | 講師から課す導線 |
| 締切通知 | 無し | 押し通知は未実装 |

## 7. 引き継ぐ人がまずやること

```bash
# 1. 動かす
cd server && python3 tube_server.py serve --demo

# 2. 教材を検査する
python3 app/tools/check-content.py

# 3. アプリを検査する（ブラウザのコンソールで）
#    var s=document.createElement('script'); s.src='tools/check.js'; document.head.appendChild(s);
#    await TubeCheck.all({id:'j2a01', password:'…', teacherId:'teacher4', teacherPassword:'…'})
```

**変更したら必ず2と3を通すこと。** 通らないものを配らない。

### 触る場所の見分け方

| やりたいこと | 触るファイル |
|---|---|
| 教材を足す | `app/content/<科目>/*.js` ＋ `manifest.js` に1行 |
| 学年ごとの分量を変える | **画面から**（講師 → 進度）。ファイルは触らない |
| 新しい科目を足す | `manifest.js` の `subjects` に1行＋フォルダ |
| 置き場所を変える | `app/curriculum.js` の `sync.base` **1行だけ** |
| 画面を直す | `ui-core` / `ui-student` / `ui-teacher` のどれか |
| 出題の理屈を変える | `js/srs.js`（DOMに触らないので単体で試せる） |

### 絶対に守ること

1. `../myenglish/` を変更しない（本人が毎日使っている稼働中の個人用アプリ）
2. 項目IDは内容由来。配列位置を使わない
3. 保存の可否は実測でプローブする（`try/catch` で握りつぶさない）
4. 読み取りが空のときに保存しない
5. 仮サーバに実在の生徒データを入れない
6. 市販単語帳から転記しない
