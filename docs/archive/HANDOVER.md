## 1. 企画

### 1.1 目的

学習塾の生徒一人ひとりが、通学時間に毎日20分だけ使う受験英語アプリ。
忘却曲線にもとづく出題間隔制御で、**語彙・語法・文法を「短期記憶」ではなく「定着」させる**。
講師側は、誰がどこでつまずいているかを一覧できる。

### 1.2 前身との違い（ここが企画の核）

| | 前身（個人用） | 本プロジェクト |
|---|---|---|
| 利用者 | 1人 | 塾の全生徒＋講師 |
| 目標 | IELTS / CEFR B2→C1 | 高校・大学受験 |
| 英語の種類 | 英国英語 | **米国英語**（受験の標準） |
| 保存 | 端末内のみ | **サーバ同期**（端末を跨ぐ・講師が見る） |
| 認証 | なし | クラスコードによる生徒識別 |
| 教材 | 固定1セット | 学年・志望校帯で出し分け |

### 1.3 想定利用シーン

- 生徒: 通学の電車内。**電波が切れる前提**。オフラインで解けて、あとで同期される必要がある
- 講師: 週1回、クラス全体の定着率と離脱者を確認。個別に範囲を指示

### 1.4 成功の定義

「毎日開かれること」がすべて。機能の多さではなく、
**20分で終わること・起動が速いこと・記録が絶対に消えないこと**の3点で評価する。
前身プロジェクトでは記録消失が最大の障害だった（後述 5.1）。

## 2. そのまま使えるもの

`reference/tube-english-personal.html` から移植可能。実装済み・実証済み。

### 2.1 SRSエンジン（SM-2）

Anki と同系統。`grade(id, g)` に 1〜4 を渡すだけ。

- `iv`（間隔日数）, `ef`（易しさ係数）, `due`, `reps`, `lapse`
- Again: 10分後に再出題、ef −0.20
- Hard: iv×1.2, ef −0.15 / Good: iv×ef / Easy: iv×ef×1.32, ef +0.15
- 新規カードは Good→1日, Easy→4日
- 「もう知っている」で 45日先に飛ばす（既知語を捨てる導線）
- `iv >= 21日` を「定着(mature)」とみなす

**この部分は無改造で流用してよい。** 受験用でも原理は同じ。

### 2.2 出題形式の自動切替

定着度に応じて同じ語の問い方を変える。暗記の丸暗記化を防ぐ実装。

| 間隔 | 形式 |
|---|---|
| < 7日 | 認識（英→意味） |
| 7〜20日 | 文脈穴埋め（例文から語を抜く） |
| 21日〜 | 産出（日本語→英語を思い出す） |

### 2.3 レベル推定モデル

「その帯の項目を8割、間隔21日以上まで定着させて初めてその級」という定義。
自己申告値を下限に置き、**次の帯の定着度で連続的に前進**する（1項目ごとに動く）。

受験用には CEFR ではなく**偏差値帯 or 志望校帯**に読み替える。
モデル自体（`levelPos()`）はそのまま使える。指標名と帯の定義を差し替えるだけ。

### 2.4 UIデザインシステム

- 地は `#000000`。サーフェスは温かいニュートラル（`#131211` / `#232019`）
- **有彩色はアクセント1色のみ**。正誤は色相ではなく「塗り／打ち消し線」で表す
- 書体: `Fraunces`（英字）→ `Hiragino Mincho ProN`（日本語）で1つのセリフの声に統一。SF Pro はラベル・数値専用。**500より重いウェイトを使わない**
- 今日の予定は路線図の発想（ヘアラインのレール＋進捗で塗り上がるノード）
- フォントは woff2 の latin サブセットを base64 で埋め込み（CDN不要・オフライン動作）

塾のブランドに合わせるならアクセント色だけ差し替えれば成立する設計になっている。

### 2.5 コンテンツのデータ形式

タプル配列。トークン効率がよく、追記しやすい。

```js
// V: [head, pos, level, ja, en, ex, collocations(|区切り), note, exJa]
["reluctant","adj","B2","気が進まない","not willing to do something",
 "She was reluctant to commit to a date.","reluctant to do sth|reluctance","..."]

// P（前置詞・語法）: [pattern(___), answer, distractors(|), level, ex, ja, note]
// G（文法）: {t, ja, level, rule, forms:[[label,en,ja]], q:[[q,answer,opts,why]]}
// SYN: 見出し語 -> "類義語 · … | 反意語 · …"（別テーブルなので後から一括追加できる）
```

## 3. 作り直すもの

### 3.1 コンテンツ（全面差し替え）

前身の1,590項目の内訳と、本プロジェクトでの扱い：

| 種別 | 数 | 扱い |
|---|---|---|
| 語彙 | 1,134 | **半分程度は流用可**。ただし英国綴り（realise, centre, -ise）を米国綴りへ。英国生活語（council tax, A&E, chippy 等）は全削除 |
| 前置詞・語法 | 365 | **ほぼ流用可**。受験の語法問題と重なる |
| 文法 | 61ポイント | **流用可**。倒置・仮定法・分詞構文など受験頻出と一致 |
| 英国表現 | 30 | **全削除**。受験には不要 |
| 類義語 | 161語分 | 流用可。受験は言い換え問題が出るので価値が高い |

**追加が必要な受験固有の領域**
- 発音・アクセント問題（IELTSでは不要だったので未実装）
- 語法問題（動詞の語法、可算/不可算、自動詞/他動詞）
- 熟語・イディオム
- 長文頻出テーマ語彙

### 3.2 保存層（設計からやり直す）

前身は端末内保存のみ。本プロジェクトでは成立しない。理由：

1. 生徒が端末を変えたら記録が消える
2. 講師が進捗を見られない
3. **埋め込みページでは保存自体が遮断される**（5.1 参照）

**推奨構成**: オフラインファースト＋サーバ同期

- ローカル: IndexedDB に SRS 状態を保持し、オフラインでも解ける
- 同期: オンライン復帰時に差分を送る。衝突解決は **`last_seen` が新しい方を採用**（同一生徒の複数端末を想定しているのでこれで足りる）
- サーバ: Supabase（Auth + Postgres + Row Level Security）が最小構成で要件を満たす。RLS で「生徒は自分の行だけ、講師は担当クラスの行だけ」を DB 層で担保できる

### 3.3 データモデル（たたき台）

```sql
users     (id, role: 'student'|'teacher', display_name, class_id, created_at)
classes   (id, name, teacher_id, join_code)
decks     (id, name, grade_band, subject)
items     (id TEXT PRIMARY KEY, deck_id, type, payload JSONB, level, seq)
progress  (user_id, item_id, iv, ef, due, reps, lapses, last_seen,
           PRIMARY KEY (user_id, item_id))
sessions  (id, user_id, started_at, ended_at, answered, correct)
assignments (id, class_id, deck_id, level_from, level_to, due_date)
```

**`items.id` は必ず内容由来の安定キーにすること**（例 `v:reluctant:adj`）。
配列インデックスを使うと、教材を1語挿入しただけで全生徒の進捗がズレる。前身でこの設計にしてあり、実際に何度も救われている。

### 3.4 認証（新規）

生徒にメールアドレスを持たせない前提で設計する。

- 講師がクラスを作ると `join_code` が発行される
- 生徒は「クラスコード＋自分の名前」で参加。端末に紐づくトークンを保持
- 端末を変えたときの復帰手段が要る（コード再入力＋名前選択、など）

### 3.5 講師用ダッシュボード（新規）

見せるべきものは3つに絞る。多機能にすると使われない。

1. **継続**: 直近7日の学習日数（生徒別）。離脱者が一目で分かる
2. **定着**: 帯ごとの定着率。クラス平均と個人
3. **つまずき**: `lapse >= 3` の項目を集計。**クラス全体で共通してつまずいている項目**は授業で扱う価値がある

## 4. 法務上の注意（着手前に必読）

**受験用単語帳の見出し語リスト・訳語・例文をそのまま複製することは著作権侵害になりうる。**

- 単語そのものに著作権はない。しかし**語の選定・配列・訳語の付け方・例文は編集著作物として保護される**
- 入試過去問の英文も著作物である
- 市販単語帳（ターゲット、システム英単語、鉄壁 等）からの転記は不可

**安全な進め方**
- 語の選定根拠は、公開されている語彙リスト（CEFR-J Wordlist、JACET8000、学習指導要領の語彙表など）に置く。**ただし各リストの利用条件・商用利用可否を必ず確認すること**
- 例文・訳語・解説は**すべて自作**する（前身プロジェクトの1,590項目はすべて書き下ろし。そのまま流用してよい）
- 塾の教材として配布・課金するなら、着手前に条件を確定させること

この確認を飛ばして開発を進めないこと。後から作り直しになる。

## 5. 踏んだ罠（同じ穴に落ちないために）

前身プロジェクトで実際に発生し、解決に時間を要したもの。**すべて再発しうる。**

### 5.1 保存が消える（最重要）

**症状**: セッション中は動くのに、リロードすると全部消える。

**原因**: Artifact/埋め込みページは別オリジンの iframe であり、**Safari はサードパーティ枠のストレージを遮断する**（ITP）。書き込みは成功したように見えて破棄される。

**対策**
- 本プロジェクトは**自前ドメインの first-party ページとして配信する**。これで根本回避できる
- それでも、以下は必ず実装する:
  - **書き込み可否を別途プローブする**。`try{}catch{}` で握りつぶすと「遮断」と「空」が区別できず、警告が一度も出ないまま消え続ける
  - 読み取りが空のときに**保存してはいけない**。`restore()` が控えても直後の日付処理が空を保存して全滅させた実例がある
  - IndexedDB のオープンにタイムアウトを置くなら、**「遅い」を「空」と誤判定しない**（リトライしてから判定）
  - 診断結果の所有者を1箇所に限る。`save()` が `STORE.kind` を上書きして `blocked` の判定を潰した実例がある

### 5.2 項目IDを配列位置にしない

教材を途中に挿入した瞬間に全ユーザーの進捗が壊れる。内容由来の安定キーにすること。

### 5.3 CSSクラス名の衝突

`.done` を「完了トラック」と「完了画面」の両方に使い、後者の `flex-direction:column` が前者に効いて行が縦組みになった。BEM 的な接頭辞をつけるか、用途ごとに名前を分ける。

### 5.4 押せそうで押せない要素を作らない

枠・影・角丸を持つ要素はすべて操作可能の合図に見える。ロゴやステータスチップが押せず苦情になった。

**検査方法**: 画面ごとに `document.querySelectorAll('button')` を走査し、
「ハンドラがあるか／`disabled` か」を機械的に検査する。目視で確認しない。
タップ領域は 44×44px 以上（見た目を変えず `::after` で当たり判定だけ広げる）。
無効化ボタンは「何もしない」で終わらせず、代わりにできることを提示する。

### 5.5 CSS Grid の自動配置に頼らない

`grid-column` / `grid-row` を明示しないと、要素が想定外の場所に流れる。

### 5.6 レベルメーターは連続的に動かす

自己申告値でクランプすると、次の帯を8割固めるまで針が1ミリも動かない。
**次の帯の定着度で駆動**すれば1項目ごとに前進する（前身では330px幅で1項目あたり0.205px）。
動かないメーターは「壊れている」と受け取られる。

## 7. 分量の現実（前身での実測）

- 1日20語 × 365日 = **7,300語**。これは受験英語の総語彙量を超える。水増しなしには埋まらない
- 大学受験の標準的な目標語彙は **4,000〜6,000語**。高校受験なら 1,500〜2,500語
- **新出材料が尽きても復習は続く**。365日分の「新出」は不要。1日20語なら 250〜300日分あれば1年運用できる
- 1日20語は20分に収まらない。数週間後には復習が1日150〜200問に育ち、実際には30〜40分かかる。**1日8〜12語が20分の現実的な上限**

塾に提案する際は、この数字を先に共有すること。「毎日20分」と「1日20語」は両立しない。
