# TUBE study ―― デザイン仕様書

宿題タブで決めた形を、ほかの画面へそのまま持っていくための書きつけ。
**迷ったら apple.com を見る。** それ以外の形を採るときは、理由を
このファイルに書き足すこと。理由を書けないものは採らない。

---

## 0. 大原則

| | |
|---|---|
| **枠線は基本悪** | 区切りは面と余白でつくる。線を引くのは表の罫だけ |
| **白い箱で囲まない** | 節ぜんぶを card で包まない。中の1行1行を白くする |
| **色は意味のあるところだけ** | 黄＝いま手を入れる所。青＝進んでいる所。それ以外は無彩色 |
| **ページを移動させない** | 詳細・採点・予定はポップアップ（紙）で出す |
| **押したものは動かない** | 描き直しても巻き位置を保つ。札は押した位置に留まる |
| **数は実数で** | 「9/10人」と書く。百分率は出さない |
| **できないことは書かない** | 押せそうに見えるものは必ず押せる |

## 1. 色

### 定義（app/css/app.css の :root）

```
--accent        #005BAC   青。進んでいること、選ばれていること
--accent-soft   #E7F0FA   青の地
--accent2       #F9B900   早稲アカの黄。ロゴの study と同じ色
--accent2-fill  accent2 を白で 68% に薄めたも（塗りつぶし用）
--accent2-soft  accent2 を白で 26% に薄めたもの（地）
--accent2-text  #8A5A00   黄の系統で、白地に書ける濃さ
--accent2-line  #EDBE45   黄の線
```

**黄は1本しか持たない。** `--warn-*` はこの別名である。
2本持つと片方を直したときにもう片方が置いていかれる。

### 面積と濃さ

同じ #F9B900 でも、**細い字と広い面では濃さが違って見える**。

- 字（ロゴ、見出しの数字）… `--accent2` そのまま
- 塗りつぶし（今日の札、選んだカプセル）… `--accent2-fill`
- 地（束の帯、回数の丸）… `--accent2-soft`
- 白地の上の文字 … `--accent2-text`（#F9B900 は 1.6:1 で読めない）

### 目盛りのグラデーション

満ちた目盛りは **青→黄** に抜ける。判定は CSS がやる ――
JS で印を付けて回らない（8か所あって必ず付け忘れる）。

```css
.bar i[style*="width:100"]{ background:linear-gradient(90deg,
  #0A4F8F 0%, #2E86D6 45%, var(--accent2) 100%) }
```

節の見出しの左の柱と、ロゴの TUBE は **まったく同じ**縦グラデーション。

```css
linear-gradient(180deg, var(--accent) 0%, var(--accent) 42%, var(--accent2) 100%)
```

## 4. レイアウト

### 幅で決める。画面の幅では決めない

縦タブが 148px あるので、画面の幅と中身の幅は一致しない。
**必ず container query を使う**（`@container bento (min-width:…)`）。
`@media` で切ると、PCの窓を縮めたときに形が化ける。

### 土台（.bento）

```
.t-full  幅いっぱい      .t-wide  広め（既定は全幅、2列とれたら span 2）
.t-one   1枚ぶん
```

**列番号を直に書かない。** `grid-column:3 / -1` のような書き方は
app/tools/check-source.py が弾く。

### 段の切り替え（実測して決めた値）

| 部品 | しきい値 | 形 |
|---|---|---|
| 時間割 | 710px以上 | 月〜土 6列 |
| 時間割 | 470-709px | 3列 × 2段（月火水／木金土） |
| 時間割 | 470px未満 | 曜日ごとに横へ流す |
| Upcoming / Grading | 900px以上 | 左右2本 |
| 紙（sheet） | 641px以上 | 中央に浮かぶ（680px） |
| 紙（sheet） | 640px以下 | 下から出る全幅 |

**行を端から端まで伸ばさない。** 1本のときも 760px で止める。
日付と件数が1メートル離れると、目が横に走れない。

### 共有している札は、共有していると見える所に置く

Upcoming と Grading は学年・教科の札を共有している。
柱を左右に分けたので、札は **2本の柱の上**に幅いっぱいで置く。

## 5. ポップアップ（紙）

別ページへ飛ばさない。**3種類ある。**

| mode | 出どころ | 中身 |
|---|---|---|
| `list` | 提出状況の棒 | その枠に出した宿題の一覧 |
| `grade` | 宿題の行 | 採点欄（◎○△✕）＋ のばす・取り消す |
| `lesson` | 時間割のコマ | 前後3回の授業＋ずらす・止める・にがて集め |

決まりごと:

- 開いても**ページは1pxも動かない**（実測して確かめること）
- 閉じる道は2つ ―― 右上の × と、後ろの暗がり
- 紙の中から紙の中へ移る（list → grade）。いちど閉じない
- **入りの動きで位置を変えない。** 濃さと大きさだけ。
  動きが走らない場面（背面のタブ、動きを減らす設定）で
  最初の1コマのまま止まり、下端が画面の外へ出る

## 6.5 5週の周期と、組み分けテスト

早稲田アカデミーは **5週ごと**に組み分けテスト（α/β・T/R の入れ替え）がある。
システム全体がこの周期で回る。

### カリキュラム

```
1〜4回目  新しい単元
5回目     その4回の総復習
```

`server/lessons.py` の `CYCLE = 5` が唯一の出どころ。
`is_review(n)` / `cycle_of(n)` / `block_of(n)` を使い、数字を散らばらせない。

### 総復習テスト対策

本番の **14日前**（`exams.json` の `prepDays`）から、毎日テストの最上部に出る。

| | |
|---|---|
| 範囲 | 前回のテストの翌日から、いまの回まで |
| 量 | 1教科 **50分**（本番と同じ長さ。ふだんの3倍だがここで頭打ち） |
| 版 | 直近の出来 **6割以上→上位編** ／ 未満→基本編 |
| 持ち越し | まちがえた問題は**必ず翌日の先頭**に戻る |
| 並び | その日の種で決まる。同じ日なら同じ、日が変われば変わる |

**実データで動くための約束**

1. **日付を決め打ちしない。** 組み分けテストの日は `exams.json` から読む。
   入っていなければ対策は出ない ―― 無い日程に向けて生徒を走らせない。
2. **範囲は授業計画の単元名で決める。** 教材の単元名と一致すればそこだけ、
   一致しなければ学年ぜんぶ。狭められないだけで止まらない。
3. **難易度は教材の `level` で分ける。** 無ければ記録から測った
   「まちがえられやすさ」で分ける。嘘の難易度を作らない。
4. 60分に足りなければ **範囲を広げる**。4分で終わる総復習は総復習ではない。

### 紙（A3 **よこ** 1枚・3段）

`server/prepsheet.py` が印刷用のHTMLを返す。PDFを組む道具は入れない ――
日本語フォントをサーバに置き、行分けを自分で書くことになるため。

段は3本にしてある。よこ置きで2段にすると1行が200mm（約95字）になり、
目が行の頭に戻れない。3段なら1段130mm・約60字で、たて置きと同じ読みやすさ。

1枚に載る数は **実測した高さ**から決めている。**平均ではなく最悪値**を使う。

```
選択肢つき 17.6mm ／ 選択肢なし 11.2mm ／ 使える高さ 3段で 645mm
解答ページは別に見積もる（解説の行数ぶん高くなる）
```

見積もりで置くと必ず外す。実際に踏んだ順:

- 11.4/5.6（たて置き）→ 122mm はみ出し
- 平均値で見積もる → 英語だけ毎回 2〜10mm はみ出し
- 問題ページだけ見る → 英語の解答ページが 3mm はみ出し
入りきらない分は「のこり n問はアプリで」と紙に書く。

2枚目は解答と解説。解説は教材の持っているものをそのまま出す
（数学は全問にある。理社は一部）。教材に `<b>` などのタグが混ざって
いることがあるので落とす ―― 残すと「&lt;b&gt;」と刷られる。

見本は `sample/対策-*.html`（5教科ぶん）。

## 6.6 カメラで丸つけ

刷った解答らんを撮ると、その場で採点する。

**写真は端末の外に出さない。** サーバへ送らないし、保存もしない。
読み終わったら捨てる。送らなければ、漏れることもない。

### なぜ文字認識をしないか

手書きをその場で読むには外の認識サービスが要る ―― 写真を外へ出すことに
なり、費用も通信も増える。だが **問題用紙はこちらが刷っている**。
決まった場所に決まった形のマスを置けば、読み取りは「どのマスが黒いか」を
測るだけの話になる。計算だけででき、学習も外部の機械も要らない。

### 紙の作り

| | |
|---|---|
| 1枚目 | 問題（3段） |
| 2枚目 | 解答らん（**カメラで読むのはこの紙**） |
| 3枚目 | 解答と解説 |

解答らんは **問題と別の紙**にする。問題は高さがまちまちなので、同じ紙に
置くとマスの位置が問題文の長さで動き、読む側から見つけられない。

紙に刷るのは **選択問題だけ**。用語（「〜とは？」）は書いて答えるので
マークシートでは採点できない。載せると「読めませんでした」が何十個も並ぶ。

### 読み取りの手順（app/js/omr.js）

1. 写真を 1200px に縮める
2. まわりとの差で明るさのむらを消す（影・紙の反り）
3. 四隅の黒い正方形を、四隅の区画それぞれで探す
4. その4点から射影変換を作り、傾きと遠近を打ち消す
5. 決まった場所のマスの黒さを測り、いちばん黒いものを選ぶ

**迷ったら選ばない。** いちばん黒いマスが2番目より 0.10 以上濃く、かつ
紙の地より 0.22 以上濃いときだけ答えとする。まちがった採点は、
採点しないより悪い。

### 寸法は1か所

`server/prepsheet.py` の `SHEET` が唯一の出どころ。読む側へは API が
そのまま渡す（`/api/assignments/prep` の `sheet`）。**数字を2か所に書かない。**

選択肢の並びも同じ。紙に刷る順と、採点で使う順がずれると総崩れになるので、
サーバが `paper`（紙に刷った並び）を返し、画面はそれを使う。

### 検査

`app/tools/test-omr.html` をブラウザで開く。紙の写真を9通り
（傾き・影・遠近・かすれ・暗い机）作って読ませる。**実機のカメラが
無くても、読み取りの正しさはここで確かめられる。**

## 8. これまでに踏んだ穴（同じ所を踏まないために）

- **`@media` で段を切った** → 縦タブ 148px を勘定に入れておらず、
  窓を縮めると時間割が横長に潰れた。→ container query へ
- **`grid-column:3 / -1`** → 2列しかない幅で3列目を指して札が重なった
- **`.who` の名前がヘッダと衝突** → 採点欄の名前が右端に寄った
- **`animation … both`** → 動きが止まる場面で紙が14px下にずれた
- **学年で数えた提出率** → 小4βの棒に小4αの数字が出た。**クラスで数える**
- **`#F9B900` を白地の文字に** → 1.6:1。読めない
- **JS で `full` 印を付けて回った** → 付け忘れが出る。CSS で判定する

## 9. ウィジェットの格子（2026-08-20）

### 9.1 なぜ「白い箱をならべる」をやめたか

生徒のトップは、白い箱が5つ横に伸びているだけだった。
画面が広いほど1つが間延びし、どれも同じ重みに見えた。
1830px の画面では、教科名から「›」までが空白の帯になっていた。

iOS のホーム画面は、そうなっていない。
**色を持った札が、大きさを変えながら格子に収まっている。**
これを教科書にする。

### 9.2 札は4色だけ

| 種類 | 使うところ |
|---|---|
| `w-marble` | その画面でいちばん見てほしい数。**1画面に1つ** |
| `w-blue` | 押して先へ進む札 |
| `w-warm` | 手を入れてほしい所（にがて・のこり） |
| `w-plain` | それ以外 |

マーブルは丸いぼかしを4枚重ねて作る（`app/css/app.css` の `.w-marble`）。
**画像は使わない** ―― 画像にすると暗い配色に切り替えたとき直せない。

2つ以上マーブルを置くと濁る。1画面に1つ。

### 9.3 列の数は「割り切れる数」だけ

`auto-fill` に任せると、札が5枚のとき「4枚＋1枚」の歯抜けができる。
**歯抜けは、そこに何かがあるはずだと読まれる。**

だから札の合計を6つぶんにそろえ（大きい札が2つぶん）、
6を割り切る 1・2・3 だけを列の数に使う（`.wgrid`）。
4枚ちょうどの帯は 1・2・4（`.wgrid4`）。

- 電話でも **2列**。1列にすると札5枚で750pxになり、宿題まで指を3回すべらせる
- 4列以上にはしない。札が250pxを割ると添え字が2行に折れ、行が波打つ
- 広い画面は列を増やさず、**本体の幅を1320pxで止めて中央に寄せる**
  （apple.com もそうしている。講師の画面は止めない ―― 40人ぶんの帯は横に広いほど読める）

### 9.4 幅の検査は目でやらない

崩れは「ある幅でだけ」出る。作っている最中の幅では出ない。

`frame-ancestors 'none'` を返しているので iframe に並べられない
（**この見出しは外さないこと**。クリックジャッキング除け）。
代わりに入れ物の幅を直に変える ―― 折り返しは全部 `@container` なので、
入れ物を細くすれば細い画面と同じ見え方になる。

    app/tools/幅の検査.js をコンソールに貼る

390〜2000px の12通りで、歯抜けとはみ出しを数で見る。

### 9.5 「学年のなか 0%」をやめた

輪グラフに 100 と 0 が並び、何の数か読めなかった
（輪は正答率、下の字は順位で、そもそも別の数だった）。

いまは **今週やった問題数** ひとつに絞り、自分・まんなか・1番を
同じ物差しで並べる。比べるものが1種類なら誤読しようがない。

- **1週間で切る。** 通算だと去年から通う子に4月入会の子は一生追いつけない。
  追いつけない競争は競争ではなく、ただの身分の掲示になる
- まんなかは **中央値**。平均だと1人の猛烈な生徒が引き上げ、半数以上が
  「へいきん以下」と出る。それは目標として働かない
- 出すのは「あと何問でまんなか」まで。1番との差は、ほとんどの生徒に届かない

## 10. パソコンで解いて、スマホで撮る（2026-08-20）

紙はパソコンから刷る。撮るのはスマホ。この2台をつなぐのに
**合言葉もQRコードも作らない。**

同じアカウントで入っているのだから、「さっき何を刷ったか」は
サーバに聞けば分かる（`/api/assignments/prep/last`）。
スマホでカメラを開くと、その教科で直接ひらく。教科を選ぶ画面は出ない。

- 2台で同時に入ってよい。ログインのたびに別の合言葉が発行され、
  先に入ったほうも切れない
- おぼえるのは **教科・版・時刻だけ**、6時間で捨てる。
  答案の画像はどこにも送らないし、置かない
- QRコードは作らなかった ―― この場に読み取り機が無く、
  **正しく読めることを確かめられない**。確かめられない物は入れない

パソコンの画面には3行の手順を出す（`handoff()`）。
スマホには出さない ―― 手に持っている機械に「スマホでひらいて」と
書いても意味がない。

## 11. 教材を手で書かない（2026-08-20）

算数・数学は `app/tools/gen_math.py` が書き出す。**JS を手で直さない。**

答えは計算で出し、誤答は **実際にありがちな間違い** から作る ――
符号の取りちがえ、通分のし忘れ、`÷2` のし忘れ。どれも
「やってしまった側の答え」なので、読まないと選べない。

誤答が3つ作れないときは例外で止まる。乱数で埋めない ――
埋めると、読まなくても消せる選択肢が混ざる。

### 消してしまった話

`app/content/math/j1.js` は手書きだった。生成器を作ったとき
**同じ道に書き出して消した。** 公開サイトに古い版が残っていたので
取り戻せたが、次は残っていないかもしれない。

いま j1 の手書き分は `gen_math.py` の `J1_TERMS` / `J1_QUIZ` にある。
教材の出どころを1か所にまとめておけば、同じ消し方はしない。

## 12. Safari で全ページが縦一本になった（2026-08-22）

`#app` は縦の flex で、`main` の横幅は **引き伸ばし（stretch）** で決まる。
そこへ `container-type:inline-size`（`.bento`）が載っている。

Safari では、引き伸ばしと横方向の閉じ込めが重なると
**横幅が中身の幅まで縮み、全ページが縦一本の細い帯になる。**
Chrome と Edge では起きない。そちらだけ見ていると気づけない。

```css
main{ flex:1; width:100%; … }   /* ★ width:100% を消さないこと */
```

同じ理由で `margin-inline:auto` も単独では使えない ――
引き伸ばされている flex の子に `margin:auto` を足すと、伸長が止まる。
必ず `width:100%` を先に書く。

`app/tools/幅の検査.js` が、本体が中身の幅まで縮んでいないかを見る。

## 20. ノートの宿題を写真で出す（2026-08-22）

```
生徒  ノートに解く → 家で写真を撮る → 宿題の行から出す
講師  評価の行のとなりの「◯まい」を押す → 見ながら4段階を付ける
      → ひとことを書いて「見ました」を返す
生徒  Feedback に ✓ と評価と ひとことが出る
```

紙の宿題は、アプリからは達成が見えない。見えないものは「未提出」にも
数えられないし、褒めることもできない。**紙でちゃんとやっている生徒ほど、
システム上は何もしていないように見える。** 写真1枚でそこがつながる。

### 置くもの・消えかた

    schools/<校舎>/submissions.json      目録（いつ・何枚・見た・ひとこと）
    schools/<校舎>/submissions/<sid>/…   画像そのもの

- **評価（4段階）は ratings.json のまま。** すでに提出率も「要注意の生徒」も
  そこを見ている。二重に持つと必ず食い違う
- 出し直したら **前の写真は消す。** 講師が見るのは最後の1組だけで、
  残せば残すほど消し忘れた個人情報が積もる
- 退塾から6か月で、進捗と一緒に消える（`purge`）。**答案は進捗より重い**
- 読めるのは本人と、そのクラスの担当講師だけ。サーバで必ず確かめる

### 写真は評価のとなりに置く

別画面に飛ばすと「見て→戻って→つける」の3手になり、30人で90手になる。
その場で開いて、その場でつける。

### 合言葉を URL に載せるときの決まり

`<img>` には見出し（Authorization）を付けられないので `?t=` で渡す。
そのかわり **ログには問い合わせを書き出さない**（`log_message`）。
画面を人に見せたときや、ログを貼って相談したときに漏れる。
印刷の紙も同じ経路で、こちらは前から穴が開いていた。

### 評価は毎日テストに効く

紙の宿題で「もうすこし」以下が付いた単元は、その生徒の
「にがてつぶし」に入る（`low_rated_units`）。35日を過ぎたものは効かせない
―― 直したあとも出続けると、直した手ごたえが消える。

## 23. デモは「回している先生」を基準にする（2026-08-22）

採点待ち60件・未確認の写真65件が並んでいた。
**1学期ぶん採点をためている先生は、見習うべき姿ではない。**
デモは、これから使う人が自分の姿を重ねる場所である。そこに
散らかった机を置いたら、散らかった机が普通だと伝わる。

いまの作り

| | 数 | 考え方 |
|---|---|---|
| 提出 | 90% | 声をかける相手が1〜2名。10割にはしない |
| 手が要る宿題 | 6件 | 枠の3割だけが今週まだ途中。残りは付け終えている |
| 未確認の写真 | 11件 | 同上。手を付けていない枠の最新回だけ |
| 要注意の生徒 | 22名 | 正答率5割未満 |

### 数え方の決まり

- **先週までのぶんは終わっている。** 手元に残るのは今週の分だけ。
  枠ごとに「今週すでに手を付けたか」を決め、3割だけを途中にする
- **出していない子にも 0（出ていない）を付ける。** 付けないと、その回は
  永久に「採点待ち」に残る。評価を付けない限り rated < assigned のままだから
- **札と一覧は同じ規則で数える。** 一覧は3週間より前を畳んでいるので、
  札も同じ線で切る。札に9、一覧に6と出ると、どちらが本当か分からなくなる
- **線を層に重ねない。** 要注意の線を6割にすると、60%あたりの層が
  ゆらぎで半分こちら側に落ちる。5割にすれば、どの見方でも本当に手が要る子になる
