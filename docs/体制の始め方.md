## 2. main を守る代わりにすること（無料版。5 分）
無料の私有リポジトリでは、「検査が赤（✗）なら merge ボタンを押せなくする」「担当の線（CODEOWNERS）に沿って承認を必須にする」は使えない（GitHub Pro・Team の機能。料金表で確かめた）。検査そのものは無料でも PR のたびに流れ、✓ か ✗ が付く。代わりに次で守る：
- **merge は本人だけが、PR の ✓ を見てから押す。** ✗ のときは押さず、Claude に「直して」と言う。
- **Claude のセッションは main に直接 push できない**（番人 `.claude/hooks/guard.py` が `git push origin main` と `--force` を止める。`scripts/check/test_guard.py` で確かめている）。枝への push は Claude がする。PR を作る・merge・Secrets を置くのは本人。Claude は GitHub の token を鍵束から取り出さない。
- `.github/CODEOWNERS` は担当の線の記録として置いておく（無料の私有リポジトリでは自動の承認依頼は出ない）。`@OWNER` はそのままでよい。
- 人が増えたり、鍵を機械で強制したくなったら、Pro（個人）か Team（組織、1 人あたり月 $4。料金表の 2026-10 の値）にすると、Settings → Rules → Rulesets で main を守れる。
- **毎晩の巡回は GitHub Actions の「巡回」（`.github/workflows/patrol.yml`。2026-10-20）。** 04:00 UTC に本番を読むだけの検査（`scripts/check/expect.py`）を GitHub の Ubuntu が流す。失敗なら issue「巡回 YYYY-MM-DD：失敗」、月曜に通れば控えの PR「巡回 YYYY-MM-DD（週の控え）」。止めるのは置き場の直下に `巡回を止める.txt` を置く。動かすのに要る本人の手は 2 つ（秘密を 1 つ置く・1 回手で流す。4 章）。

Actions タブで「検査」が緑になるのを 1 度見る。「画面の流れ」は画面やサーバに触る PR のときだけ走り（約 30 分）、結果を PR に書く。初回が赤なら、そのまま私に見せる（GitHub の Ubuntu では一度も流したことが無い）。
