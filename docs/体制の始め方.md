## 2. main を守る代わりにすること（無料版。5 分）
無料の私有リポジトリでは、「検査が赤（✗）なら merge ボタンを押せなくする」「担当の線（CODEOWNERS）に沿って承認を必須にする」は使えない（GitHub Pro・Team の機能。料金表で確かめた）。検査そのものは無料でも PR のたびに流れ、✓ か ✗ が付く。代わりに次で守る：
- **merge は本人だけが、PR の ✓ を見てから押す。** ✗ のときは押さず、Claude に「直して」と言う。
- **Claude のセッションは main に直接 push できない**（番人 `.claude/hooks/guard.py` が `git push origin main` と `--force` を止める。`scripts/check/test_guard.py` で確かめている）。枝への push は Claude がする。PR を作る・merge・Secrets を置くのは本人。Claude は GitHub の token を鍵束から取り出さない。
- `.github/CODEOWNERS` は担当の線の記録として置いておく（無料の私有リポジトリでは自動の承認依頼は出ない）。`@OWNER` はそのままでよい。
- 人が増えたり、鍵を機械で強制したくなったら、Pro（個人）か Team（組織、1 人あたり月 $4。料金表の 2026-10 の値）にすると、Settings → Rules → Rulesets で main を守れる。
- **毎晩の巡回は GitHub Actions の「巡回」（`.github/workflows/patrol.yml`。2026-10-20）。** 04:00 UTC に本番を読むだけの検査（`scripts/check/expect.py`）を GitHub の Ubuntu が流す。失敗なら issue「巡回 YYYY-MM-DD：失敗」、月曜に通れば控えの PR「巡回 YYYY-MM-DD（週の控え）」。止めるのは置き場の直下に `巡回を止める.txt` を置く。動かすのに要る本人の手は 2 つ（秘密を 1 つ置く・1 回手で流す。4 章）。

Actions タブで「検査」が緑になるのを 1 度見る。「画面の流れ」は画面やサーバに触る PR のときだけ走り（約 30 分）、結果を PR に書く。初回が赤なら、そのまま私に見せる（GitHub の Ubuntu では一度も流したことが無い）。

## 4. クラウドと iPhone ―― 5 つのチャット（2026-10-20 に Claude が作った。本人の手は済み）
10-20 までに済んだこと：巡回の秘密 `TUBE_DEMO_ACCOUNTS_B64` を置いて巡回を 1 回流した（262 件通過）。Claude の GitHub App を autumn07020 に入れ、claude.ai/code に環境「TUBE study」を作った。そのあと Claude が、分野ごとのチャット（routine）5 本と、issue で起きる仕掛けを作った（`knowledge/40-運用/routine.md`）。

**使い方（iPhone・iPad・Mac のどれでも）**
1. **分野のチャットに書く**：Claude のアプリ → Code → `tube-schools` → セッションの一覧から「TUBE コード」「TUBE デザイン」「TUBE 運用」「TUBE 法務」「TUBE 資料」の最新の実行を開いて、続きを書く。その会話の指示は issue より先に動く。
2. **issue で頼む**：GitHub のアプリ → `tube-schools` → Issues → New → 雛形（コード・仕様／デザイン／運用・データ・デバッグ／法務・申請／資料）を選んで書く。分野のラベルが付き、そのチームの routine が数分で起きて拾う。終わると PR が立ち、issue に link が付く。
3. **merge する**：PR の「検査」（と、画面やサーバに触ったときは「画面の流れ」）が緑なら、GitHub のアプリで Merge を押す。赤なら issue に「直して」と書く。
4. **本番へ反映する**：Mac で `cd ~/Projects/tube-schools && git switch main && git pull` のあと `sh deploy/更新.sh`（本人だけ）。
5. **止める**：全チームを止めるなら、リポジトリの直下に `チームを止める.txt` を置く（GitHub のアプリの「Add file」でよい）。巡回を止めるなら `巡回を止める.txt`。1 本だけなら https://claude.ai/code/routines で切る。

**仕組みの要点**
- routine は決まった時刻（コード 05:00・デザイン 05:30・運用 06:00 UTC は毎日、資料は月曜 07:00、法務は月曜 08:00 UTC）と、GitHub の issue の出来事（立てる・ラベルを付ける・閉じる）で起きる。issue が無い実行は数秒で終わる（knowledge を読まない）。
- 指示文の原本は `.claude/routines/`（共通.md と分野ごとの 1 枚）。直して PR → merge すれば、次の実行から効く（routine は main のファイルを先に読む）。
- クラウドのセッションには本人の claude.ai の道具（Claude Docs・Google Drive）がつながる。本番の鍵・合言葉は置かない。
- iPhone：GitHub のアプリ（issue・PR の merge・Actions の結果）と Claude のアプリ（チャット）。Working Copy は 1 行直すときだけ。
- Remote Control：Mac が起きているあいだは、iPhone の Claude から Mac のセッションも続けられる（蓋を閉じると眠る）。
