# やめ方と引き継ぎ（下書き。稟議の別紙の案）

前回の稟議で本部が挙げた「依存が深まる」への答えは、機能を足すことではなく、**いつでもやめられ、誰でも引き継げる**ことの証明。この 1 枚は、校舎の名で出す文書の下書き（名義・連絡先は法務と校長が決める）。

## 1. 止まった日にどうするか
- 道具が開けない・写真が出せない日は、**その回の宿題は紙で提出**に切り替える。講師は「今回は紙で」と授業で言うだけ。生徒の画面には「いまは紙で先生に出してください」と出す（道具が動かないときの案内文は静的な頁として別に置く）。
- 復旧の手順と連絡先は `knowledge/40-運用/障害時の手順書.md`（2026-11-04）。復元の練習の記録は `knowledge/40-運用/復元の練習.md`。
- 評価とひとことの記録は毎晩の控え（バックアップ）から戻す。戻せる範囲（直近 1 日まで）を明記する。

## 2. 運営費の持ち主と上限
- 運営費（サーバ・配信・控え）は月額 £110 の定額（2026-10-12 の稟議書）。校舎の裁量の枠（月 5〜6 万円相当。元の控えは要確認）の内。
- 外の AI・外の連絡サービスは使わない（費用と、子どものデータを外へ出さないため）。費用が増える機能は入れない。

## 3. 2028 年 6 月以降の出口（作った人がいなくなるとき）
- 本人の在留は 2028-06-15 まで。その前に、次の 3 つのどれかを校舎が選べる状態にしておく。
  1. **本部の仕組みへ移す**：記録を本部の形（CSV・PDF）で書き出して渡し、道具は止める。
  2. **校舎で続ける**：後任（校舎の職員か外の保守者）が手順書だけで運用できる形。保守する面は小さく保つ（下の 6）。
  3. **畳む**：記録を家庭と校舎に書き出し、保持期間のとおり消し、サーバを止める。
- どれを選んでも、**家庭の手元に「この子の 1 枚」（評価・ひとこと・毎日テストの要約）を残せる**ようにする（候補 1 の絞った形）。

## 4. 本部の形で記録を書き出す約束
- 書き出せるもの：クラス・生徒 ID・宿題の一覧・提出の有無・評価・ひとこと・返却の有無・毎日テストの記録・保護者からのメッセージ。氏名は持っていないので出ない（席と ID の対応は校舎の表で結ぶ）。
- 形：CSV（UTF-8）と PDF。本部の仕組みが決まれば、その取り込みの形に合わせる。
- いつでも校舎の管理ページから流せる（本人の手を要しない）。

## 5. ソースと手順の預け先
- ソース・手順書・知識は GitHub の私有リポジトリ（Git）。校舎（と本部が望めば本部）に閲覧の権限を渡す。預け先を第三者（例：校舎の指定する口座）にも写す。
- 鍵と合言葉の表は校舎が持つ。本人が持ち続けるものを無くす。
- 更新の手順（反映）は 1 本の命令。後任が 10 分で流せる。

## 6. 保守する面を小さくする
- 外の部品に頼らない（標準ライブラリだけのサーバ・自前の QR・自前の検査）。
- 機能を足すときは、必ず「やめられるか」「書き出せるか」「後任が読めるか」を先に書く。
- 検査は GitHub Actions が毎晩流す。失敗は issue になり、校舎に見える。

## 7. まだ決まっていないこと
- 名義（データの管理者は校舎）と連絡先。
- 「3 か月使われない口座は消える」は本番に切り替えてから動く。切替（go-live）の日。
- 後任の候補（校舎の職員か、外の保守者か）。
