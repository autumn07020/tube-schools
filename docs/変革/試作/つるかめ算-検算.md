# 試作：つるかめ算の「解き方を走らせる」（2026-11-04）

`docs/変革/試作/tsurukame/tsurukame_engine.py`（純 Python・150 行・外の部品なし・LLM なし）。正しい手順 R と誤りの型 E1〜E8 を同じ形の「手順」として持ち、1 つの解釈器で走らせる。

## 出た数（批評 第 4 回の条件に当たるもの）
| 数 | 結果 |
| --- | --- |
| 類題 200 問の検算（正しい手順の答え ＝ 数え上げ） | 食い違い **0 件** |
| 答えだけで誤りの型が一意に引ける割合（8 型・200 問・問われる量は鶴か亀を無作為） | **74.5%**（研究の 86%（2018）と 29.4%（2025）のあいだ。手順が 4 段と短いので高い） |
| 正しい答えと一致してしまう誤りの型 | E2（亀を答える）と E4（頭から引くのを忘れる）が 200 問中 98 問。**亀を問う問題では、これらの誤りは正解と同じ答えになる** → 問う量を鶴に変えると見える |
| 型どうしが同じ答え | E2 と E4 は 200 問中 200 問で同じ（最終の答えだけでは区別できない。違いは途中の 1 行＝「頭から引いたか」）。E6 はそれらと 113 問 |
| 判別の数 | E1 対 E2・E1 対 E7・E3 対 E5 は 1 問で分かれる数がある（例：頭 8・足 26）。E2 対 E4 は数では分かれない → **途中の数を 1 つ打ってもらうか「どっちで解いた？」を 1 回押す**（第 5 版 段 1 の 2 と一致） |
| 端の場合（頭 6） | 全部が亀（足 24）：正しい手順は鶴 0、E1 は 3、E3 は 12、**E5 は −6**、E7 は 4。全部が鶴（足 12）：E2・E4・E6 は 0（正解は 6）。足が奇数（足 15）：正しい手順でも 4.5 羽 → 「問題として成り立たない数」と見せられる |

## 分かったこと（設計への含み）
1. **問う量を変えるだけで見える誤りがある。** 亀を問う問題では E2・E4 は正解に化ける。判別の数の探索は、数だけでなく「問う量」も変える。
2. **最終の答えだけで区別できない型の対（E2/E4）がある。** 第 5 版の「途中の数を 1 つ任意で打つ」と「2 本の道筋を並べて 1 回押す」は、この対のためにある。
3. **端の場合は、誤った手順の崩れを数で見せられる**（鶴が −6 羽、亀が 12 匹で頭 6 を超える）。「崩れた行を指す」の材料は機械で作れる。
4. 解釈器は eval を使わない小さな式の評価器で足りる（+ − × ÷ と括弧）。単元の表は手順の列（4 段）だけ。**2 単元目は表を書くだけ**で、解釈器・逆引き・判別の数・検算はそのまま使える見込み。
5. まだ無いもの：画面、戻りの日の予定、部品の札（段 2）、割合の表（2 単元目）。
