# 技術の棚卸し（調査員の報告。判断はしない）

見た日はすべて 2026-11-04。検索 22 回・頁の読み取り 3 回。検索の要約だけで原典を読めていないものは「要確認」と書いた。

## 要約
- 手書きの答案を読む部分は、数式なら「オープンな学習モデル＋公開データ」が揃ってきた（Google の MathWriting、TrOCR の派生）。ただし**どれも大人の手書き**で、子どもの手書きと日本語の漢字での精度を示す出典は見つからなかった。精度は自前の答案で測るしかない（事実：出典なし）。
- 子どもの答案を外に出さずに読む道は、技術上はある（ブラウザ内で ONNX 実行の PaddleOCR、Apple の端末内機能）。ただし**手書き日本語の精度の数字は見つからず**、自前の答案での試験が先に要る。
- 問題の自動生成は「LLM に式を作らせ、記号計算で解く・見積りで照合する」型が研究にある。ただし生成した類題の誤り率を測った出典は見つからなかった。検証を機械側に持たせる設計が要点。
- 知識の構造：米国は Common Core の前提関係を開いたデータ（Learning Commons）で配っている。日本の学習指導要領には、同じ形の公開データは見つからなかった（民間の系統一覧表のみ）。中学受験算数の単元図は公開された形では見つからず、**ここは現場の知識が堀になる**（推測）。
- 知識追跡：少ないデータでは Elo 型や単純な回帰が堅く、深層の手法は差が小さい（3 件の出典）。215 名の塾では BKT・Elo・ロジスティック回帰が現実的（推測）。
- 間隔反復：FSRS は公開の大規模比較で SM-2 に勝つと報告され、実装は公開されている。1 人で作る部品として最も軽い。
- 子どものデータの扱い：外部の生成 AI への入力に学習利用・流出の懸念を示す学校向け資料がある。API 側は「既定で学習に使わない」とされるが保持期間の資料が食い違う（要確認）。端末内・自前・仮名化を基本に置く設計は文書の面で筋が通る。

## 生の声
個人が特定できない形に言い換え、30 字以内。
- 「書き順が合っていても、とめ・はねが雑だと×になる」（漢字アプリのレビュー）
- 「手書きの数式は入れ子で、読み取りがまだ難しい」（中国の技術レビュー）
- 「大規模言語モデルは正しい途中式を誤判定しうる」（中国の報道）
- 「手書き認識は自前の答案で試せ」（複数の開発者記事の共通の勧め）

## 声になっていない兆し
事実：
- 数式の手書き認識の公開データは大人のものだけで、**子どもの手書きと日本語の学年別漢字の公開データは見つからなかった**。
- 日本の国内製品は「答えの正誤」を読むところまでで、途中式や詰まり方の診断まで出ているものは確認できなかった。
- 米国は前提関係の開いた図を配っているが、日本には同じものが見つからなかった。

推測（確かめていない）：
- 校舎で集める**子どもの手書き答案＋講師の評価**は、公開データにない学習用の資産になりうる。ただし保護者の同意・個人情報・許諾の整理が先（法務の確認が要る）。
- 中学受験算数の「詰まり方」の分類（誤概念の図）は、日本語の公開版が無い。講師の知識で作れる余地がある。
- 検証を機械に持たせる類題（式・パラメータで持つ）は、LLM に自由に作らせるより事故が少ない。
- 少ないデータでは複雑な追跡モデルより、単元の図＋単純な更新式＋講師の評価を重みにした現行の理解度（insight）の延長が堅い。
