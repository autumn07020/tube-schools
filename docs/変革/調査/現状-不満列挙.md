# 現状の不満列挙（不満列挙法の材料）

調べ方：リポジトリの記録だけを読んだ（web は使っていない）。読んだもの：`CLAUDE.md` の「本人」の引用、`knowledge/20-決まり`・`70-決定録`・`90-種.md`・`10-現状.md`、`docs/作業記録`・`docs/週報`・`docs/SPEC.md`・`docs/archive/HANDOVER.md`、`outputs/デザイン引き継ぎ/04-新しい見た目の方向.md`、`outputs/見た目リデザイン案を読んだ記録.md`、`outputs/引き継ぎ書-TUBE study の全体像.md`。判断はしない。事実（出典あり）と推測を分けて書く。講師の名字は書かない。なお `docs/変革/00-計画.md` は、この調査の時点でリポジトリに見つからなかった（読めていない）。

## 要約

- 記録に残っている不満の大半は **開発者本人（時間講師）の「本物として動いていない」への叱責**で、価値の薄さではなく**張りぼて・表面だけ・途中・見た目のずれ**に集中している（10-08〜10-13、10-20）。ここから「本人が最も嫌うのは、動くふりをすること」と読める。
- **経営・本社側の不満は 9/14 の専務の 5 つの意見に集約**される（依存のリスク・早稲アカOnline と同じ・講師の負担が増える・使わない講師への批判・宿題を管理させる正義）。TUBE study は「構造で消す」作りをしてきたが、**「減る証拠」はまだ無い**（引き継ぎ書 2.3）。
- **講師・生徒・保護者の不満はほぼ「本人の推測と観察」で、現場の生の声の記録が無い**。生徒・保護者の声は、本人の判断（順位を出すとやめる・％でがっかりする）が代わりになっている。ここが最大の空白で、後半の仮説 H1〜H20 はこの空白を埋める推測である。
- 開発運用の不満（Mac 依存・本人の手が要る反映・PR の待ち・検査の偽陽性）は多く、半分は 10-13〜11-03 の体制づくりで途中まで解けた。ただし「本人の手が要る」ものは名目上解けても、本人の時間という制約は残る。
