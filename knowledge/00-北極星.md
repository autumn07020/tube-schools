# 北極星 ―― 目的とデザイン哲学（圧縮のあとに必ず読み直す。2026-09-24）

文脈の圧縮で少しずつ薄れるものを、ここに固定する。着手前・圧縮のあと・迷ったときに読む。
細部は各文書（docs/DESIGN.md／docs/デザイン仕様書.md／CLAUDE.md／docs/SPEC.md）へ。ここは**判断の軸だけ**。

## 1. 大目標
- **一講師として、ロンドン校の役に立つ。** 講師の時間を授業へ。生徒の宿題と成績の「あいだ」を仕組みで支える。
- 買い手は組織ではなく、**現場の講師と生徒**。組織のシステム（早稲アカOnline）と比べさせない。売り文句を作らない。
- **スロースタート・部分導入**が前提。使う講師だけ、使う教科だけ、使う深さだけ（導入の段階 0〜4）。
  使わない講師には何も要求しない。紙のクラスと半年以上混在しても便利であること。
- 本導入は **2026-10-15**（遅らせてもよい。遅くとも 10-31。2026-09-30 本人：妥協は要らない、全部を完成させる）。壊れない・嘘をつかない・戻せる、が価値より先。
  （2026-10-12 の稟議書で、**11 月から講師の希望制の試運用**に変わった。`70-決定録/2026-10-12-稟議書.md`）
- **2026-09-30 本人：これからお金をいただいて実際に運用する。** 張りぼては不可。見た目だけでなく、本当に使いやすいか・価値があるか・バグが無いかを、毎回ぜんぶ確かめて進む。
  席（ID と合言葉）・講師・担当は管理ページ（/admin）で足し引きする。**サーバは合言葉そのものを受け取らない（作るときも、入るときも）。** 紙はカード（QR）、オンラインは1回だけ使えるリンクで渡す。本物の校舎は `waseaca-london`、`london` はデモ。

## 2. 誰のために
- 講師：コンピュータが苦手な人が前提。覚えることを作らない。数字は入力させず、押すだけ。
- 生徒：小4〜中3。小5以下はかな多め（`jp()`）。小6以上は講師と同じ漢字。
- 保護者：生徒の端末の中の「保護者の方へ」。別の口座は作らない。
- 遠くのスクリーンで見る50代の人にも分かる大きさと言葉（プレゼンの教訓）。

## 3. 圧倒的なわかりやすさ
- 1画面に「**次にやる1つ**」を先に出す。大量のタスクを並べない。
- 見出しは**日本語だけ**、中身をそのまま言う短い名前。タブと同じ中身ならタブと同じ名前。英語を添えない。
- 抽象的な言い回しを使わない。**動作だけを言う**（写真を選ぶ・数字を押す・赤を入れる・返す・足す）。
  「赤ペン」「先生の目」「あたたかみ」の類は禁止（本人）。
- 数字には必ず根拠を添える。分からないものを 0 と出さない。紙の子を不真面目に見せない。
- 小さな添え書きに頼らない。読む時間が無い前提で、大きな文字だけで伝わるか。

## 4. 美しさ
- **線を引かない。** 面と地の明度差、影（髪の毛ほどの縁＋近い影＋遠い影）、上辺の光で面を立たせる（Apple のウィジェット）。
- 色はワセアカの青と黄（#004E93 / #0A6FC7 / #F9B900）。教科の色は薄く（`.sjt`）。達成の黄は濃い所を狭く。
- 角は大きく（面 22px）。絵文字・記号アイコンを使わない。階層は大小と余白で作る。
- 押せるものは必ず押せる。押した手ごたえ（沈む）。44px の当たり判定。
- 同じ概念は同じ見た目。新しい部品を作る前に、ある部品で書けないか。

## 5. 単純な論理
- 概念を増やさない。増やすなら、既存の概念で置き換えられないか先に考える。
- 推測より明示。発行のときに確定させ、出したあとの記録を書き換えない。
- **判定はサーバ。** 画面の出し分けは判定ではない。校舎は合言葉から引く。パスは paths.py の中だけ。
- 5週周期（単元確認テストは35日ごと）。月や年の単位が出たら設計が外れている。
- 誰にも追加入力をさせない（経路は教材の性質で決まる）。
- 鍵は1つ（`paths.GUARD`）。確かめてから使うまでのあいだに、誰にも割り込ませない。生徒を数える所は `role == "student"` で数える（渡していない席を混ぜない）。

## 6. ガバナンス（変えない）
- 氏名・住所・電話をサーバに置かない。教材データを置かない。本部のシステムに触れない。
- 本番の反映・本番へのログインは本人の操作。私は命令を渡すだけ。
- 前身 `../myenglish/` を変更しない。サブエージェント・Workflow を使わない。

## 7. 検査と自律
- 「動く」ではなく「**意味が合っている**」を確かめる（scripts/check/expect.py・前回との差 ledger）。
  減った数があれば、理由を言えるまで写さない。不具合を1つ直したら不変条件を1つ足す。
- **指示の範囲内は、聞かずに完了まで進める。** 範囲外・権限の拡張は、提案して止まる。
- 作業の最後に `knowledge/90-種.md` へ1つ以上書き、効果大・手間小のものを1つ提案する。
