# 全体の仕組み（事実）

## 校舎と役割
- マルチテナント。本物の校舎 `waseaca-london`（コード w）、架空のデモ `london`。本物の校舎があるとき、デモの入口は `/demo`。デモの作り直しはサーバを止めない（demo-swap。一覧が london の口座だけのときしか上書きしない）。
- 役割は 4 つ（`ROLES`）：student／teacher／seat（まだ渡していない席。名簿にも宿題にも出ない）／admin（/admin だけ。答案も記録も読めない）。生徒を数える所は `role == "student"`。
- 席が在籍になったら、その場で期限前の宿題に足す（`join_open_homework`。入るたびに）。クラス全員の提出箱（期限前）も足す。選んだ生徒だけの箱（picked）・上位（extra）・個別（personal）は足さない。

## 入る口と合言葉
- **サーバは合言葉そのものを受け取らない（作るときも、入るときも）。** `/api/login/start`・`/finish`（`server/scram.py`・`app/js/scram.js`。SCRAM-SHA-256 の考え方）。`app/js/scram.js` を直したら `紙の宿題/web/js/scram.js` へ写す。
- 渡し方：紙はカード（管理ページの「カード」。QR は `入口#k=ID.合言葉`）、オンラインは 1 回だけ使えるリンク（本人の端末が合言葉を作る。`/api/claim`）。
- 入口の見張り：同じ相手×同じ ID 8 回／同じ ID に 300 回／同じ相手から 200 回（15 分）。429 は `/api/login/start` でも返る。締め出したら管理ページの「報告」に出る。
- 鍵は `paths.GUARD` の 1 つ（スレッドにもプロセスにも効く）。
- トークンの期限：生徒 14 日・講師 12 時間・管理者 8 時間（30 分の無操作）。

## 初回登録と匿名の口座（2026-10-01）
- 塾は ID と名前を結ばない。学年・クラス・科目は保護者の自己申告。登録コード（QR・6 桁、1 文字ずつの枠）から登録。ID は生徒 `s-000`（無作為・再利用）、講師 `t-001`、開発者 `d-001`。
- 順：ようこそ → できることの動画（全画面）→ 学年・クラス・科目 → 確かめる → ID と合言葉 → 完了。文言の原本は `outputs/設計-初回登録と匿名の口座.md` と `app/js/ui-join.js`。
- 続き：設定で科目・クラスを変える、管理ページの俯瞰、組分けの申告（テストの日程の 7 日後から 2 週間）、対面採点（ID の帯をなぞる）、3 か月使われない口座の破棄（`server/retire.py`。本番の校舎だけ）、学年の繰り上げ（管理ページに日付を 1 つ・中3 は切り替えの日に卒業・小6→中1 は本人に聞く）。
- 「個人情報を保存しない」とは書かない（記録と答案の写真は ID に結びつけて保存する。UK GDPR では個人データ）。
- 本番の登録コードは管理ページで作る。本番では `index.html` の trial-join-code.js の 1 行を消す（ためし運用のあいだは先に入る）。

## 提出箱と過去問（2026-10-11〜12）
- 提出箱（`make_quiz`）に種類 `kind`（`QUIZ_KINDS`：漢字テスト・計算テスト・英語テスト・作文・過去問の添削）と相手 `students`（選んだ生徒だけ＝印 `picked`）。回の名札が種類。宿題チェックは「種類でしぼる」と 12 回ぶんの回の札。
- 追加の宿題は上位（`extra`）と個別の決まり（`personal`）で普段の回の束に入る。評価は束に 1 つ。成績の種類別の集計はまだ無い。
- 生徒側：「提出」（上にテストの提出箱、下にいつもの宿題）。中3 と小6（K 以外）には「過去問」のタブ（`me.grade` で判定。`me.stu.level` は存在しない）。小6K は高校受験向けにゆっくり進む学年で過去問演習は無い。
- 過去問のデータは提出箱そのもの（1 本＝1 箱）。講師は授業計画の紙で種類「過去問の添削」→ 年度と学校 → 題「年度 学校 教科」。消すのは同じ紙の一覧（出した生徒がいる箱は 409 で消せない）。デモの見本は中3R 数学・小6α/β 算数（`server/demo_trial.py` の `KAKOMON`）。
- 写真の向き（デモ）：国語は横長、ほかは縦長（`demo_running._dims`）。

## ためしのデモ（2026-10-12）
- `server/demo_trial.py`：席を先に、足りなければ在籍の生徒。クラスごとに 5〜15 人（`SEED` 固定）。demo の印＋席だった印 `demoRole`。全講師の全コースに計画・学期ぶんの宿題・写真・評価・毎日テスト（段階 4）。講師ごとに 1 つ、きのう期限の提出箱に未評価の写真。入口の生徒は学年ごとに 2 人 → `school.json` の `trialPick`。
- `--clean`：記録・印を消し、席だった口座は席に戻す。go-live で生徒ごと退避。
- 手元の土台は `scripts/check/flows/reset.sh`（クラスごとに席 10 を足し `--keep`・`--pick-classes`。約 4 分）。

## 宿題の往復で直した根本（2026-10-10）
- 提出箱の期限は既定 7 日後。講師の「今日やること」と回の一覧は「期限が来た回」だけだった → `_paper_due` に「写真が 1 枚でも出ている回」を足した。
- 授業計画の無いコース（本物の校舎は全コース）でも提出箱を出せるようにした。
- デモ校（london）の生徒と本物の校舎の講師では何も届かない（校舎が違う）。本物の校舎は授業計画が無いので自動の宿題は出ない。計画を原本から作る仕組みはまだ無い（種）。

## カリキュラムの原本（2026-10-08）
- 第一信頼情報源は `カリキュラム/カリキュラム.json`（本部の PDF 8 本から起こした。PDF は Git に無い）。人が読む形は `カリキュラム.md`。作り方は `scripts/curriculum/`（compose.py → render.py）。JSON を手で直さない。
- サーバは `server/curriculum_source.py` だけから読む（シラバス 43 本 `<クラス>-<教科>-2026b`、休みの週、組分けの既定、本部基準）。日程表の「第N回」は週の帯。
- 時間割の元は `カリキュラム/時間割.csv`（講師の名字入り。Git に入れない）。`scripts/curriculum/時間割/build.py` が `時間割.json`・`コマ.csv`・`担当.csv`（ID だけ）を作る。本番へは `sh deploy/時間割.sh`（時間だけ）と `sh deploy/担当.sh`（講師だけ）。
- 本番の計画は講師が画面で作っていて原本と結びついていない → 進み具合は数えず「今週の本部の予定」だけ出す。

## できることの動画（2026-10-12）
- `scripts/video/intro.py <作業の場所> --base http://127.0.0.1:8951 [--preview] [--only phone]`。ためしのデモを別の置き場（W/vreal）に写して `serve --port 8951 --demo` で起こし、中3R の見本の生徒で Chrome から撮る。PIL で組み、numpy の音、imageio-ffmpeg の ffmpeg で H.264＋AAC（brew は無い。`python3 -m pip install --user imageio-ffmpeg`）。
- 出力 `app/media/intro-phone.mp4`（1080×2340）・`intro-ipad.mp4`（1536×2048）・`intro-pc.mp4`（1920×1080）。画面は `introKind()` が画面の比で 1 本を選び、`.jn-full`（fixed・inset 0）＋`object-fit: cover` で端まで。端に字と写しを置かない（`SAFE`：電話 上下 240px・iPad 200px・PC 左右 290px）。印の輪は icon.svg と同じ（半径 40・太さ 13）。
- 画面を変えたら動画も作り直す（場面は `scenes_for`）。撮り直し＋3 本で 8 分ほど。確かめは adm_flow16（占有率 100% を数で）。
