# TUBE study 技術仕様と法的対応の一覧

Oct 13, 2026 · @Kentaro Aki

早稲田アカデミー ロンドン校の宿題サービス TUBE study（tube-study.uk）について、いま動いている仕組みの技術仕様と、実装・運用に伴って法的に行うべきことを、リポジトリの文書（SPEC・SECURITY・DPIA・IP・OPERATIONS・CLAUDE.md・deploy/）とコードから起こした一覧です。法的な項は法律の専門家の助言ではなく、英国のデータ保護法に詳しい solicitor か DPO に確かめる前提の下ごしらえです。

## 1. 全体像

TUBE study は、塾の宿題を「出す・写真で提出する・評価と添削を返す・記録を残す」ためだけの Web サービスです。生徒と保護者はスマホ・iPad・PC のブラウザで使い、アプリのインストールは要りません。氏名・連絡先はサーバにも校舎にも置かず、ID だけで区別します。

| 項目 | いま（2026-10-13） |
| --- | --- |
| 本番 | https://tube-study.uk。AWS Lightsail（ロンドン eu-west-2）1 台。外向きの口は開けず、Cloudflare のトンネル越しに配信 |
| 校舎 | 本物：waseaca-london（早稲田アカデミー ロンドン校）。デモ：london（架空の校舎。実在の生徒はいない） |
| 状態 | 試し運用。全講師の全コースに架空の記録（demo\_trial.py）。入口に「ためしに見る」が出て、講師 6 人と学年ごとの生徒 2 人で入れる |
| 使う人 | 生徒（小4〜中3）、保護者（生徒の端末の「保護者の方へ」。別の口座は作らない）、講師 7 人、管理者 |
| 導入 | 講師の希望制。コースごとに段階 0（紙のまま）〜4（毎日テストまで）。紙のクラスと半年以上混在する前提 |
| 次 | 11 月から本導入。`deploy/本番切替.sh` で試しの口座を退避し、登録コードを配って保護者が自分で登録する |
| 作り | サーバは Python 3 の標準ライブラリだけ（依存パッケージ無し）、画面は素の JS・CSS（ビルド無し）。データは校舎ごとの JSON ファイル |
| 費用 | サーバー費・維持費として月額 £110（稟議書の計上額）。AWS の実費は月 $6〜8 程度＋ドメイン代（deploy/README.md の実測） |
| 運用者 | 開発者（講師 wt01）が 1 人で保守。本番への反映・切替は本人の端末から `deploy/*.sh`。単一障害点（第 8 節） |

## 2. 構成

通信はすべて Cloudflare を通り、サーバは外向きの口（80/443）を開けていません（`deploy/aws.sh`）。サーバの中では Python の標準ライブラリだけで書いた 1 つのプロセス（`server/tube_server.py`、systemd の myacady）が 127.0.0.1 で待ち、画面（`app/`）の配信と `/api` の両方をします。データベースは無く、記録は `/srv/myacady/` の JSON ファイルです（移す・戻すは rsync で全部）。

## 3. データ

持つのは「ある ID の生徒が、どのクラスで、何をどうやったか」だけです。氏名を受け取る口そのものが無く（名簿の取り込みは氏名の列を拒む）、ID と氏名の対応表は 10-01 から校舎も持ちません（保護者が自分で登録し、ID は家庭が持つ）。ただし、氏名と結びついていなくても、これらは UK GDPR では個人データ（仮名化されたデータ）です。小人数のクラスでは記録から本人を思い当たることがあり得るので、「匿名」とは書きません。

**持つもの**（すべて `schools/<校舎>/` の中。サーバは合言葉から校舎を引き、要求が名乗る校舎を信じない）

| ファイル | 中身 | 個人データか |
| --- | --- | --- |
| accounts.json | ID、無作為の内部番号（sid）、役割（seat・student・teacher・admin）、学年・クラス・受講科目、合言葉を確かめる値（salt・storedKey・serverKey。合言葉そのものは無い）、使った日、クラス替えの履歴 | はい（仮名） |
| assignments.json | 宿題・提出箱：題・範囲・期限・受け取り手の sid | はい |
| submissions.json と submissions/\<sid>/ | 出したノートの写真・PDF、講師が見た時刻・ひとこと・返した添削、過去問の点数（本人が書く） | はい（写真に氏名や顔が写り込むことがある） |
| ratings.json | 紙の宿題の 5 段階の評価、「理解が心配」の印 | はい |
| progress/\<sid>.json・summary/\<sid>.json | アプリ（毎日テスト）の記録と講師向けの要約 | はい |
| scores.json・weak.json・notes.json・personal.json | 塾内テストの点、落とした単元、講師だけの特筆事項、生徒ごとの宿題の決まり | はい |
| messages.json | 保護者から講師への文と返事（自由記述。氏名を書き込むことがある） | はい |
| audit.log | 誰が・いつ・何をしたか（ts・actor・action・target・extra。追記だけ。IP は書かない） | はい |
| school.json・curriculum.json・lessons.json・materials.json・exams.json・presets.json・sheets.json・insight.json・reports.json | 校舎の設定・クラス・コース・授業計画・教材の記号・テスト日程・登録コード・報告 | 報告は自由記述。ほかはいいえ |
| ルートの index.json・tokens.json | ID→校舎の索引、入ったままの印（SHA-256 のハッシュ。生徒 14 日・講師 12 時間・管理者 8 時間） | はい（仮名） |
| 端末の中（localStorage） | 入ったままの印、画面の好み、送る前の写真。Cookie は使わない | はい（端末の持ち主のもの） |

**持たないもの**：氏名・生年月日・住所・電話・メール・保護者の情報・支払い・位置情報・端末の識別子・追跡 Cookie・広告・外部の解析・特別カテゴリのデータ。市販教材の中身（問題文・語・訳）も持たず、ページと番号で指します。

**ID の形**：配った席は `w` ＋ クラス ＋ 番号（wj3r06）、保護者が自分で登録した口座は `s-042`（無作為）、講師は `wt01` か `t-001`、管理者は `d-001`。クラス替えでも ID と記録は変わらず、クラスと番号だけを移します（`move`）。

**校舎ごとの分離**：パスは `server/paths.py` だけが組み立て、生徒に関わる読み書きはすべて校舎を第 1 引数に取ります。別の校舎の記録が見えないことは `server/test_isolation.py` がサーバを立てて確かめます。

## 4. 入る口と鍵

サーバは合言葉そのものを一度も受け取りません。作るときは端末（WebCrypto）が確かめるための値だけを送り、入るときは SCRAM-SHA-256 の考え方（RFC 5802。`server/scram.py`・`app/js/scram.js`）で、サーバが出した使い捨ての数への証明だけを送ります。TLS をほどく Cloudflare もサーバも、合言葉を見られません。

| 項目 | 中身 |
| --- | --- |
| 役割 | seat（まだ渡していない席）・student・teacher・admin。生徒は自分の記録だけ、講師は担当のクラス×教科だけ（同じクラスの別の教科は見えない）、管理者は席・講師・担当・登録コード・報告だけ（答案も記録も読む口が無い）。判定はすべてサーバ。他人の ID を指定しても 403 |
| 合言葉の強さ | 配った席：3 語＋4 桁（約 2³⁷ 通り）、講師：4 語＋4 桁（2⁴⁵）、管理者：5 語＋4 桁（2⁵³）。自分で登録した保護者は 8 文字以上を自分で決める。保存は salt・storedKey・serverKey（PBKDF2-HMAC-SHA256 60 万回）。古い形は入った瞬間に作り直す |
| 入ったままの印（トークン） | 生徒 14 日・講師 12 時間・管理者 8 時間（さわらなければ 30 分）。ファイルには SHA-256 のハッシュだけ。合言葉を作り直すとその場で切れる。nonce は 1 回きり・2 分で、サーバを起こし直すと前の nonce は通らない |
| 入口の見張り | 同じ相手×同じ ID で 15 分に 8 回（IPv6 は /64 を 1 人）、相手を変えても 1 つの ID に 15 分で 300 回まで。入る前の口は本文 4KB まで、何も送らない接続は 60 秒で切る。無い ID でも同じ時間・同じ返事（ID の有無が分からない）。締め出しは管理ページの「報告」に出る（校舎ごと・種類ごとに 1 時間 20 件まで）。相手（IP）は数えるためにメモリでだけ使い、ファイルには書かない |
| 登録コード（招待） | 6 文字（0/O/1/I を外した 32 種）。管理ページの「いまの様子」で作り直し、紙と QR（`入口#join=コード`）で配る。確かめは同じ相手から 15 分に 20 回、登録は 1 時間に 6 回・1 回に 4 人まで。仮の口座は 1 時間で消える |
| 初回登録 | 保護者が学年・クラス・受講科目を自己申告 → ID（s-042）を見せる → 合言葉を本人が作る → 在籍の生徒に。氏名・メール・電話の欄は無い。入ったときに期限前の宿題とクラス全員の提出箱を受け取る（`join_open_homework`） |
| オンラインの生徒への引き換え | 1 回だけ使えるリンク（7 日）。「はじめる」を押した端末が本物の合言葉を作る。リンクにもメールにもサーバにも合言葉は載らない |
| ためしに見る | `--demo` で起こしたときだけ。試し運用の印のある校舎では、講師 6 人と学年ごとの生徒 2 人に ID だけで入れる（管理者には入れない）。本番切替でふつうの入口から消え、デモは /demo だけに |
| 管理ページ /admin | 管理者だけ。席を作る・使う・在籍終了、講師と担当、登録コードと QR、最近の動き、報告、設定。操作は 1 つずつ鍵の中で確かめて書き、監査の記録に残る。管理者は講師を作って担当に付けられるので、信頼できる 2 人まで |
| 確かめ方 | `server/test_admin.py`（426 件）・`server/attack.py`（自己攻撃 56 項目）・`server/test_isolation.py`。2026-09-30 に第三者の検査 2 回（5 人）を受けて直した（SECURITY.md 8） |

**できないこと（正直に）**：画面の JS を書き換えられる相手には効かない（TLS と CSP が前提）。入ったあとの印は Cloudflare とサーバの中では読める。サーバの保存と入る手順の記録の両方を手に入れた相手はその人として入れる（漏れたら全員の合言葉を作り直す）。合言葉の作り直しは「ID を言えた人」に渡すことになる（氏名と結んでいないので本人確認は対面で）。

## 5. 画面と機能

| 使う人 | 画面 | できること |
| --- | --- | --- |
| 生徒 | ホーム | 今日やること（次にやる 1 つを先に）、今週の輪と今週の目標、自分の記録。宿題はカリキュラム（カリキュラム/カリキュラム.json が第一信頼情報源）から授業回ごとに自動で出る |
| 生徒 | 提出 | 上に小テストの提出箱、下にいつもの宿題。ノートの写真か PDF を 10 枚まで（端末で縮めて JPEG に）。紙の宿題は未提出に数えない |
| 生徒 | 毎日テスト | 段階 4 のコースの教科だけ。間隔反復（SRS）で自動に組む。点数と順位は出さず、続いた日数だけ |
| 生徒 | 過去問 | 中3と小6（小6K を除く）。学校ごと・年度順の一覧、出す・添削を見る・点数を自分で書く |
| 生徒 | 先生から | 評価・コメント・返ってきた添削、お知らせ |
| 生徒 | 設定 | クラスと受講科目を変える、組分けの申告、返った添削を消す |
| 保護者 | 保護者の方へ（生徒の端末の中） | 教科ごとの成績の伸びと今週の目標、講師へのメッセージと返事。別の口座は無い |
| 講師 | 宿題 | 今日やること（未評価の回）、宿題チェック（1 画面：写真・5 段階の評価・ひとこと・ペンでの添削・PDF・紙の取り込み）、時間割、授業計画（回ごとの宿題を直す・ずらす・止める、提出箱を作る・消す、学期の予定、上位の指名、にがてを集めて出す）、保護者からのメッセージ |
| 講師 | 成績 | 担当コースの一覧とテコ入れ候補、生徒ごとの個票（理解度・落とした単元・特筆事項）、塾内テストの取り込み |
| 講師 | 導入と進度 | コースごとの段階 0〜4（下）、進度と教材 |
| 管理者 | /admin | 席・講師・担当・登録コード・最近の動き・報告・設定。答案と記録は読めない |

**導入の段階（コースごと。上の段は下を含む）**：0 紙のまま（時間割にだけ出る）・1 宿題を出す（授業計画の宿題が生徒に出る。提出と評価は紙）・2 写真で提出・3 添削まで・4 毎日テストまで。押した瞬間に保存され、いつでも戻せ、出した宿題と評価は消えません。使わない講師には何も要求しません。

**提出箱**：種類は漢字テスト・計算テスト・英語テスト・作文・過去問（種類を選ばない提出箱も可）。クラス全員か「選んだ生徒だけ」。過去問は 1 本＝1 箱で、題は「年度 学校 教科」。ほかに追加の宿題（上乗せ）と生徒ごとの決まり（個別）。

**紙との併走**：経路（紙かアプリか）は教材の性質で決まり、誰にも追加入力をさせません。講師の評価が無いまま期限から 7 日過ぎた紙の宿題（写真は出ている）は、生徒には仮に「できた」として渡します（付け忘れ＝最低評価を防ぐ）。外の仕組み「紙の宿題」が、撮った紙を生徒ごとに分けて同じ口から取り込みます。

**初回登録の案内**：登録コードのあとに 45 秒の動画（電話・iPad・PC の 3 本。`scripts/video/intro.py` が本物の画面から作る）を全画面で見せ、学年・クラス・科目 → 確かめる（大事なこと 4 つと利用規約）→ ID → 合言葉 → 完了。

## 6. API の一覧

すべて `/api/` の下。返事は JSON。入る前の口以外は Bearer の印が要り、校舎は印から引く。本文は辞書だけを受け、入る前の口は 4KB、入ったあとは 12MB まで。主なものを役割ごとに挙げます（実装は `server/tube_server.py` の `api()`、管理の口は `server/admin.py`、登録は `server/join.py`）。

| 誰が | 口 | 何を |
| --- | --- | --- |
| だれでも | GET /health | 生きているか、校舎の数、デモの有無 |
| だれでも | POST /login/start → POST /login/finish | SCRAM で入る（合言葉は送らない） |
| だれでも | POST /join/check・POST /join・POST /join/finish | 登録コードの確かめ・仮の口座・合言葉の値を置いて在籍に |
| だれでも | POST /claim | 1 回だけのリンクで合言葉を引き換える |
| だれでも | POST /report | うまく動かないときの報告（管理ページに出る） |
| デモのときだけ | GET /demo・POST /demo/enter | 「ためしに見る」の一覧と登録コード、ID だけで入る |
| 入った人 | GET /me・POST /logout・GET /rev | 自分の口座と担当、出る、データの版 |
| 生徒 | GET・PUT /p/\<sid>・GET /p/\<sid>/head | アプリの記録（自分の sid だけ） |
| 生徒 | GET /assignments・GET /assignments/prep… | 自分宛ての宿題と提出箱、総復習テスト対策 |
| 生徒 | POST /submissions/<宿題>・GET /submissions/mine・PUT /submissions/<宿題>/score | 写真・PDF を出す、出したものと返った添削、過去問の点数 |
| 生徒 | GET /growth・GET /rank・GET・PUT /me/placement・DELETE /me/returned | 成績の伸びと記録の要約、組分けの申告、返った添削を消す |
| 生徒（保護者）・講師 | /messages・/notices | 保護者から講師への文と返事、お知らせ |
| 講師 | GET /today・GET /check・PUT /check/rate | 今日やること、宿題チェックの行、評価・ひとこと・心配の印 |
| 講師 | GET /submissions/<束>/\<sid>/<名前>・…/scan・…/return | 答案を見る、紙を取り込む、添削を返す |
| 講師 | /lessons・PUT /lessons/use・GET /lessons/grid・POST /quiz | 授業計画、導入の段階、時間割の格子、提出箱を作る |
| 講師 | POST /assignments・PUT・DELETE /assignments/\<id>・POST /assignments/draft・GET /hw/outbox | 宿題を出す・直す・消す（出した生徒がいると消せない）、下書き、保護者への週の連絡の書き出し |
| 講師 | /ratings・/notes/\<sid>・/personal・/presets・/scores・/materials・/curriculum・/class/…・/insight/… | 紙の評価、特筆事項、生徒ごとの決まり、プリセット、塾内テストの点、教材、カリキュラムのずれ、クラスの要約、理解度 |
| 講師 | POST /roster/bulk | 名簿の一括登録（氏名の列があると拒む。合言葉の値は端末が作る） |
| 管理者 | /admin/…（state・accounts・classes・teachers・assign・join/code・reports・settings など） | 席・講師・担当・登録コード・報告・設定。答案と記録を返す口は無い |

コマンド（サーバの中で、運用者だけ）：`python3 server/tube_server.py` の serve・add・passwd・move・roster-import（氏名列を拒む）・bundle-import・school-trial・go-live・prune-photos・purge・rebuild-summary・anonymise など。管理ページがあるので、日々の席・講師・担当に SSH は要りません。

## 7. 保持・消去・バックアップ

消す仕組みはサーバの中で 1 時間ごとに動きます（`housekeep_once`：登録しかけの口座・学年の繰り上げ・写真の消去・使われない口座の破棄）。下の「仕組みが無い」行が、第 11 節の保持期間の決め事に直結します。

| 何を | いつ消える／残る | 仕組み |
| --- | --- | --- |
| 出した答案の写真・PDF | 講師が見て（採点して）から 7 日で消える。見ていなくても出してから 180 日で消える。評価とひとことは残る | `submissions.prune`（1 時間ごと） |
| 返した添削（赤を入れた画像） | 生徒が自分で消すか、口座が消えるまで | `DELETE /api/me/returned`・retire |
| 使われない口座 | 92 日使われないと、口座・記録・写真・評価・点・メッセージ・宿題の受け取り手を全部消す（本番に切り替えた校舎だけ。試し運用とデモ校では消さない）。残るのは ID も sid も時刻も無い数字 1 行（retired.jsonl）。ID は空きに戻る | `retire.run`（1 時間ごと） |
| 在籍終了にした口座 | 6 か月で消す（戻せない） | コマンド `purge`（運用者が流す。自動ではない） |
| 登録しかけの仮の口座 | 1 時間 | `join.sweep` |
| 入ったままの印 | 生徒 14 日・講師 12 時間・管理者 8 時間（さわらなければ 30 分）。合言葉を作り直すと即時 | tokens.json |
| 登録コード | 作り直すまで。本番切替で必ず作り直す | school.json |
| クラス替えの控え | 60 日 | `backups/<番号>/` |
| 宿題の一覧 | 1 年より前は画面に出さない（消さない） | `HW_KEEP_DAYS` |
| 監査の記録 audit.log | 消す仕組みが無い（保持期間を決めて実装する：第 11 節） | — |
| 報告（/report）・コース・設定 | 消す仕組みが無い | — |
| 試し運用の生徒の口座と記録 | 本番切替で「前の校舎ごと退避（消さない）」。退避先をいつ消すかは未定（第 11 節） | `本番切替.sh`（go-live） |
| 学年の繰り上げ | 管理者が入れた年度のはじまりの日に 1 回。小6→中1 は本人にクラスを聞く、中3 は卒業（新しい宿題は届かず、使わなくなって 92 日で消える） | `retire.roll` |
| 端末の中 | 入ったままの印・好み・送る前の写真。出ると印は消える。残りは端末の持ち主が消す | localStorage |
| バックアップ（S3 ロンドン） | 毎日 3 時に `/srv/myacady/` を写す。30 日で自動削除。消した記録もバックアップには最長 30 日残る（通知に書く） | `backup-setup.sh`（systemd timer） |

本人・保護者からの消去の求めに即日応じる道は、いまは運用者のコマンドだけです（管理ページは「在籍終了」まで）。手順を決めて文書にするのが第 11 節の項目です。

## 8. 運用

| こと | どうするか | 誰が |
| --- | --- | --- |
| 反映 | `sh deploy/更新.sh`：手元の検査 → app/・server/・カリキュラム/（JSON と文書だけ。PDF と講師名の入った時間割は送らない）を rsync → サービスを入れ替え（止めない）→ 外から確かめる → デモを作り直す → 意味の検査 | 開発者の端末からだけ（SSH 鍵） |
| 試し運用 | `sh deploy/ためしのデモ.sh`：全講師の全コースに架空の記録。クラスごとに 5〜15 人を今ある席から選ぶ（clean で席に戻る）。入口の「ためしに見る」は `deploy/ためしに見る.json` | 開発者 |
| 本導入への切替 | `sh deploy/本番切替.sh`（1 回だけ）：試しの生徒の口座と記録を退避、試し運用の印を外す、登録コードを作り直す、デモを作り直す。そのあと管理ページで登録コードの紙を刷って配る | 開発者＋校舎 |
| 日々の席・講師・担当 | 管理ページ /admin（SSH は要らない） | 管理者（校舎） |
| 毎日の片づけ | サーバの中で 1 時間ごと（第 7 節）。`python3 server/tube_server.py housekeep --dry` で消す予定を見られる | 自動 |
| バックアップ | systemd の timer で毎日 3 時に S3 へ。復元は rsync で戻すだけ（データベースが無い）。**復元の練習はまだ**（第 11 節） | 自動＋開発者 |
| 見張り | 入口の締め出しは管理ページの「報告」に出る。反映のたびに外から /health を見る。**止まったことを知らせる仕組み（週報・通知）はまだ**。大量の接続は Cloudflare で止める前提 | 開発者 |
| 障害のとき | 止まっても紙にそのまま戻れる（宿題は時間割どおりに出す）。サーバは Lightsail の画面から再起動、`systemctl status myacady`・`journalctl -u myacady`。**校舎に渡す手順書（紙 1 枚）はまだ**（稟議書の約束） | 開発者＋校舎 |
| 鍵の在りか | SSH 鍵は開発者の端末だけ（サーバには公開鍵）。S3 は IAM ロール（鍵をファイルに置かない）。Cloudflare と AWS の口座は開発者名義。合言葉の表（配った席の初期の合言葉）は Google スプレッドシート（制限付き共有・氏名は書かない）と刷ったカード | 開発者 |
| 撤収 | rsync で記録を引き上げてから、Lightsail のインスタンス・静的 IP・スナップショット・S3 を削除（停止では課金が止まらない）。誰が「書き出す→消す→解約→保護者へ通知」をするかは未定（第 11 節） | 開発者 |

単一障害点は開発者 1 人です（SSH 鍵 1 本、AWS と Cloudflare の口座、反映の手順）。コードは依存パッケージが無く、引き継ぎ文書（SPEC・CLAUDE.md・OPERATIONS）があるので、引き継ぎそのものはできますが、鍵と口座の 2 人目がいません（第 13 節の契約とエスクロー）。

## 9. 検査

「動く」ではなく「意味が合っている」を機械で確かめてから本番に写します。直したら不変条件を 1 つ足す決まりです。

| 検査 | 何を確かめるか | いまの数 |
| --- | --- | --- |
| サーバの検査 `server/test_*.py` | 席・管理者・入る口・同時操作（test\_admin）、校舎の分離（test\_isolation。サーバを立てて）、クラス替え（test\_moves）、宿題・コース・担当・導入の段階・紙との併走・写真の提出と返却・ためし運用のデモ・シラバス・理解度 など | test\_admin 426・test\_submissions 54・test\_trial 24・test\_moves 64・test\_isolation 24 ほか |
| 自己攻撃 `server/attack.py` | 未ログインで読めるもの、他人の記録（IDOR）、校舎をまたぐ参照、ユーザ列挙、形のおかしい本文、大きい本文、証明の使い回し など | 56 項目 |
| 流れの検査 `scripts/check/flows/adm_flow1〜16.py` | 画面を実際に押す台本。初回登録（flow6：49）、宿題の往復（flow12）、ためし運用のデモ（flow13：50）、今日やることの札の密度（flow14）、ずれ（flow15：講師と生徒の全画面×6 つの幅で重なり・はみ出し・小さい押し場所を数える。84）、登録コードの枠と全画面の動画（flow16：36）。土台は `reset.sh` が毎回作り直す。Chrome・Edge・WebKit（Safari と同じエンジン。`wk.py`）で流せる | `sh scripts/check/flows/run.sh <作業の場所> chrome edge webkit`（1 ブラウザ 80 分ほど） |
| 意味の検査 `scripts/check/expect.py` | 生徒・講師・管理の口を読んで、数と中身が決めたとおりか。前回との差（ledger）を見て、減った数があれば理由を言えるまで写さない。本番には読むだけで当てる（`更新.sh` の 4/4） | 本番 272 件（2026-10-13） |
| ソースの検査 `app/tools/check-source.py` | 言い回し・単位・解答らんの寸法 など、書いてあることの一貫性。指摘があると `更新.sh` が送らない | 111 ファイル |
| 見本との差 | デザインの決定版（Claude Design の東）と同じ画面・同じ幅で撮って比べる（4 つの役×3 幅） | London の見本 270 |
| 紙の宿題 | 外の仕組みが使う口の形を変えたら `sh 紙の宿題/検査/全部.sh` | — |

本番に対しては読むだけです（GET と、デモの入口からの試しの生徒での入室だけ。本番への SSH と本物の講師での入室はしない）。反映は `deploy/更新.sh` が「手元の検査 → 送る → 入れ替え → 外から確かめる → デモを作り直す → 意味の検査」を一続きで行い、途中で止まると先へ進みません。
