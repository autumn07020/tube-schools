# 障害時の手順書（A4 1 枚）　tube-study.uk　版 2026-11-04（下書き）

**この紙の決まり**：上から順に。1 つ済んだら次へ。**授業は止めない**（宿題は時間割どおり、紙で出す。アプリが戻ったら写真で出し直せる）。生徒の氏名・連絡先はこの紙にもアプリにも書かない。

## 0. 担当者（校舎）がすること ―― 5 分
1. 生徒・保護者への一言：「アプリが一時的に使えません。宿題は紙で先生に出してください。直ったらお知らせします。」
2. 本人（開発者）に連絡する（6 の連絡先）。伝えること：**いつから・誰が・どの画面で・何が出たか**（画面の写真があれば一緒に）。
3. 待つあいだ：講師は評価を紙に控える（戻ったら宿題チェックに入れる）。

## 1. 本人が確かめる ―― 5 分（読むだけ）
1. `https://tube-study.uk/api/health` を開く。`{"ok": true, …}` が出れば**サーバは生きている**（→ 3 へ）。出なければ 2 へ。
2. Cloudflare の状態：https://www.cloudflarestatus.com（London・Tunnel に障害が無いか）。
3. AWS Lightsail の画面：インスタンスが Running か、CPU が張り付いていないか、ディスクが満杯でないか。
4. 管理ページ `/admin` →「報告」：生徒・講師からの「うまく動かないとき」、画面のエラー、入口の見張り（締め出し）。

## 2. 止まっているとき ―― 10 分
1. Lightsail の画面 → インスタンス → **Reboot**。2 分待って 1-1 をもう一度。戻れば 7 へ。
2. 戻らなければ Mac から：`ssh ubuntu@<静的IP>`（鍵 `~/.ssh/lightsail.pem`）
   - `sudo systemctl status myacady cloudflared --no-pager`（両方 active か）
   - `sudo journalctl -u myacady -n 50 --no-pager`（最後のエラーを読む）
   - `sudo systemctl restart myacady && sleep 3 && curl -s http://127.0.0.1:8765/api/health`（サーバの中から生きているか）
   - `sudo systemctl restart cloudflared`（外から届かないだけのとき）
   - `df -h /srv`・`free -m`（満杯・メモリ切れなら、Lightsail の枠を上げる＝再起動のみ）
3. それでも戻らなければ 5 へ。

## 3. 動いているのに おかしいとき ―― 見分け
| 症状 | まず疑う | 本人がすること |
|---|---|---|
| 入れない（合言葉が通らない） | 入口の締め出し（同じ ID に 8 回） | 15 分待つ。`/admin` →「報告」の入口の見張り。本人確認のうえ合言葉を作り直す（管理ページ） |
| 宿題が出ない | コースの段階（紙のまま＝0）・授業計画が未発行・クラスの違い | 講師の「導入と進度」で段階、`/admin` →「生徒に出ているもの」、生徒の設定のクラス |
| 写真が送れない | 1 回 12MB 超・HEIC・古い画面 | 枚数を減らす、画面を読み込み直す。`/admin` →「報告」のエラー |
| 画面が白い・崩れる | 反映の直後（古い部品）・古い iPhone（iOS 16.2 未満） | 再読み込み。`sh deploy/更新.sh` の直後なら数分待つ |
| 数字がおかしい（人数・次の授業） | データの壊れ | `python3 scripts/check/expect.py --base https://tube-study.uk --accounts deploy/demo-accounts.json --ledger /tmp/ledger.json`（× の行を読む）→ 4 へ |

## 4. 記録が壊れた・消えたとき ―― 戻す（本人だけ。30〜60 分）
控えは **S3 に毎日 03:00（UTC）、30 日ぶん**。戻すと、**その時刻より後の提出・評価・登録は失われる**（校舎に伝える）。
1. 先に今の状態を退避：`ssh ubuntu@<静的IP> 'sudo tar -czf /tmp/before-$(date +%Y%m%d-%H%M).tar.gz -C /srv myacady'`
2. 戻す控えを**まず手元で確かめる**：`sh deploy/復元の練習.sh s3://<バケット>/<日付>.tar.gz`（3 つの条件が通った控えだけを本番へ。`knowledge/40-運用/復元の練習.md`）
3. 本番へ：`復元の練習.md` の「本番へ本当に戻すとき」4〜7（stop → scp → tar → chown → start → health → expect.py）
4. 校舎に「何時の状態に戻したか」を伝える。失われた分は紙で受ける。

## 5. 直らないとき
- **紙で続ける**（何日でも。時間割と授業計画は講師の手元にある）。
- 反映を戻す：直前の `sh deploy/更新.sh` が原因なら、`git log` で前の版に戻して `sh deploy/更新.sh`。
- サーバごと作り直す：Lightsail のスナップショットから新しいインスタンス、または `deploy/aws.sh` で素の Ubuntu に入れ直し → S3 の控えを 4 の手順で戻す → Cloudflare のトンネルを付け直す（`deploy/aws.sh`・`tube-study.uk の手順.md`）。
- 個人データの漏えい・消失の疑いがあるとき：**72 時間以内に ICO へ**（法務の表 `50-法務/`）。氏名は無いが ID・提出の写真・評価は個人データ。
