# 2026-10-14 Git 化と置き場

**決めたこと（本人「git化に踏み切ります。今日、1-4まで終わらせましょう」）**
- 原本を iCloud の `tube-schools` から Mac の `~/Projects/tube-schools` に移し、Git 化。GitHub の私有リポジトリを origin にする（本人が作る）。iCloud 側は読むだけの控え。1 か月後に消す。
- ルートの文書は `docs/`（古いものは `docs/archive/`）、Claude outputs の文書は `outputs/`（文字のファイルだけ。画像・PDF・動画・pptx は iCloud に残す）。北極星は `knowledge/00-北極星.md`、改良の種は `knowledge/90-種.md`。
- 入れないもの（.gitignore）：合言葉の表・`demo-accounts.json`（2 か所）・本物の束 `deploy/accounts/`・講師の名字入りの時間割 3 本・カリキュラムの PDF・前身（tube_next・firebase・reference）・控え（`紙の宿題/控え/`）・`server/data/`・log・shots。手元には置く（スクリプトが使う）。
- 本番反映は案A（本人が Mac で更新.sh）で 11 月を始める。案B（GitHub の承認ボタン）は 1〜2 か月後に判断。
- 動画 4 本（35MB）は Git LFS が無いのでそのまま入れた。作り直すたびに履歴が 35MB 増える（種：LFS か Releases へ）。

**同じ日の後半に直したこと（引き継いだ Opus 5.5 が確かめて見つけた）**
- 講師の名字が 4 つのファイルに残っていた（`outputs/時間割の確認.html`・`outputs/見た目リデザイン案を読んだ記録.md`・`scripts/curriculum/時間割/README.md`・`scripts/curriculum/時間割/build.py`）。まだ GitHub に送る前だったので、4 つの commit を書き直して名字を消した（filter-branch。README と記録は ID に、build.py は 時間割の講師.csv から名字を引く形に、確認の HTML は Git から外した）。build.py の出力 4 つと画面の出力が前と 1 バイトも変わらないことを確かめた。
- 番人は書く道具しか見ていなかった → 読む道具（Read・Grep・Glob）で合言葉の表を開くのも止める。番人は `~/Projects` で開いたセッションでしか効かない（古い場所で始まったセッションでは効かないことを確かめた）。
- iCloud の deploy/*.sh を先頭で止めた（手癖で古い場所から流すと、古いコードで本番が巻き戻る）。
- GitHub Actions は 2 本に分けた：速い検査（必須）と画面の流れ（画面とサーバに触る PR だけ）。毎晩の実行はやめた（無料枠）。段の中で 1 本が落ちても残りを流すよう `set +e`。server/test_*.py は全部、終わりの番号で判定（test_syllabus は「すべて通った」と書かない）。
- 秘密の検査を `scripts/check/secrets.py` という名前で置いたため、scripts/check を読み込む道具（画面の流れ・本番を読む expect.py）で Python 標準の `secrets` が隠れ、`scram.py` の `secrets.token_urlsafe` が無いと落ちた（Git から取り出した写しで画面の流れを流して見つけた）。`scan_secrets.py` に改め、標準ライブラリと同じ名前の .py を置かない検査 `scripts/check/stdlib_shadow.py` を pre-commit と GitHub の検査に足した。新しい置き場から 更新.sh を流す前に直せた（流していれば反映の直後の expect.py が落ちていた）。
- pre-commit は日本語のファイル名を「\346…」の形で受け取っていて、秘密の検査・合言葉の表の名前の検査・knowledge の検査が日本語の名前のファイルに効いていなかった。`core.quotePath=false` と `-z` で直し、捨てる写しで 4 例を確かめた。
- カリキュラムの PDF 8 本は写すときに除いたため新しい置き場に無かった（文書は「置き場にある」と書いていた）。iCloud から新しい置き場へ写した（SHA-256 一致。Git には入らない）。
- 番人は「ssh」という字を含むだけで止め、`grep ssh` のような読むだけの命令まで止めていた → 命令の位置にあるときだけ止める。make.py も流すときだけ止める。34 例を `scripts/check/test_guard.py` に残し、GitHub の検査に入れた。
- iCloud を消す前に `Claude outputs/` の画像・PDF・動画・pptx を Drive へ移すこと（Git には文字のファイルしか写していない）を手順書と種に書いた。
- 何をどう変えたか・失敗と試し方の誤り・確かめていないことは `docs/作業記録/2026-10-14-Git化と引き継ぎ.md`。

**理由**：iCloud の上で git を使うと同期が壊れる。worktree・雲のセッション・routine・GitHub Actions は Git が前提。秘密と巨大なものは履歴に入れない。

**却下した案**：iCloud の中で git init（同期が壊れる）／Claude outputs をまるごと Git に（125MB、画像 700 枚）／本物の束を Git に（ハッシュでも入れない）。

**影響**：セッションの作業フォルダが変わる（Claude の記憶も新しいフォルダに紐づく → knowledge/ が原本）。`deploy/更新.sh` は新しい置き場から流す。`担当.sh`・`時間割.sh` は手元にだけある時間割の CSV を使う。
