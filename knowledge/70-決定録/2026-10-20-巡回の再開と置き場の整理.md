## 翌日の昼に加えたこと ―― 分野ごとのチャット
**本人の言葉**：「別々の独立したチャットを開設し、自律的に動いてもらいつつ、私自身も各分野でやって欲しいことを指示できる基盤を作ってもらうことが目的」「新しいセッションでやるべき？あなたにやってもらうべき？」→ 元のセッション（番人が効くようになっていた）で作った。

**決めたこと（Claude の設計。本人の目的に沿う）**
- 分野ごとに 1 本の routine（claude.ai/code）＝ 1 つのチャット。TUBE コード・デザイン・運用・法務・資料。決まった時刻と、GitHub の issue の出来事で起きる。
- 指示の入口は、そのチャットに書くか、issue を分野の雛形で立てる。チームはラベルで自分の issue を拾い、`<チーム>/issue-N` の枝で PR を出す。merge は本人。
- 定例：運用は毎朝、巡回の結果を読んで切り分ける。資料は月曜に週報（`docs/週報/`）。法務は月曜に期限を照らして「本人」ラベルの issue。コードとデザインは issue だけ。
- 指示文の原本はリポジトリ（`.claude/routines/`）。routine はその写しを持つが、main のファイルを先に読んで優先する。
- 止める合図は `チームを止める.txt`。
- GitHub の読み書きは REST だけ（クラウドのセッションでは GraphQL が 403）。issue の無い実行は knowledge を読まずに終える（安く）。

**本人の手が要ること（夜の時点）**
1. PR を作る（枝 `code/surname-check-and-status`）。「検査」と「画面の流れ」が緑になったら merge。
2. GitHub の Secrets に `TUBE_DEMO_ACCOUNTS_B64` を置く（`docs/体制の始め方.md` 4 章の 1 行）。
3. Actions → 巡回 → Run workflow を 1 回。緑と「すべて通った」を見る。
4. Claude の GitHub App を autumn07020 に入れる（iPhone・iPad からクラウドで編集するため）。
5. ChatGPT の Project に GitHub を読むだけでつなぐ。
6. Drive の送信が終わったのを見てから、iCloud の元を消す。
7. 稟議を出す。
