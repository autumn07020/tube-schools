## 1. 考え方（ここだけは必ず読む）

**今後の編集とバグに耐えるよう、論理は単純に保つ**（担当講師の指示）。
例外を足したくなったら、まずデータに書けないかを考える。

### 概念は3つ

| 概念 | 何か | 置き場所 |
|---|---|---|
| **在籍クラス** | 生徒が名簿のどこにいるか。1人1つ | `accounts[].classId`。表は `curriculum.json` の `classes[]` |
| **コース** | 1つの授業。講師・時間割・受ける生徒・宿題の予定を**1件にぜんぶ書く** | `lessons.json` の `plans["<コースID>:<教科>"]` |
| **受講科目** | 生徒が契約している教科 | `accounts[].subjects`（無ければ全教科） |

合同（中2理科）も、指名（土特・早慶必勝・難プロ・特講・オンライン・動画）も、講習も、
**ぜんぶ「コース」1種類で書く。** 種類ごとの特別な処理を作らない。

### 規則は5つ

1. **講師の担当は、`teachers` に自分が入っているコース。** 見られる生徒と宿題、直せる予定はここで決まる
2. **受ける生徒は、`students`（指名）があればそれ。無ければ `classes` の生徒のうち、受講科目にその教科がある生徒**
3. **宿題は授業日に出し、次の回の授業開始時刻を期限にする**
4. **出した時点で、受け取る生徒をその宿題に書き込む。** あとで名簿やコースを直しても、出した宿題は変わらない。0人なら出さない
5. **総復習は週で数える。** 5週に1週

### 古い形を読むのは3か所だけ

- `teacher_pairs`・`teacher_slots` は、旧 `assign` とコースの**足し算**で担当を返す（どちらかを優先する分岐を作らない）
- 生徒の教科から計画を引く `courses.key_for()` は、コースが無ければ旧来の `学年:教科` を返す
- `teachers` の無い計画（旧 `学年:教科`）は、旧来の自動発行 `auto_publish_legacy()` だけが扱う。
  **新しい処理を旧計画に対応させない。** デモを作り直すと旧計画は無くなる。無くなったらこの関数ごと消す

## 2. 形

### コース（`lessons.json`）

```jsonc
{"plans": {
  "e5b:math": {
    // ── コースの定義。教室長が CSV で入れる。講師の画面からは変わらない
    "name": "小5β 算数", "grade": "e5", "subject": "math",
    "teachers": ["<講師のsid>"],
    "slots": [{"day": 1, "start": "16:40", "end": "18:10"},
              {"day": 4, "start": "16:40", "end": "18:10"}],
    "classes": ["e5b"],               // 指名のコースは代わりに "students": ["<sid>", …]
    "unit": "week", "weekday": 1,     // 1回＝1週（月曜）。省略すると 1回＝授業1回
    "from": "", "to": "",             // 講習など期間のあるコース。空なら常設
    // ── 授業計画。講師が画面で直す
    "start": "2026-09-07", "skip": [],
    "lessons": [
      {"n": 1, "date": "2026-09-07", "topic": "…", "review": false,
       "hw": {"items": [
         {"text": "予習シリーズ 基本問題", "source": "yos-e5-math", "from": 12, "to": 13},
         {"text": "演習問題集 基本問題＋トレーニング", "source": "enshu-e5-math", "from": 20, "to": 23}]},
       "extraHw": {"top": {"items": [
         {"text": "基礎力強化プリント", "source": "kiso-print", "from": 1, "to": 4}]}}}
    ],
    "weekly": [{"id": "keisan", "text": "計算テキスト", "source": "keisan-yos",
                "step": 7, "at": 0, "wrap": 0}],
    "weeklyAt": "",                   // 最後に毎週の分を出した ISO週（2026-W37）
    "extra": [{"id": "top", "name": "上位", "students": ["<sid>", …]}]
  }
}}
```

- コースIDは ASCII（`^[a-z0-9_-]{1,16}$`）。**IDから学年・教科・種類を読み取らない。** `grade`・`subject` を見る
- 在籍クラスIDは生徒のログインIDに入るので、あとから変えない

### コースから出した宿題（`assignments.json` の1件）

```jsonc
{"id": "a1b2c3d4", "title": "予習シリーズ 基本問題", "source": "yos-e5-math",
 "from": 12, "to": 13,
 "classId": "e5b",                  // コースID（在籍クラスIDとは限らない）
 "students": ["<sid>", …],          // 出した時点の受け取り手。空にしない
 "subject": "math", "route": "paper", "graded": true,
 "dueAt": 1757952000000, "lesson": {"key": "e5b:math", "n": 1},
 "note": "第1回（…）の宿題です。", "kind": "hw", "createdBy": "plan"}
```

### 生徒（`accounts.json`）

足すのは `subjects` だけ。`["japanese","math","english"]` の形。無い生徒は全教科。

### コースの CSV（`courses-import` / `courses-export`）

```
id,教科,名前,学年,講師,時間,クラス,指名,単位,期間
e5b,算数,小5β 算数,e5,<講師ログインID>,月16:40-18:10 木16:40-18:10,e5b,,週:月,
j3doku,数学,中3 土特（RD特） 数学,j3,<講師ログインID>,土16:00-17:10,,j3r-01 j3r-02,授業,
kaki-j3,数学,夏期講習 中3 数学,j3,,月10:00-12:00,j3t j3r,,授業,2027-07-20〜2027-08-25
```

- 講師はログインID、指名は `在籍クラス-出席番号`（氏名を書かせない）。空欄区切り
- 出して直して入れ直すと、元に戻る（`test_courses.py` が見る）
- **入れても消さない。** CSV に無いコースは残る。やめるときは `期間` の終わりを入れる

## 3. 規則の中身

| 項目 | 決まり |
|---|---|
| 授業日 | `slots` の曜日。`unit:"week"` なら `weekday` の曜日に週1行 |
| 発行 | 授業日の0時を過ぎたら出す。10日を過ぎた回は出さない（どちらも今と同じ） |
| 期限 | 次の回の日付の、その曜日の `slots.start`。次の回が無ければ7日後。その曜日に枠が無ければ 23:59 |
| 総復習 | `start` の週を第1週として 5・10・15…週目の回 |
| ずらす | そのコースの授業日の並びで N コマ動かす（週2回なら火→木）。`unit:"week"` は N 週 |
| 複数ブロック | `hw.items[]` の1つが宿題1件。`items` の無い旧形式は `{text, source, from, to}` を1件とみなす |
| 上乗せ | `extra[].students` のうち、その回の受け取り手に入っている生徒にだけ `extraHw[id]` を出す |
| 毎週固定 | その週の最初の回を出すときに `weekly[]` を1件ずつ出す。範囲は `at+1`〜`at+step`、`wrap` を超えたら1に戻る。同じ ISO週に二度出さない |
| 受講科目 | CSV の `subjects` 列に「国数英理社」の形。列の無い CSV は全教科。列があって空欄の行は取り込まない |
| 期間 | `from`〜`to` の外では、時間割に出さず宿題も出さない |
| 時刻 | 校舎の `tz`（Europe/London）で計算する |
| 見られる生徒 | 担当コースの `classes` の在籍生徒と、担当コースの `students` |
| 担当の期間 | 期間の外のコース（終わった講習）も担当に残す ―― 講習の宿題を後から採点できるように |
| コースだけの講師 | `assign` を空の配列で持つ。持たないと旧形式の `classes` に落ち、そのクラスの全教科が見える |
| 台帳に無い教材 | 紙とみなす（`route_of`）。アプリ扱いにすると押した先に中身が無い |

## 4. 不変条件

INV-1〜9 は `CLAUDE.md` の再掲（パス・校舎・氏名を置かない・route と graded は教材から・紙を未提出に数えない・未評価を描かない・項目IDは内容由来・空で保存しない・仮サーバに実データを入れない）。

| ID | 条件 | 破ると |
|---|---|---|
| INV-10 | `classId` は1つのまま。accounts に足すのは省略できる `subjects` だけ | 認証・分離・集計が同時に意味を変える |
| INV-11 | 講師の担当は「コースの `teachers`」と「旧 `assign`」の足し算。ほかで担当を決めない | 担当の定義が割れる |
| INV-12 | 鍵の形は `<ID>:<教科>`。IDから学年や種類を推測しない | `j3doku` を `j3` の何かと取り違える |
| INV-13 | 1ブロック＝1宿題。まとめない | route・graded・評価がブロックごとに決まらない |
| INV-14 | 上乗せは足すだけ。クラスの宿題を消さない | 上位の生徒から通常の宿題が消える |
| INV-15 | 市販教材（四谷大塚・GRIT など）の中身を持たない。名前と範囲だけ | `IP.md` |
| INV-16 | 計画を保存できるのは、そのコースの `teachers` にいる講師だけ | 後から保存した講師が前の講師の計画を消す |
| INV-17 | 受講していない教科の宿題を出さない | 合同コースで取っていない生徒に出る |
| INV-18 | コースから出す宿題の `students` を空にしない | 空だと `students_for` がクラス全員を返す |
| INV-19 | 総復習は週で数える。回の数で数えない | 週2回のコースで2.5週ごとになる |
| INV-20 | ほかの講師の氏名をデータにもデモにも入れない | ― |

## 7. 検査

```bash
python3 server/test_isolation.py     # 校舎の分離
python3 server/test_blend.py         # 紙とアプリの併走
python3 server/test_assign.py        # 担当（旧 assign）
python3 server/test_examprep.py      # 総復習テスト対策
python3 server/test_courses.py       # コース（新規）
python3 server/test_hw.py            # 発行（新規）
python3 server/test_outbox.py        # 配達の禁止キー（新規）
python3 app/tools/check-content.py   # 教材
node    app/tools/check.js           # アプリ
python3 app/tools/こわれ方の検査.py   # 紙の割りつけと壊れ方
```

`test_courses.py` ―― 合同の担当者に各クラスの生徒が見える／指名の生徒だけ見える／他校舎の sid を指名に書いても入らない／担当外の講師は計画を保存できない／CSV を出して入れ直すと同じ／期間の外のコースは時間割に出ない

`test_hw.py` ―― 1回に2ブロックで宿題2件／`items` の無い旧形式で1件／ブロックごとに route・graded／受講科目の無い生徒が入らない／指名のコースは指名の生徒だけ／上乗せは extra の生徒だけ1件多い／毎週固定は同じ週に何度走っても1回分で wrap で1に戻る／期限（3R 火の回→木 18:20、小5β 月の回→次の月曜 16:40）／0人のコースは出さない／出したあとで受講科目を変えても受け取り手は変わらない

`test_outbox.py` ―― 返り値を再帰的に歩き、キー名で禁止キー（氏名・連絡先・点数・提出率・評価・グループの記号）を落とす

| 起きること | 原因 | 避け方 |
|---|---|---|

## 9. 取り下げた案（再提案しないこと）

| 案 | なぜ要らないか |
|---|---|
| `enrolments.json` で枠を別に持つ | コースに受ける生徒を書けば足りる。名簿を二重に持たない |
| 生徒を複数クラスに所属させる | 在籍は1つ。受けるものはコースと受講科目で決まる |

| `byLevel`（クラスごとに教材を差し替える） | コースごとに計画を持つので、T と R の違いは各コースに書く |

| `assign` の行を畳んで時間割を作る | 合同を1コースで書けるので畳む必要がない |
| 宿題の受け取り手を、読むたびに名簿から計算する | 名簿やコースを直すと、出した宿題まで変わる。出した時点で書き込む |
| 合同の種類（学年全体・TR・指名）ごとの処理 | すべて `classes` か `students` で書く |

## 10. 別件と、人に聞くこと

**別件（このプランでは作らない）**

- **GRIT をアプリで解く**：本部経由で発行元に許諾を問うか、早稲アカ自社の単語教材でアプリの単語練習を作る。GRIT の番号や語の並びを写さない（語の選び方・並べ方は編集著作物になりうる。塾は営利なので著作権法35条の対象外）。最終判断は本部
- **早稲アカ教材を毎日テスト・対策テストに使う**：入れる前に、教材をログインした生徒にだけ配る仕組みを作る（F11）
- **カメラの自動採点**：答えのデータが要る。四谷大塚の教材では持てない
- **中3の過去問・個別の宿題**：生徒を指名した宿題はいまも出せる。過去問の管理は別に設計する
- **小1〜小3**：枠だけ作る。実在の生徒アカウントは `DPIA.md` の対象年齢（9〜15歳）を直してから
- **講習**：`from`〜`to` つきのコースを CSV で足す。通常の授業を休む週は各コースの `skip` に入れる
