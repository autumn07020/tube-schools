| 問い | 答え |

- 宿題タブ：何が終わっていて何が終わっていないか分からない。「今日は何をすればいいのか」が一覧で分かり、終われば「今日は終わり」になること

- 講師の判断（提案を見送る・書き換える）を受け入れ、提案の出し方を改める

## 2. 考え方

### 「クラス」＝ 担当コース

成績・宿題の単位は**コース**（時間割のコマ：中2R 数学、中1 理科、中2TR 英語…）。
単元（授業の回）はコースにあり、在籍クラス（中2R）には教科ごとに別の単元が並ぶため、在籍クラスでは「単元の理解度」が定まらない。

### 単元 ＝ コースの授業の回

`<コースの鍵>#<n>`（例 `j2r:math#7`）。名前はその回の topic（一次関数）。

### 理解度（insight.py）

生徒 × 単元ごとに、**あるものだけ**を重ねる。無い根拠は0点ではなく「無い」。

| 根拠 | 元 | 値 | 重み |
|---|---|---|---|
| 宿題の評価 | ratings.json（その回の束） | 5→100 4→80 3→60 2→40 1→20 | 0.45 |
| 塾内テスト | scores.json（その回に割り当てた列） | 点÷満点 | 0.35 |
| 毎日テスト | 進捗のカード（単元名が topic と合う問題） | できた回数÷答えた回数（3回以上答えたとき） | 0.15 |
| 対策テストの丸つけ | weak.json（単元名が合うもの） | (出た−落とした)÷出た | 0.05 |

重みは**ある根拠の中で割り直す**。画面には必ず根拠（どれがいくつか）を添える。

- コースの単元の理解度 ＝ 根拠のある生徒の平均。**70%未満は黄**
- 生徒の理解度 ＝ 直近5単元（期限の来た回）のうち根拠のあるものの平均
- 月ごとの推移 ＝ 授業日の月ごとの平均（生徒の紙で出す）

**二重に持たない。** 理解度は保存しない。評価・テスト・進捗から毎回組み立てる（食い違いが起きない）。

### 提出（その回の束）

- 紙の束がある回：写真を出した、または評価が1以上 → 提出
- アプリだけの回：その生徒の宿題をぜんぶ終えた → 提出
- 期限が来ていない回は数えない

### 生徒ごとの宿題（personal.py）

「決まり」を生徒 × コースに持ち、**発行のとき**（publish_courses）に既定の宿題へ当てはめる。

| 種類 | 意味 | 例 |
|---|---|---|
| drop | その宿題を出さない | 計算テキスト なし |
| scale | 範囲を減らす | 計算テキスト 43-49 → 43-46（半分） |
| swap | 代わりに出す | 計算テキスト の代わりに 予習シリーズ 練習問題（その回の予習シリーズと同じページ） |
| add | 足す | 第7回 単位量あたり の基本問題を解き直す |

- 期間：`from`（第何回から）〜`until`（null ＝ 次に変えるまでずっと／同じ回 ＝ この回だけ）
- **出したあとの宿題は変えない。** 決まりはまだ出していない回にだけ効く（写真・評価と食い違わない）
- 生徒を抜いた既定の宿題は、受け取り手が0人なら落とす（students が空の宿題はクラス全員に化ける）
- 生徒だけの宿題は `students:[sid]`・`personal:[決まりのID]`・同じ `lesson`。**束に入る**ので写真は1回・評価は1つのまま
- 生徒の画面には特別な札を出さない（ふつうに自分の宿題として並ぶ）
- 束の代表（写真を出す先）は**生徒ごと**に決まる：その生徒の宿題のうち、上位でない紙の宿題で ID が最小のもの（homework.js の head と同じ）

### 提案（insight.suggest）

黄色（70%未満）の単元を押すと出る。

| 種類 | いつ | 中身 |
|---|---|---|
| redo | その単元が70%未満 | その回の最初の紙の宿題と同じページを「解き直し」として次の回に足す（この回だけ） |
| app | 単元名が合う問題がアプリにある | 毎日テストの問題からその単元を10問、次の回に足す（この回だけ） |
| lighten | 提出が続かない（直近5回で3回以上出ていない） | 毎週の分（計算テキストなど）を半分に（ずっと） |
| basic | 上位の宿題を受けていて単元が60%未満 | 上位の宿題の代わりに解き直し（この回だけ） |

**講師の判断を覚える。** 出した・見送ったを insight.json に残し、
よく出す種類を上に、見送った（生徒×単元×種類）は21日出さない。講師は中身を書き換えてから出せる。

### 塾内テスト（scores.py）

- 1列目は席番号（中2R-01、または同じコースで一意なら 01）
- 形は自動で見分ける
  - **大問（単元）ごと**：見出し「比例(20)」「比例/20」、または「満点」の行
  - **合計点だけ**：合計・得点・点数の列が1本（偏差値・順位は読まない）
  - **設問ごとの正誤**：○×（1/0）が並ぶ。「大問1-(2)」は「大問1」にまとめる
- 列 → 単元は、見出しと授業の topic が合えばその回、合わなければテストの日から5週間の回すべて
- **名前らしい列（氏名・名前・保護者・電話・メール・塾生番号）があれば取り込まない**
- 取り込んだ文字は残さない。残すのは sid と点数だけ
- 取り込みは「確かめる → 取り込む」の2手。確かめる画面で満点・単元の割り当てを直せる

### 成績タブ ＝ コースの診断

1. **すべて**：担当コースの札を並べる（テコ入れ候補が先）。札には最新単元の理解度（大）・直近5単元の理解度の棒（青／黄）・直近5単元の提出率
2. **コース**：
   - 直近5単元の提出率の棒・理解度の棒（押すと単元の中身）
   - 度数分布（0〜100%を10区切り、縦は人数）と線（40/50/60/70%、既定50%）
   - 線より下の生徒：理解度・苦手な単元（自動）・提案。まとめて「解き直しを足す」
   - 生徒 × 直近5単元の表（黄を押すと提案）
   - テストの取り込み
3. **単元**：生徒ごとの理解度と根拠（評価・テスト・毎日テスト）、提出。黄を押すと提案
4. **生徒**：単元ごとの推移・月ごとの推移、宿題の決まり（効いている／終わった、止める・直す）、次の回のこの生徒の宿題（決まりを当てたあと）、特筆事項

## 4. API（講師だけ・自分のコースだけ）

| | |
|---|---|
| GET `/api/today` | 今日のチェック（コース×回：写真・評価まだ・未提出）と、今日おわったもの |
| GET `/api/check?key=&n=` | その回の全員（束の代表・写真・評価・その子の宿題）、切り替え用のコースと回 |
| PUT `/api/check/rate` | `{key, n, sid, v}` 束の全件に同じ評価。v が null なら消す。写真は「見た」にする |
| GET `/api/insight/overview` | 担当コースの札 |
| GET `/api/insight/course?key=` | 単元・生徒・度数分布のもと |
| GET `/api/insight/student?key=&sid=` | 単元ごと・月ごと・決まり・次の回の宿題 |
| GET `/api/insight/suggest?key=&sid=&n=` | 提案 |
| POST `/api/insight/feedback` | `{key, sid, n, kind, action}` 出した／見送った |
| GET/POST/DELETE `/api/personal` | 決まりの一覧・保存・止める |
| POST `/api/scores/preview` | 表を読んで形・列・席の一致を返す（保存しない） |
| POST `/api/scores` | 取り込む |
| GET `/api/scores?key=` ／ DELETE `/api/scores/<ID>` | 一覧・消す |

## 6. 罠（先に書いておく）

| 起きること | 避け方 |
|---|---|
| 生徒だけの宿題で、束の代表が講師と生徒でずれる | 代表は生徒ごとに同じ規則で決める（サーバとhomework.js） |
| 既定の宿題から全員を抜くと、students が空になり全員に化ける | 0人になった既定は落とす |
| 決まりを出したあとの宿題に当てて、写真・評価と食い違う | 決まりは発行のときだけ当てる |
| 古い4段階の評価（0〜3）を5段階として読む | `s` の無い評価は読み替える（ratescale.value） |
| テストの表に名前が入っている | 見出しで弾き、取り込まない。文字は残さない |
| 理解度を保存して、評価を直しても変わらない | 保存しない。毎回組み立てる |
