## 2. Claude Design で何を選ぶか

### Design system
- **段0〜段4 は `None`。** 試作の段では、決まった指針に縛らない。出発点の値は `04` の 2.3 にあり、プロンプトにも書いてある。
- **段4 で、新しいデザインシステム「TUBE study 新デザイン」を作らせる。段5 からは、それを選ぶ。**
- **10/3 の `Tube study デザインシステム`（v0）は選ばない。** チャット版が実物を見ずに作ったもので、色・線・書体が実物とも、いまの好みとも違う。まちがえて選ばないように、消すか、名前の頭に「旧」を付けておくとよい。

### codebase
- この Mac のフォルダを選べるなら、**段5 から `デザイン引き継ぎ/codebase/` を選ぶ**（いまの HTML の組み方・部品の名前・文言を正確に引ける）。試作の段（段0〜段4）は、接続なしでよい。
- **`tube-schools` の本体は選ばない。** 大きい（教材データ）、渡してはいけない物がある（合言葉の表・サーバの台本）、Claude Design が本体を書き換える事故を防ぐ。
- GitHub のリポジトリしか選べないなら、**接続しない。** 値は `tokens-現状.json` と `01` に、形は PDF にある。

## 3. 進め方

`04` の 6章のとおり。要点だけ。

1. **実寸で、1要素ずつ。** 比べる2つは、違いを1つだけにする。Ken の答えは「A・A寄り・B寄り・B」。
2. **強い好み（`04` の 2.1）は、かけ直さない。** 確かめるのは、寄り（2.2）と、いまと食い違う所（4章）と、問い（7章）。
3. **iPhone とパソコンを、同じ段で。**
4. **各段の終わりに「この段で決まったこと」を、`04` と同じ形で書かせる。** それを `04` の付録の下に貼り足してから、次の段へ。セッションは前の回を覚えていないので、`04` が記憶になる。
5. **段4 より前に、全画面を作りはじめない。** 段5（代表の 10 画面）で指針が破れる所を直してから、全部へ。
6. どの見本にも、**画面の番号（S01 など）をアートボードの題の先頭に付けさせる。**

## 5. 確かめられていないこと

- Claude Design の画面は、最初の1枚（「What should we create?」）の写しでしか見ていない。「＋」で PDF と .md が添付できるか・大きさの上限（いちばん大きいのは第2巻の 17MB）・codebase にフォルダを選べるか、は使いながら確かめる。
- A/B の結果は、チャット版が実物を見ずに作った試作でのもの。見た目の好みは信頼できるが、実物の中身（項目の多さ・講師の画面）に当てたときに同じ答えになるかは、段1〜段3 で確かめる。
- ガラスを全部の札に使ったときの、Safari での重さと、字の読みやすさ。試作の段から `04` の 8章の作り方で。
- iOS 27 の見た目を、Claude Design がどこまで正確に知っているか（段0 で、不確かな所を挙げさせる）。
