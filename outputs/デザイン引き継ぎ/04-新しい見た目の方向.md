Claude Design が迷わないための指針。**これから作る見た目**について、Ken の好み（試作への判定と A/B テストの結果）をまとめ、いまの実物と食い違う所の裁きと、進め方を書く。

## 0. どの文書が、何を決めるか

| 文書 | 決めること |
|---|---|
| `01-デザイン哲学と現状.md`・`02-画面台帳.md`・PDF | **機能と中身。** 何の画面があり、何が書いてあり、何ができるか。いまの見た目の値（記録として） |
| **この文書（04）** | **これからの見た目の向き**と、進め方 |

- 食い違ったら、**機能と中身は 01、見た目は 04。**
- `01` の 4〜5章（いまの見た目の決まりと値）は「いま、こうなっている」という記録で、新しい見た目を縛らない。ただし 3章の「変えないもの」は、見た目が変わっても守る。
- 好みの強さ：**強**＝A か B をそのまま選んだ（そのまま使う）／**寄り**＝A寄り・B寄りを選んだ（まずその向きで作り、実寸で確かめ直す）。
- 出どころが食い違うときは、①試作への判定（Ken の言葉）＞ ②A/B 第2回（生徒ホームを実寸で、1要素ずつ）＞ ③A/B 第1回（小さな見本）。
- **A/B の試作は、チャット版の Claude が実物を見ずに作った。** 見た目の好みは信頼できる。画面の中身は実物と違う所がある（5章）。10/3 の「Tube study デザインシステム」（v0）も同じ事情で作られたもので、**無視してよい**。
- 付録 A に、Ken が貼った A/B テストの結果を原文のまま置く。

## 3. 変えないもの（見た目が変わっても守る）

1. **機能・画面の数・項目・文言の中身**（`01`・`02`・PDF）。足りない／余ると思ったら、作らずに案として言う。
2. **匿名。** 氏名・顔写真・アバター・キャラクターを入れない。生徒は ID（`s-042`）とクラス名。
3. **1画面に「次にやる1つ」を先に出す。** 大量のタスクを並べない。
4. **生徒の画面に％を出さない。責めない言い方。**（数字は保護者と講師だけ）
5. **見出しは日本語だけ。** 中身をそのまま言う短い名前。「赤ペン」「先生の目」「あたたかみ」のような言い回しは使わない。動作だけを言う。
6. **押せそうなものは必ず押せる。** 当たり判定 44px 以上。
7. **講師の作業を増やさない。** 数字を入力させず、押すだけ。宿題チェックは 1〜5 を連打する画面なので、押した反応の動きを付けない。
8. **ロゴと印。** 一語の `tubestudy`（tube は太い青、study は細い黄 `#F9B900`）と、印（青い角丸の四角に、白い輪と黄の横棒）。
9. **初回登録の順番**（`01` の 10章）。最初に触れる画面は美しく親切に。質問や入力の欄から始めない。
10. **実装の条件**（`01` の 9章と、この文書の 8章）。

## 5. A/B の試作が置いていた前提と、実物の違い

好みは採る。**中身は、実物に合わせる。**

- **生徒ホーム。** 採るのは並べ方（次にやる1つ → 2枚 → 教科 → 先生から最新1件 → 記録1枚 → 浮いたタブ）。実物のホーム（`S01`）には、試作に無かったものがある：先生からのお知らせ（「わかった／質問する」）、成績の伸び、今週の目標、毎日テストの正答率、学年の中の量、続けた日、時期で出る札（組分けの申告・新しい学年のクラス・卒業）。**消さない。** どこへ置くか（ホームに残す・1枚にまとめる・押して開く・別のタブへ）を、案として出す。
- **「教科ごと（残り問題数）」。** 実物では、教科ごとの宿題は「宿題」のタブ（`S02`）、教科ごとの毎日テストの問数は「毎日テスト」のタブ（`S03`）にある。ホームに置くなら、どちらの数かを決める。
- **「きろく（6週間のヒートマップ）」。** 実物は「これまでの宿題」（12週・1週1マス。ホーム）と「続けた記録」（4週×7日。毎日テストのタブ）。
- **生徒の識別「色＋コード」（第1回では強い好み）。** 実物は ID（`s-042`）とクラス名で、色は持っていない。色を添えるなら、ID から決まる色（どこにも保存しない）を案として。氏名もニックネームも無い。
- **講師「宿題を出す画面は1画面のフォーム」。** 実物では、宿題は授業計画から自動で出る。講師が手で触るのは「授業の紙」（`T03`。ずらす・止める・提出箱）と「宿題を足す紙」（`T13`）。フォームの好みは、この2つに当てる。
- **講師「提出状況はリスト＋絞り込み」。** 実物は宿題チェック（`T04` マス目と大きな答案／`T07` 対面の帯）と成績（`T08`・`T09`）。「一覧して、絞る」という向きとして当てる。表か状況ボードかは、まだ答えていない。
- **「路線図」。** 使わない。ログインのあとの幕の一言「All aboard!」（`E07`）は、いまの実物にある。残すかどうかは、動きを作るときに案として。

## 6. 進め方 ―― 一気に決めない。たくさん試して、段を踏んで絞る

Ken：「一気にデザインを決定するのではなく、たくさんの試作を多段階で作った上で、洗練させていきたい。」

**原則**
- **実寸で、1要素ずつ。** 比べる2つは、違いを1つだけにする。iPhone は 390×844、パソコンは幅 1440。
- **実物の文言と数で。** 写し（PDF）にある本物の文と数字を使う。架空の文を作らない。
- **iPhone とパソコンを、同じ段で。** パソコン版を後回しにしない。
- **Ken の答えは「A・A寄り・B寄り・B」。** 理由のひとことがあれば添える。答えは、この文書と同じ形（強／寄り）で記録し、次の段の入力にする。
- **強い好み（2.1）は、かけ直さない。** 寄り（2.2）と、食い違いの表（4章）の「確かめること」を、実寸で確かめる。
- **決めた値は、次の段でも変えてよい。** 最後に固めるのはデザインシステムを作る段。

| 段 | やること | 作るもの | 終わりの合図 |
|---|---|---|---|
| 0 読む | `01`・`04`・第0巻を読み、分かったことを言う | 10行のまとめ・試す計画 | Ken「合っている」 |
| 1 広く試す | 2章の向きの中で、**生徒ホーム（S01）を 6〜8 通り**。背景・透け方・文字の段・余白・札の並べ方を振る | 並べた試作 | Ken が 2〜3 に絞る |
| 2 1要素ずつ | 絞った案を土台に、4章と 7章の問いを **A/B で**（1回に 8〜12 問） | A/B の組 | 寄り → 強 になった数 |
| 3 ほかの役と機械へ | 同じ考えを **講師（T01・T04）とパソコン（S01・T01）**に当てる。3〜4 通りずつ | 並べた試作 | Ken が絞る |
| 4 仮の指針 | ここまでの答えから、色・文字の段・間隔・角・素材・動きの値を**仮に**置く | デザインシステム（仮） | Ken「これで広げてよい」 |

## 7. 次に確かめる問い（A/B の種）

1. ガラスの上の字：よく透ける（白 20%）で、にじみの濃い所でも読めるか。読めないなら、白を何%まで上げるか。
2. 影なしで、札の重なり（紙・タブバー・札）の前後が分かるか。光る縁だけで足りるか。
3. 背景のにじみ：何色・どの位置・どの濃さ。画面ごとに変えるか、どの画面でも同じか。
4. 黄（かアンバー）の役：期限が近い印だけに使う／使わない。
5. 次にやる札：ガラスのままで主役に見えるか。大きさ・位置・ボタンの形で差を付ける案を比べる。
6. 数字：ui-rounded の太さと大きさ。リングの中の数。
7. 文字の段：何段にするか（いまは 59 種類）。いちばん小さい字を何 px にするか（いまは 13px 以下が7割）。
8. 教科の印：チップ・アイコン・点・縦の帯のどれか。鮮やかな5色の最終の値。
9. アイコン：線の太さと角。タブの4つ（生徒）と3つ（講師）。
10. 浮いたタブバー：幅・丸み・選んだ印。パソコンでの置き場所。
11. 主ボタン：下の固定バーにするのは、どの画面か。
12. 期限の書き方：「10/5（日）21:00」だけ／「あした」を添える。
13. 小4の画面：漢字にふりがな／かなに開く。実寸で。
14. 記録：ヒートマップの週の数と、色の段。
15. 達成：静かな演出の形（輪が満ちる・数が増える・縁が一度だけ光る）。
16. ばねの動き：押した反応・紙の出入り・リング。強さと長さ。
17. 講師の一覧：表か、状況ボードか（まだ答えていない）。宿題チェック（T04）の密度。
18. パソコンの組み方：左のタブか上か。本体の幅。ガラスの札を広い画面でどう並べるか。
19. 入口と幕：新しい素材での、ようこそ・ログイン・幕。
20. iPhone 以外の書体と数字（Android・Windows）。
21. ダーク：作るか。作るなら、いつの段で。

## 8. 実装する側（Claude Code）からの条件

見本どおりに作れるよう、試作の段から守ってほしいこと。

- **ガラス。** ぼかし（backdrop-filter）は、Safari で数が増えると重くなりやすい（実機で測って決める）。**背景を画面に固定して、にじみをはじめからぼかした絵にしておけば、札は「半透明の白＋光る縁」だけで、ほぼ同じ見た目になる**（札の後ろにあるのは、ぼけた背景だけなので。彩度を上げる効きだけは出ない）。本当のぼかしが要るのは、動く中身の上に重なるもの（タブバー・上の帯・紙）だけ。試作も、この前提で作る（札の後ろに、くっきりした物を通さない）。
- **字の読みやすさ。** ガラスの上の字は、背景のいちばん濃い所と、いちばん薄い所の両方で、濃さの比 4.5:1（24px 以上は 3:1）を確かめる。
- **書体。** 外からフォントを読めない。`-apple-system` と `ui-rounded` は Apple の機械だけで効く。Android と Windows では別の書体になるので、そのときの見え方も1枚作る。どうしても同じ数字にしたいなら、数字だけの書体を1つ、自分の置き場に置く案を出す（Ken と Claude Code が決める）。
- **アイコン。** インラインの SVG だけ。1つの一式にそろえる（線の太さ・角）。**SF Symbols は使わない**（Apple の許諾は、Apple の機械で動くアプリむけ。Web のアプリは外れる）。自作するか、使ってよい一式（Lucide・Phosphor など）から。
- **ばねの動き。** CSS の transform と opacity だけで作る（JS で計算しない）。長さと曲線を数字で。動きを減らす設定では全部止める。
- **ふりがな。** 生徒むけの文言は、いま「かな」と「漢字」の2つの形で持っている。ふりがなにすると、全部の文言に読みを付け直すことになる。決める前に、手間を Claude Code に聞く。行の高さが増えることも、実寸で見る。
- **動く下限** は iOS／Safari 16.2。パソコンは Safari・Chrome・Edge。
- そのほかは `01` の 9章。
