## 0. 結論（先に3つ）

1. **名前はサーバに置かない。だから同期は「社内サーバの Excel を読める Mac」で動かす。** 道具（`scripts/roster/sync.py`）が Excel を読み、名前を落とし、ID・学年・受講科目・クラス・在籍だけをサーバへ送る。名前と ID の対応は、その Excel（か、事務の表）の列として社内に残す。サーバは名前を一度も見ない。
2. **本番の ID は「校舎コード＋生徒番号」に変える**（例 `w1042`。クラスを ID に入れない）。今の `we4a07` の形は「クラス替えのたびに ID がクラスと食い違う」「入退塾が多いとクラスごとの番号が伸びる」。生徒番号なら、入塾で1つ増え、退塾で消え、クラス替えでも変わらない。**今の 521 は、そのままデモに使う**（本番と形が違うので、ぶつからない）。
3. **講師の取捨選択は、すでにある「導入の段階」（コースごとに 紙のまま／宿題を出す／写真で提出／添削まで／毎日テストまで）で足りる。** 新しい仕組みは作らない。同期が「このクラスのこの教科」のコースを作り、講師が段階を選ぶ。既定は「紙のまま」。

初回サインオンの自己申告（学年・科目・クラスをボタンで）は **作る。ただし「まだ分からないところだけ聞く」補助**にする（7章）。名簿の元は1つ（社内の Excel）。2つにすると、食い違いがバグになる。

## 3. 同期の道具（`scripts/roster/sync.py`）

### 3.1 入れるもの（Excel から）

要る列は5つ。列の名前は Excel に合わせて設定で決める（`scripts/roster/設定.json`）。

| 列 | 例 | 無いとき |
|---|---|---|
| 生徒番号（変わらない番号） | `1042` | 道具が連番を振り、対応表.nosync に持つ |
| 氏名 | ― | 対応表.nosync にだけ書く。サーバへ送らない |
| 学年 | 小4 | 必須 |
| 受講科目 | 国算理社 | 必須（国数英理社の字） |
| クラス | α ／ 国=α・算=β | 教科ごとなら「国=α,算=β」の形。無ければ1つ |
| 在籍 | 在籍／退塾／休会 | 列が無ければ「行がある＝在籍」 |
| オンライン | ○ | 無ければ対面（カード）。○ならリンク |

**先に、Excel の見出しの行（名前の列を消したもの）を1つ見せてください。** それに合わせて設定を書く。

### 3.2 やること（毎回同じ結果になる）

1. Excel を読み、対応表.nosync（前回まで）と突き合わせる。
2. **新しい生徒**：ID を決める（`w`＋生徒番号）→ 合言葉を作る（3語＋4桁）→ 確かめる値（scram）を作る → 対応表に1行 → カードの PDF に1枚（オンラインなら「1回だけのリンク」を作って、送る文を1行）。
3. **変わった生徒**（学年・科目・クラス）：差分に入れる。
4. **消えた生徒**：在籍終了（記録は残る）。もう一度現れたら在籍に戻す（同じ ID。カードもそのまま）。
5. 差分を `/api/admin/roster` へ送る（管理者として入る。合言葉はこの Mac のキーチェーンに）。
6. 結果を1画面に出す：入った n・変わった n・出た n・カードを刷る n。

`--dry`（何も書かない・送らない）を必ず持つ。毎日は `launchd` で朝に1回、か、事務が「同期」をダブルクリック。**Excel の列が変わった・知らない学年やクラスが出た、なら何も送らずに止まる。**

### 3.3 サーバ側（`PUT /api/admin/roster`）

いまの管理の口（席を足す・状態を変える・クラス替え）を1つにまとめた口。
`{rows:[{id, role:"student", grade, subjects:[...], classId, placements:{japanese:"e4b"}, state:"live|left", verifier?}], dryRun}`
- 1つでも形がおかしければ**何も変えない**（クラスが無い・学年が違う・ID の形が違う）。
- 新しい ID は口座を作る（`verifier` 必須）。ある ID は verifier を**受け取らない**（合言葉は同期で変えない。なくしたときは管理ページで）。
- クラスが変わる生徒は、クラス替えと同じ道（`move_plan`／`move_apply`。取り消せる）。
- 在籍終了・在籍に戻すは `set_state` と同じ（記録は残す・宿題の受け取り手を直す）。
- 無いコースの枠（クラス×教科）は紙のままで作る。
- 返すのは `{added, changed, left, returned, courses, errors}`。

検査：test_admin に「同じ差分を2度送っても変わらない」「途中で失敗したら何も変わらない」「同期のあとで、講師の名簿・宿題の受け取り手・成績の一覧が合う」を足す。

## 4. ID と合言葉が枯れない理由

- **入塾＝ID が1つ増える**。番号は生徒番号（か連番）なので上限は実質ない。クラスごとの席を作り置きしないので、余りも足りなくなることもない。
- 退塾した ID は再利用しない（記録が混ざる）。戻ってきたら同じ ID。
- 合言葉は ID ごとに1つ。なくしたら管理ページで作り直す（前のは その場で無効）。
- 1日に何人入っても、道具が作る。事務がすることは Excel を直すことだけ。

## 5. 教科ごとのクラス（`placements`）―― **作らない（09-30 決定：そういう生徒はいない）**

（記録として残す）いまは生徒にクラスが1つ。「国語は α、算数は β」を持てるようにする。

- 口座に `placements: {"japanese": "e4a", "math": "e4b"}`。**無い教科は `classId`**（今までどおり）。
- 変える所は「その生徒がこのコースを受けるか」を決める1か所（`courses.receivers` と、クラス替え・あとから入った子の同じ判定）。名簿（`roster_of`）は在籍クラスのまま、宿題の受け取り手だけ教科ごとに分かれる。
- 管理ページの席の行に「教科ごとのクラス」を出す（既定は空＝在籍クラス）。同期の道具が入れる。
- 塾内テストの席番号は在籍クラスの番号のまま。

やる前に1つ確かめたい：**実際に「国語だけ別のクラス」の生徒はいますか。** いなければ、この章は作らない（概念を1つ減らす）。

## 7. 初回サインオンの自己申告（学年・科目・クラスをボタンで）

**作る。ただし役目は「同期がまだ入れていないところを、本人に聞く」。**

| 場面 | 聞く | 聞かない |
|---|---|---|
| 本番（同期あり） | 何も聞かない。Excel が元 | ― |
| 同期が止まっている・Excel に科目が無い | 無い項目だけ | 分かっている項目 |
| デモ（521 の席） | 学年・科目・クラス（3画面） | ― |

- 答えは口座に入るが、**「本人の申告（まだ確かめていない）」の印**が付く。講師の名簿と管理ページの席の行に印が出て、講師が1回押せば確かめた印になる。同期が来たら上書き（印も消える）。

- 小4は α・β を知っているので押せる。知らない子のために「わからない」を置く（講師に聞く、で止まる）。

これで**デモの席は、カードを渡すだけで動く**（管理者が科目やクラスを入れなくてよい）。本番は Excel が元なので、この画面は出ない。

## 9. 決めてもらうこと

1. **ID の形**：`w`＋生徒番号（推し）か、今の `we4a07` のままか。生徒番号は Excel にありますか（あれば、それをそのまま使う）。

3. **教科ごとのクラス**：本当にある（国語 α・算数 β の子がいる）か。無ければ5章は作らない。
4. **自己申告**：7章の形でよいか（デモでは3画面、本番では出さない）。
5. **10/15 の 521 の扱い**：退避して残す（推し）か、消すか。デモに触った講師の記録は、切替のあと見えなくてよいか。
