## 0. 先に結論

1. **勧めは案B「取り込みと採点を足す」。作る順は A → B → C。** A は B の前半なので、A で止めても無駄にならない。
2. **スキャンそのものは作らない。** 校舎の複合機（プリント）と、iPad の「書類をスキャン」（ノート・冊子）が出す PDF をそのまま入れる。作るのは、その後ろ ―― 生徒ごとに分ける・名前を消す・採点する・返す ―― だけ。
3. **生徒ごとに分けるのは、ノートの表紙に1回貼る番号シール。** 中身は生徒ごとに変わらない sid だけ。表紙は撮るが送らない（名前が書いてあるので）。
4. **分けたあとは、対面とオンラインを区別しない。** 同じ列に並び、同じ画面で採点し、同じ「先生から」に返る。対面の子のノートは、その授業のうちに手元へ戻る。
5. **tubestudy は記録と配達にだけ使う。** 今ある口（取り込む・評価する・返す）を外から呼ぶ。tubestudy から見れば「先生が画面で取り込み、評価し、返した」のと区別が付かない。
6. **10/03 には間に合わせない。** 最初の1周期は今の tubestudy で本導入し、その間に A を作り、2周期目に1コースで試す。

決めてほしいことは §11。いちばん大きいのは1つ ―― **tubestudy の口を、外の画面から（中継して）使ってよいか。** だめなら残るのは案D だけになる。

## 1. 何を解くか

依頼の6つの工程を、いまの姿で並べる。

| 工程 | いま（紙・対面） | いま（オンライン・tubestudy 以前） | いまの tubestudy（段階3） | 痛いところ |
|---|---|---|---|---|
| スキャン | しない | 写真を受け取る | 生徒が写真で出す。対面の子の紙は講師が1人ずつ「紙を取り込む」 | 対面の子の紙を入れる道が1人ずつ |
| 生徒ごとに整列 | ノート単位なので要らない | ファイルと生徒を手で結ぶ | 行を選んでから写真を選ぶ | 15人なら15回 |
| 処理 | ― | 傾き・影のまま印刷 | 長辺1600pxに縮めるだけ | 写真の出来が生徒ごとにばらばら |
| 書き込み | 赤ペン | 印刷して赤 | iPad で赤（写真の上に書く） | ― |
| 採点 | ノートを開いてページを探し、✕を数える | 同左 | 1〜5 を押す | ◯✕を数える道具が無い |
| 返却 | 次の授業で名前を呼んで手渡し | スキャンしてメール | 「返す」を押す（1人ずつ） | 持ち帰ったノートは、次の授業まで生徒の手元に無い |

批評（`批評-ワセアカOnlineに対して何が負けで、何が本質か.md` §8・§9）の二つの指摘を、解く相手として正面に置く。
- **対面は「その場で直して、その場で返す」が最も速い。** ここと競わない。競うのは、持ち帰って見る宿題・記述・小テスト・オンラインの子の往復。その場で直した紙も、望めば写して返せる形にだけしておく（§4）。
- **混在クラスで、集め方・返し方・記録が2通りになる。** 入口だけを2つ（対面は講師が束で、オンラインは生徒が写真で）にし、その先を1本にする。

## 2. 動かせない前提（ここから形が決まる）

## 3. どの案にも共通の部品

### 3.1 番号シール
- 生徒ごとに、小さな四角い印を刷ったシール。**中身は sid だけ**（組み分けで変わるクラスと番号は入れない）。
- 貼る所：ノート・冊子の表紙の右上。**新しいノートにするときに1枚貼るだけ。** 台紙（A4に24枚ほど）を生徒に1枚ずつ渡す。台紙の上の余白にだけ、いまの「小4β-07」を刷る。
- プリント（ばらの紙）を複合機に通すときは**区切り紙**：生徒ごとのA4 1枚に大きな印。クリアファイルに入れておき、出すときに自分の紙の一番上に重ねる。iPad で撮るなら、プリントはノートに挟んで出せば表紙のあとに続けて撮れ、区切り紙は要らない。
- 読み方：tubestudy の `app/js/omr.js` と同じ作り（四隅の黒い正方形で傾きを消し、マスの黒さを測る）を写して使う（tubestudy 側は変えない）。読めなければ「だれ？」に置く。**当てずっぽうで振り分けない**（omr.js と同じ決まり）。
- QR にしない理由：自分で刷り、平らなまま読むので、QR の誤り訂正の強さは要らない。部品を増やさない。困ったら QR に替えるのは難しくない。

### 3.2 撮る ―― 作らない
入口は PDF 1つにそろえる。

| 紙 | 撮る道具 | 出てくるもの |
|---|---|---|
| ノート・冊子 | iPad（か iPhone）の「書類をスキャン」（ファイル・メモに入っている）。台に立て、黒い下敷きの上で、表紙→宿題のページ→次の子の表紙…と続けてめくる。自動で撮り、四隅を切り、まっすぐにする | 1本の PDF |
| プリント・小テスト | 校舎の複合機。区切り紙ごと束で入れる。両面・カラーかグレー・200〜300dpi | 1本の PDF |
| オンラインの子 | いまのまま tubestudy に写真で出す（同じ「書類をスキャン」で撮って PDF で出してもよい。そのほうがきれいに写る） | tubestudy の中 |

- 撮る道具をこちらで作らない理由：カメラの映像から紙の四隅を探してまっすぐにするのは、最も難しく最も壊れやすい所。**iPad と複合機にはもう入っていて、速い。**
- **元の PDF の置き場に気をつける。** 「書類をスキャン」は iCloud に保存できてしまい、複合機のメール送信は講師のメールに残る。どちらも子どもの答案（表紙の名前ごと）が講師の個人の置き場に残る。保存先は「この iPad 内」か校舎の NAS・USB にし、送り終えたら消す。取り込みの画面は、送り終えたときに「元の PDF を消してください」と1行出す。

### 3.3 取り込みの画面（仕分けと確認）
PDF を入れると、端末の中で次をやる（送るまで、どこにも出さない）。
1. PDF の中の画像を取り出す（スキャンの PDF は多くが「1ページ＝JPEG 1枚」なので、描画せずに取り出せる見込み。最初の試作で、校舎の複合機と iPad の PDF を1本ずつ見て確かめる）
2. 印を探す。表紙・区切り紙なら「ここから07の子」。**表紙と区切り紙は送らない。**
3. 白紙（両面の裏）と、同じページの二度撮りを外す
4. 地を白くし、影を取る（omr.js の「まわりと比べて暗いか」と同じ考え）。長辺1600px・JPEG に縮める（tubestudy の写真と同じ大きさ）
5. 名前の欄を白で消す（3.4）
6. **確認の1画面**：行＝その回の生徒（番号順に固定）、行ごとにページの小さな絵と枚数。印の無いページは一番上の「だれ？」の行（黄）。絵を指で別の行へ動かせる。出していない子は薄く「なし」（赤にしない）
7. 「12人ぶんを送る」を1回押す → 1人ずつ tubestudy の取り込みの口へ。送った行は青

- どの回に入れるか：講師の時間割から「いまの授業（か直前の授業）」を先に出し、講師が押して決める（推測より明示。押すのは1回）。
- 1人6枚を超えたら見開きを1枚にまとめる。それでも超えたら、そう言う。
- 送る前に閉じても端末の中に残る。送ったものだけが消える。
- 印が他のコースの生徒のもの（別の教科のノートなど）なら「この回の生徒ではありません」と出し、送らない。

### 3.4 名前を消す
- **表紙と区切り紙は送らない**（ノートの名前はほとんど表紙にある）。
- ページに名前の欄がある紙（プリント・漢字とことば など）は、**その紙の形ごとに1回だけ**、講師が名前の欄を指でなぞって登録する。以後、同じ教材の紙は同じ場所を白で消してから送る。形は教材（materials の id）で覚える。
- 案C の答案用紙は、こちらで刷るので名前の場所が分かっている。名前を刷ってもよく、送るときに必ず消す。
- あわせて生徒には「名前は表紙にだけ」と頼む。仕組みと運用の二重にする。
- これで、いまオンラインの写真で運用に頼っている「名前が写る」危険を、対面の紙では仕組みで消せる。

### 3.5 名前は端末の中だけ
- 講師は番号ではなく名前で生徒を覚えている。`roster-tool/対応表.html` と同じ考えで、**名簿（番号→名前）を講師の端末にだけ読み込み、画面にだけ出す。** 中継にも tubestudy にも送らない（中継は名前を受け取る口を持たない）。
- 読み込まなければ「小4β-07」のまま動く。

### 3.6 中継
- 新しい画面は tubestudy と別の住所に置くので、口を取り次ぐ小さな中継が要る（§2）。
- **決まった口だけを通し、何も保存しない。** ログに合言葉と中身を残さない。通すのは、ログイン・自分の情報・時間割・宿題チェックの一覧・取り込み・評価・返す・答案の画像を読む、の8つほど。
- 置き場は2つの案：①小さな別のサーバ（月 $5 前後・目安）②Cloudflare の Workers（無料枠・要確認）。tubestudy はすでに Cloudflare を通っているので、②なら中身を見る相手が増えない。
- 気をつけること：tubestudy のログインの試行制限は、相手の住所ごとに数える（15分に30回の失敗で止まる）。中継を通すと講師全員が1つの住所に見える。6人なら困らないが、知っておく。
- DPIA の処理者の表に「中継（保存しない）」を1行足すことになる（本人の判断）。

## 4. 案A「取り込みだけ足す」

**ひとこと：** 対面の紙を束で入れて、tubestudy の宿題チェックに生徒ごとに並べる。採点と返却は、今の tubestudy のまま。

```
対面        紙を回収 → 表紙から続けて撮る → 取り込みの画面 → 送る ──┐
オンライン  tubestudy に写真で出す ──────────────────────────────┤
                                      tubestudy の宿題チェック（1〜5・ひとこと・iPad で赤・返す）
```

- 工程：スキャン＝iPad・複合機／整列＝番号シール・区切り紙／処理＝取り込みの画面／書き込み・採点・返却＝tubestudy。
- もう1つの使い方 ―― **赤は紙で、写して返す**：その場で赤を入れた紙を授業の終わりに撮り、「返す」の口に送る。講師のやり方は1つも変わらず、対面の子にもオンラインの子と同じ「先生から」と記録が残る。
- 段階：取り込みと評価は段階1から、返すのは段階3から（tubestudy の決まり）。
- 要るもの：iPad（か iPhone）と台、黒い下敷き（紙の四隅が見つけやすい）、番号シールの台紙。中継。
- 作る量：小（取り込みの画面・シールの印刷・中継。目安 2,000行弱）。
- 強み：新しい概念がほぼ無い。講師が覚えるのは「取り込む」画面1つ。宿題チェックで対面とオンラインが同じ行に並ぶ。
- 弱み：採点は今の宿題チェックの速さのまま（◯✕を数える道具が無い）。1人6枚まで。段階3にすると対面の子の画面にも「写真で出す」が出る（「対面の人は先生が集めます」と添える。提出箱と同じ言い方）。

## 5. 案B「取り込みと採点を足す」（勧め）

**ひとこと：** 案A に採点の画面を足す。対面もオンラインも1本の列にし、ページを順に出して、赤と◯✕と数字だけで、押して進めば返る。

```
対面        紙を回収 → 撮る → 取り込みの画面 → 送る ─┐
オンライン  tubestudy に写真で出す ──────────────────┤
                                          ↓（中継で読む）
               採点の画面：あと14人 → ページ → 赤・◯✕ → 1〜5 → 次へ（返る）
                                          ↓（中継で書く）
               tubestudy：評価・ひとこと・赤の入った答案 → 生徒と保護者の「先生から」
```

### 採点の画面（iPad を横にして）
- 入口は「次にやる1つ」：**「小4β 国語 第12回　採点　あと14人」**。押すと1人目のページが大きく出る。
- 左に答案。地を白くする処理は、対面の紙もオンラインの写真も同じにそろえる（まっすぐにするのは、紙の四隅が見つかったときだけ）。
- 右に上から：名前（端末の中の対応表があれば）と番号、ページの点（1/3）、**◎ ◯ △ ✕ の印**（校舎で手で付けている印と同じ）、数（◯8 ✕2）、**1〜5**、ひとことの札（自分がよく使う3〜6個＋書く）。
- ペンは赤で書く。指は拡大と移動だけ（ペンで書いている間は指を無視。tubestudy と同じ）。
- 印は、選んでから答案を軽く叩くとその場所に押される。◯と✕は自動で数える。**1〜5 は講師が押す**（数は根拠として横に出すだけ）。
- 1〜5 を押して「次へ」（か左へ払う）→ その子の赤と印を答案に焼き込み、評価・ひとことと一緒に tubestudy へ返す。次の子はもう読み込んである。
- 戻れる：右へ払えば前の子。直して進めば返し直す（tubestudy は前の返却を差し替える）。
- パソコンだけの講師：数字キー・印はクリック・ひとことは打つ。赤の書き込みはしない。
- 対面の子に紙でも返したい講師は「返した答案を番号順に印刷」を1回。

### 紙と比べて何が消えるか（時間ではなく手順で）
- ノートを開いてページを探す → 消える（そのページから出る）
- 1人終わるたびに山を積み替える → 消える（次へ）
- ✕を数える → 消える（数えてある）
- 記録を付ける → 消える（押した数字が記録）
- 名前を呼んで返す・オンラインの子にスキャンしてメール → 消える（次へで返る）
- 持ち帰ったノートが次の授業まで生徒の手元に無い → 消える（撮ったらその場で返す）
- 残るのは、**赤を入れること**と**数字を押すこと**だけ。

- 段階：3以上のコース。
- 要るもの：案A と同じ。赤を書くなら講師の iPad とペン。
- 作る量：中（案A＋採点の画面。目安で＋3,000行）。
- 強み：「紙で見るより簡単」と言える形になるのはここから。対面とオンラインの区別が、仕組みの中から消える。tubestudy は1行も変わらない。
- 弱み：講師の画面が tubestudy と2つになる（覚えることが1つ増える）。◯✕の数は tubestudy に残らない（残るのは 1〜5・ひとこと・赤の入った答案。残したければひとことに「8/10」と添える）。tubestudy の口の形が変わると動かなくなる（§10 の口の検査で見張る）。
- 出口：1周期以上回って数字が取れたら、この画面を tubestudy の宿題チェックへ入れるかどうかは本人が決める。外で試してから入れるので、tubestudy を危うくしない。

## 6. 案C「答案用紙から作る」

**ひとこと：** 書く紙をこちらで刷る。生徒ごとの印と四隅の目印が入った答案用紙を配り、束で複合機に通すと、生徒も順番も向きもそろい、**問題ごとに全員の答えを1画面で◯✕できる。**

- 向くもの：授業内の小テスト（漢字・計算・英単語）、提出箱、確認テストの答え、記述（原稿用紙）。**ノートと冊子への書き込みには向かない。**
- 刷るもの：A4に四隅の目印・印（sid と用紙の種類・ページ）・答えの枠（10問・20問・記述の升目などから選ぶ）。問題文は刷らない（教材を写さない）。
- 流れ：1クラス分を1回で刷る → 解く → 回収（順不同）→ 複合機 → PDF を入れる → 自動で生徒ごと・ページごと → **問題ごとの採点**：第1問の枠を全員分並べ、違う答えにだけ ✕ を叩き、「残りは◯」を1回押す → 第2問… → 1〜5 → 返す。
- tubestudy へ：提出箱を作る口（`POST /api/quiz`）が今あるので、刷るときに提出箱も一緒に作れる。返すのは案B と同じ道。
- オンラインの子：用紙の PDF を家で刷れる子は同じ流れ。刷れない子は白い紙に番号順に書いて写真で出す → 案B のページの採点で見る（問題ごとの並びには入らない）。
- 作る量：中（案B の上に＋1,500行ほど）。案B が先に要る。
- 強み：採点がいちばん速い形（同じ問題の答えだけが並び、見る場所が動かない）。全ページに印があるので、仕分けの誤りがほぼ起きない。
- 弱み：書く紙を変えることになる。向く宿題が限られる。刷る手間（1クラス1回）が増える。

## 7. 案D「端末の中だけで回す」

**ひとこと：** サーバも tubestudy も使わない。講師の iPad の中で、取り込み・仕分け・赤・◯✕まで済ませ、返すのは印刷か、ファイルを渡すだけ。

- 向く人：tubestudy を使わない講師・段階0のコース・tubestudy の口を外から使うことが許されないとき。
- 流れ：PDF を入れる → 仕分け → 採点（案B と同じ画面）→ 対面：番号順に印刷して手渡し／オンライン：生徒ごとの PDF を書き出し、今の連絡の道で送る。
- 強み：個人情報がどこにも出ない（名前ごと端末の中で扱える）。中継も口の許しも要らない。tubestudy に一切触れない。
- 弱み：オンラインの子への返却が1人ずつの手作業に戻る。記録が講師の端末にしか残らない（端末を失うと消える）。対面とオンラインで返し方が2通りに戻る ―― 依頼の「同等に」には届かない。
- 作る量：中（案B の画面を流用＋書き出し）。

## 9. 採らなかった形と理由

| 形 | 採らない理由 |
|---|---|
| 新しい画面を tubestudy と同じ住所に置く（Cloudflare で一部の道だけ振り分ける） | 中継は要らなくなるが、tubestudy と端末の中の保存（合言葉を含む）を同じ箱で共有する。「一切変えない」の線に触れる |
| 新しい仕組みに生徒の入口も作る（独立したサーバ） | 生徒と保護者の窓口が2つになる。批評で「会社が最も嫌う」とされた形。記録も二重になる |
| 対面の子にも家で写真を撮らせる | 対面の子の手間が増える（批評 §9 がそのまま当たる） |
| AI で紙の名前を読んで仕分ける | 子どもの名前と手書きを外の会社へ出す。名前をサーバに置かない線と正面からぶつかる |
| AI で自動採点する | 答え（市販教材の解答）を持つことになる。講師の判断を代わりに下すことになる。誤った採点は、採点しないより悪い |
| 専用のスキャナを必須にする | ノートと冊子が通らない。数万円かかる。複合機で足りるプリントにしか効かない |
| 最初から iPad のアプリにする | 中継が要らず、カメラとペンは最も良い。だが Apple の開発者登録（年額）、期限のある試験配布、言語がもう1つ増える。**案B が回ってから、画面の中で撮りたくなったときの次の手**として残す |
| 画面の中のカメラで撮る（入室時に生徒が自分でかざす） | 講師の手間は0になり、「提出＝自分で撮る」でオンラインの子と完全にそろう。だがブラウザのカメラは動画の1コマなので、1ページあたりの細かさが落ちる（端末によっては「書類をスキャン」の半分以下）。入口に列もできる。案B のあとで1コースで試す |

## 10. 作る順と、最初の決めごと

周期（5週）で数える。

| いつ | やること | 確かめる数 |
|---|---|---|
| いま〜10/03 | §11 の答えをもらう。使う講師の宿題の紙の内訳を1コースで数える（ノート・冊子・プリント）。校舎の複合機と iPad の PDF を1本ずつもらい、中の形を見る | ― |
| 第1周期 | tubestudy は予定どおり本導入。並行して案A を作る（手元で動かした tubestudy のデモに当てて検査） | ― |
| 第2周期 | 案A を1人の講師・1コースで。番号シールを配る | 取り込みにかかった分・「だれ？」の枚数・他人の束に入った枚数（0 でなければ止める） |
| 第3周期 | 案B の採点の画面 | 回収から返すまでの日数・画面に触れた回数 |
| 第4周期〜 | 案C（小テストの答案用紙）。入室時に生徒が自分で撮る形を試すか決める | 問題ごとの採点が使われたか |

### 置き場
- 新しいフォルダ（例：`tube-schools/紙の宿題/`）に全部を置く。`app/`・`server/`・`deploy/`・`scripts/` には触れない。
- 検査は、手元で動かした tubestudy のデモ（別の空の置き場に作る）に当てる。本番には当てない。

### 最初の不変条件（意味の検査。作る前に書く）
1. 送った先の sid ＝ そのページの前にある表紙の印の sid（講師が動かしたページを除く）。**他人の束に1枚も入らない。**
2. 表紙と区切り紙は送らない。登録した名前の欄は、送る画像の中で白い。
3. 入れたページの数 ＝ 送った数 ＋ 外した数（白紙・二度撮り）。黙って消えたページが無い。
4. 評価（1〜5）は講師が押したものだけ。◯✕の数から評価を作らない。
5. 取り込まなかった回の対面の子を「出していない」と言わない（tubestudy の併走の決まりと同じ）。
6. 口の検査：tubestudy のデモに、使う8つの口を毎回当て、形が変わっていたら止まる（tubestudy は他のセッションで日々変わるため）。

## 11. 決めてほしいこと

勧めを先に書く。「勧めのとおり」で進められる。

1. **tubestudy の口を、外の画面から中継して使ってよいか。** 勧め：よい（通す口を8つに絞り、何も保存しない）。だめなら案D だけが残る。
2. **使う講師3名の宿題の紙は、ノート・冊子への書き込み・プリントのどれが多いか。** ノート・冊子が多ければ iPad が主、プリントが多ければ複合機が主になる。
3. **誰が撮るか。** 勧め：最初は講師（1クラス数分）。回ったら、入室時に生徒が自分で、を1コースで試す。事務の方に頼めるならそれも。
4. **対面の子への返し方。** 勧め：アプリの「先生から」＋希望する講師だけ番号順の印刷。
5. **校舎の複合機で、両面・カラー（かグレー）の PDF にできるか。送り先（メール・USB・NAS）はどこか。**
6. **中継の置き場。** 勧め：Cloudflare の Workers（無料枠・中身を見る相手が増えない）。だめなら小さな別サーバ。
7. **紙に書いた名前。** 勧め：表紙は送らない＋紙の形ごとに名前の欄を1回登録して消す＋「名前は表紙にだけ」を生徒に頼む。
8. **校長の宿題帳。** 中身が分かれば、同じ取り込みに載せられるか考える（オンラインの子向けにデジタルで補う話とつながる）。
