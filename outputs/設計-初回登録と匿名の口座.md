## 1. 口座の形

```
accounts.json  "s-042": { sid, role:"student", level:"e4", classId:"e4a", subjects:["japanese","math"],
                          seat:"s-042",            ← 画面の呼び名は ID そのもの（クラス-番号 は使わない）
                          via:"join", created, lastLogin, ＋ 合言葉を確かめる値（scram） }
```
- **`seat` は ID と同じ**。講師の画面には「小4α s-042」と出る（クラス替えで変わるのはクラス名だけ）。席の番号を振る・重なりを避ける、は要らない。
- 学年・クラス・科目は口座の欄。コースの受け取り手は今までどおり「在籍クラス＋受講科目」から決まる（`courses.receivers`）。
  変えたら、期限前の宿題の受け取り手を合わせる（`join_open_homework`・`leave_open_homework`・クラス替えは `move_plan`／`move_apply`）。
- ID は校舎をまたいで一意（索引）。`s-` は 000〜999 から、使われていないものを無作為に。9割を超えたら4桁にする。

## 2. 招待コード

- 校舎ごとに1つ（`school.json` の `join: {code, at, by}`）。6文字（紛らわしい 0/O/1/I を除く英数字）。
- 管理ページの「登録コード」に、コードと QR（`https://<入口>/#join=<コード>`）が出る。刷って配る。漏れたら「作り直す」（前のコードは、その場で使えなくなる）。
- コードは秘密ではなく「入口の札」。守りは回数の上限（下）と、作り直せること。

## 3. 登録の口（入る前の口。だれでも呼べるので、小さく・回数を限る）

| 口 | 受けるもの | 返すもの |
|---|---|---|
| `POST /api/join/check` | `{code}` | `{ok, school:{name}, classes:[{id,name,grade}], combos}`。同じ相手から15分に20回まで |
| `POST /api/join` | `{code, agree:true, students:[{grade, classId, subjects}]}`（1〜4人） | `{made:[{id, setup}]}`。口座を**仮**で作る（`role:"seat"`・`pending:{exp, key}`。名簿にも宿題にも出ない）。同じ相手から1時間に6回まで |
| `POST /api/join/finish` | `{items:[{id, setup, verifier}]}` | `{ok, ids}`。合言葉を確かめる値を置き、在籍の生徒にする（期限前の宿題にも入る） |

- **ID を先に見せて、合言葉はあとで作ってもらう**ので、口座は2段で作る。仮の口座は1時間で消える（ID は戻る）。
- `setup` は1回きりの鍵（サーバには SHA-256 だけ置く）。合言葉そのものは、ここでもサーバへ来ない（端末が verifier を作る）。
- きょうだいで同じ合言葉にしても、ID ごとに別の塩で verifier を作る。

## 4. 画面（`app/js/ui-join.js`・`app/css/join.css`。文言はここが原本）

1. **ようこそ**：その端末ではじめて開いたとき（印 `tube.welcomed` が無い）か、`#join=<コード>` で来たとき。大きな銘の動き → 「Welcome to tube study!」→「登録する」「ログイン」。
   ふつうの入口の下にも小さく「初回登録する」。
2. **できること**（約30秒）：`app/media/intro.mp4`。右下に「スキップ」。**差し替えは、このファイルを置き換えるだけ**（`JOIN_INTRO` が場所を持つ）。読み込めなければ飛ばして先へ。
3. **学年 → クラス**：1枚の中で、選ぶと次が下に現れて、そこへ滑る。
4. **受講科目**：小学生は 国算／国算理社／国算英／国算理社英、中学生は 国数／国数英／国数理社／国数理社英。「2人目を登録する」（4人まで）。
5. **確かめる**：登録する生徒の一覧／大事なこと4つ／押すと開く利用規約（`app/terms.js`）／「修正する」「アカウントを作成する」。
6. **ID と合言葉**：「あなたの生徒IDは s-042 です」「ID は必ずメモをとってください」。合言葉は1つ入れれば全員に使える。
   同じクラスのきょうだいには「どちらがどの ID を使うか、いま決めてください」。
7. **完了**：銘の動き＋「登録が完了しました！」＋「はじめる」（複数なら ID ごとに並ぶ）→ いつもの All aboard! → ホーム。

## 5. まもり

- 招待コードの総当たり：32^6 ≒ 10億通り。同じ相手から15分に20回まで。
- 口座の作りすぎ：同じ相手から1時間に6回・1回に4人まで。合言葉を作らなかった仮の口座は1時間で消える。
- 知らない人が紛れても、見えるのはそのクラスの宿題だけ。講師の名簿に知らない ID が増えたら、管理ページで在籍終了にできる。3か月使わない口座は消える（⑤）。
- 合言葉を忘れたとき：ID が分かれば、管理ページで「オンラインで渡す」（1回だけのリンク）を作って本人に渡す。**ID を言えば他人の口座を取れる、にならないよう、渡すのは本人に確かめられる場（教室・塾のメール）で。**
- 「個人情報を保存しない」とは書かない。**氏名・連絡先は集めない。学習の記録と答案の写真は、ID に結びつけて保存する**（英国の法律では、これも個人データ）。規約にもそう書く。

## 7b. ② 設定で変える・管理ページの俯瞰（10-01）

  変えると、期限前の宿題の受け取り手が、いまのクラスと科目に合う（記録のある宿題からは外さない）。ID・合言葉・これまでの記録は変わらない。

- 管理ページ「いまの様子」：登録コード（QR・配る紙・作り直す）と、最近の動き（登録・変更・在籍・入口の見張り）。

## 7c. ③ 組分けの申告（10-01）

- 管理ページ「いまの様子」→「組分けテストの日程」に、テストの日を入れる（何件でも。結果が出るまでの日数は既定 7、0〜21）。
- テストの 7日後から 14日のあいだ、生徒のホームのいちばん上に「組分けテストの結果、クラスは どちらに なりましたか」。
  いまのクラスが選ばれていて、「変わらない」か、新しいクラスを押して「このクラスにする」。答えるともう出ない。
- 新しいクラスを答えると、期限前の宿題の受け取り手が新しいクラスに合う（設定から変えるのと同じ道）。ID・合言葉・記録は変わらない。
- 管理ページには「いま聞いています　10/17 のテスト（10/24〜11/6）　答えた 12／40人」。だれが答えていないかは、ID で分かる（生徒の紙の「最近の動き」）。
- 答えない生徒は、前のクラスのまま。講師が気づいたら、本人に設定から直してもらう（管理者も直せる）。

## 9. ④ 対面採点（なぞるだけ採点。10-01）

- 対面の生徒にも「できるだけ写真で出して」と伝える。それでも対面で見るときは、**ノートや教科書の各ページの上に ID を書いてもらう**。
- 講師の「宿題チェック」→「対面で採点」。ID の順に行が並び、帯を指で左右になぞると、離したところの数（1〜5）が付く。押すだけでも付く。「消す」で戻る。
- 「ID でしぼる」に数字を入れると、その生徒だけになる（ノートの山を上から順に片づけるとき）。
- 写真の採点の画面は、そのまま（「写真で採点」）。同じ宿題・同じ評価なので、どちらで付けても成績は1つ。
- ID と顔が講師の頭の中で結びつくのは、防がない（本人の判断 10-01）。システムの中に名前は入らない。

## 10. ⑤ 3か月使われない口座の破棄（10-01）

- **本番に切り替えた校舎だけ。** 生徒の口座が 92日 使われないと、サーバが自分で消す（1時間ごとに見る）。
- 消すもの：口座・記録・写真・評価・点・連絡・宿題の受け取り手。**全部。** ID は空きに戻り、あとで別の人に出ることがある。
- 残すもの：`schools/<校舎>/retired.jsonl` に1人1行の数字（消した月・学年・クラスの記号・受講科目・使っていた週の数・宿題の評価・テストの点・
  落とした単元・アプリの数）。**ID・内部の番号・時刻・文章・写真は入らない。** 少人数のクラスなので「絶対に戻せない」とまでは言えない（SECURITY.md）。
- 管理ページ「使われていない口座」に、2週間以内に消える ID と残りの日数。続けて使う生徒なら、一度入ってもらえば消えない。
- 退塾の連絡は要らない（使われなくなれば消える）。すぐ消したいときは、在籍終了にして `purge`（6か月）ではなく、**本人から ID を添えて依頼**（規約 5章）→ 管理者が消す口は、まだ無い（要るなら作る）。
- 手で流す：`python3 server/tube_server.py housekeep --dry`（見るだけ）／`housekeep`（消す）。

## 11. ⑤ 学年の繰り上げ（10-01。本人の回答：日付は管理ページに1つ／中3は切り替えの日に卒業／小6→中1 は本人に聞く）

- いまのデータに「年度のはじまり」は無い（コースも授業計画も、年をまたぐ形になっていない）。だから **入れた日付を読む**（推測しない）。
- 管理ページ「いまの様子」→「新年度のはじまり」に日付を1つ入れる。**きょうと過去の日は入らない**（少なくとも1日、気づく時間がある）。「外す」で取り消せる。
- その日の朝（サーバの片づけ。1時間ごと）に、1回だけ：

  | いまの学年 | その日から | クラス |
  |---|---|---|
  | 小4〜小5、中1〜中2 | 1つ上の学年 | 同じ記号のクラス（小4α → 小5α）。行き先の学年にクラスが1つだけなら、そこ |
  | 小6 | 中1 | **空。ホームのいちばん上に「中1のクラスを教えてください」**（T・R・D から選ぶ。答えるまで出る。設定からも選べる） |
  | 中3 | 中3のまま「卒業」 | **クラスから外れる。** 入れる・記録は見られる・新しい宿題は届かない。ホームに「卒業おめでとうございます」。3か月使われなければ破棄 |

- 出してある宿題は、そのまま（受け取った本人のもの）。ID・合言葉・記録は変わらない。在籍終了の生徒は動かさない。
- 1年に1回だけ。繰り上げた年に、別の日付は入らない（次の年度の日付を入れる）。
- まちがって卒業になった・クラスが違う → 本人が設定から、または管理者が「生徒」→「クラスの決まっていない生徒」→「変える」。
- **残っていること**：コースと授業計画の、年度の切り替え（新小5 のコースに、前の年の授業計画が残る）。講師が新年度の計画を入れ直す手順を、2月までに決める。

## 8. 検査

- `server/test_admin.py` の「初回登録」：コードの確かめ・回数の上限・仮の口座は名簿に出ない・合言葉を作ると生徒になる・1時間で消える・4人まで・学年とクラスの食い違い・同意が無ければ作らない。
- Chrome：1人／2人（同じクラスのふたご）／ログインへ／スキップ／修正する／完了 → はじめる → ホーム。
- 10-01 から、同じ流れを **Chrome・Edge・WebKit（Safari のエンジン）** の3つで流す（`TUBE_BROWSER=edge|webkit`。`scripts/check/README.md`）。
- Safari のアプリそのものと iPhone は、機械で確かめられない。**キーチェーンへの保存と Face ID の自動入力は、実機で1回。**
